Running Kubernetes well usually means a pile of Helm values, a GitOps tool to babysit, a runbook per failure, and one person who knows how it all fits together. Ankra is the AI platform engineer that takes that pile off your team: you describe what a cluster should run, Ankra deploys it and keeps it in sync, and its AI reads your logs, events and deploy history to tell you why something broke and how to fix it.

It is built for platform engineers and developers who want production Kubernetes without hand-maintaining the machinery around it.

## How it fits together

```mermaid
flowchart LR
    O[Organisation] --> C[Cluster<br/>runs the Ankra agent]
    C --> S[Stacks]
    S --> A[Add-ons<br/>Helm charts]
    S --> M[Manifests<br/>Kubernetes YAML]
    G[(Git repository<br/>optional)] <-.-> S
```

- An **organisation** is your team's account: members, roles, credentials and billing.
- A **cluster** is any Kubernetes cluster running the lightweight [Ankra agent](/concepts/cluster-agent). The agent connects out to Ankra, so it works behind firewalls and NAT.
- A **Stack** is what a cluster should run: [add-ons](/concepts/addons) (Helm charts) and [manifests](/concepts/stacks#manifests) (your own YAML), with [variables](/concepts/variables) for what differs between clusters.
- **Git is optional.** Stacks deploy straight through the agent. Connect a repository when you want every change reviewed and versioned, and edits flow both ways - see [GitOps](/concepts/gitops).

## Work from your own tools

The web UI, the CLI, the MCP server and the in-product AI all use the same tools and the same permissions, so anything you can do in one you can do in the others.

<Tabs>
  <Tab title="CLI">
    ```bash
    brew install ankraio/tap/ankra
    ankra login
    ankra chat "why is the payments pod crashing?" --cluster prod
    ```

    See the [Ankra CLI](/integrations/ankra-cli) guide.
  </Tab>
  <Tab title="AI assistants (MCP)">
    Connect Claude, Cursor or any other MCP client to Ankra's remote MCP server. For Claude Code, register it once and sign in with `/mcp`:

    ```bash
    claude mcp add --transport http ankra https://platform.ankra.app/api/v1/mcp
    ```

    Then run `ankra skills install` to teach the assistants on your machine Ankra's conventions. Setup for every client is in the [MCP Server](/platform/mcp-server) guide, and the [MCP Tool Reference](/platform/mcp-tools) lists every tool.
  </Tab>
  <Tab title="CI/CD">
    Your pipeline builds and pushes an image, commits the new tag to your GitOps repository, and Ankra deploys it - [Ship Your App](/guides/deliver-your-app) compares this with letting Ankra build and redeploy on every merge. Plain CI jobs can also call `ankra chat` and `ankra cluster apply` - see [Use the ankra CLI in CI](/guides/pipeline-agents).
  </Tab>
</Tabs>

<Note>
**Automating Ankra or building an agent on it?** Use the [MCP server](/platform/mcp-server) or the [CLI](/integrations/ankra-cli) rather than driving the web UI with a browser. Both use scoped tokens, and every call lands in your organisation's audit log.
</Note>
