## ankra canvas

Publish an HTML, SVG or Markdown file as a static page on the Ankra pages
host, list the pages your organisation has published, and unpublish them.

```bash
ankra canvas publish report.html --title "Q3 report"
ankra canvas list
ankra canvas unpublish 3f0a2f7e-0000-4000-8000-000000000001
```

Anyone holding the URL can open the page, so publish nothing you would not
hand to that audience. Pages are static snapshots, expire after a retention
period (`--ttl-hours`) and can be unpublished at any time.

The saved canvases behind the portal's canvas pages are a separate library:
'library' lists them, 'get', 'create', 'update' and 'delete' work on one, and
'revisions' and 'comments' read its history and its comment threads.

```bash
ankra canvas library
ankra canvas get 3f0a2f7e-0000-4000-8000-000000000001 --content > report.html
ankra canvas comments list 3f0a2f7e-0000-4000-8000-000000000001
```

## ankra canvas comments

## ankra canvas comments add

Add a comment to a canvas. `--reply-to` answers another comment, and `--element`
or `--revision` anchor the comment to one element or one revision.

```bash
ankra canvas comments add <canvas-id> <text> [flags]
```

**Examples**

```bash
ankra canvas comments add 3f0a2f7e-0000-4000-8000-000000000001 "The Q3 total looks low"
ankra canvas comments add 3f0a2f7e-0000-4000-8000-000000000001 "Fixed in revision 4" --reply-to <comment-id>
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `--element` |   | Element id of the canvas the comment is about |
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |
| `--reply-to` |   | Comment id this comment answers |
| `--revision` |   | Revision id the comment is about |

## ankra canvas create

Save an HTML, SVG, Markdown or JSON file as a new canvas. The canvas is private
to you until you share it with 'ankra canvas update &lt;canvas-id&gt; `--visibility`
organisation'; publishing it at a public URL is 'ankra canvas publish'.

The language is inferred from the file extension (.html and .htm, .svg, .md,
.json) and can be set with `--language`. A json canvas is a dashboard
specification, which the platform validates and never repairs. A file over
524288 bytes is refused.

```bash
ankra canvas create <file> [flags]
```

**Examples**

```bash
ankra canvas create report.html --title "Q3 report"
ankra canvas create capacity.json --kind dashboard -o json
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `--kind` | `page` | Canvas kind: page or dashboard |
| `--language` |   | Content language: html, svg, markdown or json (default: inferred from the extension) |
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |
| `--title` |   | Canvas title (default: the file name without its extension) |

## ankra canvas library

## ankra canvas publish

Publish an HTML, SVG or Markdown file and print its public URL.

The language is inferred from the file extension (.html and .htm, .svg, .md)
and can be set with `--language`. Other languages are refused, as is a file over
200000 characters.

Publishing the same file again updates the same page and keeps its URL: when
`--conversation-id` and `--artifact-id` are not given, both are derived from a hash
of the file's absolute path, so the page is identified by where the file lives.
Moving or renaming the file publishes a new page. Pass both ids to take control
of the identity yourself, for example to update a page published from the portal
canvas.

The URL is printed last, on its own line, so scripts can take the final line of
output; with -o json the publication is printed as a JSON document instead.

```bash
ankra canvas publish <file> [flags]
```

**Examples**

```bash
ankra canvas publish report.html
ankra canvas publish notes.md --title "Release notes" --ttl-hours 24
URL=$(ankra canvas publish diagram.svg | tail -n 1)
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `--artifact-id` |   | Artifact id identifying the page; give together with `--conversation-id` (default: derived from the file's absolute path) |
| `--conversation-id` |   | Conversation id identifying the page; give together with `--artifact-id` (default: derived from the file's absolute path) |
| `--language` |   | Page language: html, svg or markdown (default: inferred from the extension) |
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |
| `--title` |   | Page title (default: the file name without its extension) |
| `--ttl-hours` | `0` | Hours the page stays live (default and maximum are set by the platform) |

## ankra canvas update

Change a canvas's title, its visibility, or both. `--visibility` private keeps
the canvas to its owner; organisation lets every member read it. Only the
owner can change a canvas.

```bash
ankra canvas update <canvas-id> [flags]
```

**Examples**

```bash
ankra canvas update 3f0a2f7e-0000-4000-8000-000000000001 --title "Q3 report (final)"
ankra canvas update 3f0a2f7e-0000-4000-8000-000000000001 --visibility organisation
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |
| `--title` |   | New title |
| `--visibility` |   | Who can read the canvas: private or organisation |
