## ankra helm addon-definitions

An add-on definition describes one add-on (its name, description, links and
category) and which charts it matches: by chart name, by chart keyword and by
the prefix of a chart's home URL. The add-on catalog groups the organisation's
charts under the definitions that match them.

The organisation sees Ankra's global definitions and its own. Ankra's are
read-only; changing or deleting one is refused (403). A chart link is a manual
override: it includes a chart the rules miss, or excludes one they match.

## ankra helm addon-definitions create

Create an add-on definition for the organisation. &lt;name&gt; is a lowercase slug
(letters, digits and dashes). The match rules say which charts the catalog
groups under the add-on: any chart whose name, keyword or home URL prefix
matches. A name already in use is refused (409).

```bash
ankra helm addon-definitions create <name> --display-name <text> [flags]
```

**Examples**

```bash
ankra helm addon-definitions create internal-gateway --display-name "Internal gateway" \
  --category networking --match-chart-name internal-gateway --match-keyword gateway
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `--category` |   | The catalog category the add-on is listed under |
| `--description` |   | What the add-on is |
| `--display-name` |   | The add-on's name as people read it |
| `--documentation-url` |   | The add-on's documentation |
| `--icon-url` |   | The add-on's icon |
| `--match-chart-name` | `[]` | A chart name this add-on matches (repeat or comma-separate) |
| `--match-home-url-prefix` | `[]` | A chart home URL prefix this add-on matches (repeat or comma-separate) |
| `--match-keyword` | `[]` | A chart keyword this add-on matches (repeat or comma-separate) |
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |
| `--website-url` |   | The add-on's website |

## ankra helm addon-definitions delete

Delete an organisation add-on definition. The charts it grouped stay in their
registries and installed add-ons keep running; the catalog just stops grouping
them under it. It asks first; `--yes` skips the question and is required when
there is no terminal to ask on. Ankra's global definitions are read-only (403).

```bash
ankra helm addon-definitions delete <name> [flags]
```

**Examples**

```bash
ankra helm addon-definitions delete internal-gateway --yes
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `-y`, `--yes` | `false` | Skip the confirmation prompt (required when stdin is not a terminal) |

## ankra helm addon-definitions link-chart

Add a manual link between one chart in one registry and an add-on definition,
overriding the definition's match rules for that chart: `--type` include (the
default) groups a chart the rules miss under the add-on, `--type` exclude keeps
out one they match.

```bash
ankra helm addon-definitions link-chart <name> --chart <chart> --registry-url <url> [flags]
```

**Examples**

```bash
ankra helm addon-definitions link-chart cert-manager --chart cert-manager-fork --registry-url https://charts.example.com
ankra helm addon-definitions link-chart cert-manager --chart unrelated --registry-url https://charts.example.com --type exclude
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `--chart` |   | The chart's name (required) |
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |
| `--registry-url` |   | The URL of the registry the chart is in (required) |
| `--type` | `include` | include groups the chart under the add-on; exclude keeps it out |

command reads the definition, applies them and sends the whole definition back,

```bash
ankra helm addon-definitions update <name> [flags]
```

## ankra helm registries

Manage Helm chart registries

## ankra helm registries create

Create a Helm chart registry from a spec file (-f, JSON or YAML) or
directly from `--name` and `--url`.

In a spec file the registry must be nested under exactly one of
"helm_oci_registry" or "helm_http_registry":

```json
{"spec": {"helm_oci_registry": {"name": "my-charts", "url": "oci://ghcr.io/acme/charts"}}}
{"spec": {"helm_http_registry": {"name": "my-charts", "url": "https://charts.example.com"}}}
```

A flat &#123;"name": ..., "url": ...&#125; file is accepted and nested automatically,
inferring the registry type from the URL scheme: oci:// creates an OCI
registry, http:// or https:// an HTTP chart repository. The flag form uses
the same inference.

Examples:

```bash
ankra helm registries create -f registry-spec.json
ankra helm registries create -f registry-spec.yaml
ankra helm registries create --name my-charts --url oci://ghcr.io/acme/charts
ankra helm registries create --name my-charts --url https://charts.example.com \
  --credential-name my-cred --exclude-charts legacy-chart
```

```bash
ankra helm registries create [flags]
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `--credential-name` |   | Name of an existing Helm registry credential for private registries |
| `--exclude-charts` | `[]` | Chart name to exclude from indexing (repeatable) |
| `-f`, `--file` |   | Path to a registry spec file, JSON or YAML |
| `--name` |   | Registry name (with `--url`; alternative to `--file`) |
| `--url` |   | Registry URL: oci:// for OCI registries, http:// or https:// for HTTP chart repositories |
