## ankra tickets

Work the organisation's AI board from the terminal.

The AI board is where Ankra's agents track incidents, insights and requests
as tickets. These commands list the board, show one ticket with its
timeline, comment on it, move it through its lifecycle, and answer the
decision a blocked ticket is waiting on: the same choice the ticket page
renders as options plus "something else".

Tickets have structure. A symptom sits under the root ticket that carries
its work ("ankra tickets nest", "detach"), a sub-ticket under the ticket it
was filed for ("create `--parent`"), and tickets link to each other with a
relation such as duplicate_of or recurrence_of ("links", "link", "unlink").
"ankra tickets get" shows all of it, and "close `--duplicate-of`" closes a
ticket as a duplicate and links it to the keeper in one step.

A ticket is referenced by its number (8, T-8 or #8) or its UUID.

A refused write prints the platform's sentence and exits 2 when the request
named the wrong thing (400, 422), 3 when the ticket is not in your
organisation (404) and 1 when the tickets' state refused it (409).

## ankra tickets close

Close a ticket with a resolution: fixed, no_action, duplicate, wont_fix,
escalated, unverifiable, cleared or expired. A close as fixed can name what
confirmed the fix with `--evidence-kind` (probe, agent_run, automation_run,
observation, link or human_attestation) and `--evidence-reference`; without
them you are recorded as the evidence.

`--duplicate-of` names the open ticket that covers the same cause, by number
(42, T-42) or id, and implies `--resolution` duplicate. The platform links the
closed ticket to that ticket's canonical keeper and tells the keeper on its
timeline; the CLI then reads the link back and names the keeper. When
nothing was written, the platform says why: another resolution, a reference
that is not a ticket, an unknown number, the ticket itself, another
organisation's ticket, a loop, or a keeper that is closed (exit 2). A ticket
that cannot be closed from its current state is refused with exit 1.

```bash
ankra tickets close <ticket> [flags]
```

**Examples**

```bash
ankra tickets close T-50 --duplicate-of T-42
ankra tickets close T-50 --resolution fixed --note "Renewed the certificate"
ankra tickets close T-50 --resolution fixed --evidence-kind probe --evidence-reference "https://status.example.com/check/42"
ankra tickets close T-50 --resolution no_action --note "Expected during the maintenance window"
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `--duplicate-of` |   | The open ticket covering the same cause (42, T-42 or its UUID); implies `--resolution` duplicate |
| `--evidence-kind` |   | With fixed: what confirmed the fix (probe, agent_run, automation_run, observation, link, human_attestation) |
| `--evidence-reference` |   | With fixed: where that evidence is, such as a run id or URL (up to 1000 characters) |
| `--note` |   | Why the ticket is closed, shown on its timeline |
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |
| `--resolution` |   | fixed, no_action, duplicate, wont_fix, escalated, unverifiable, cleared or expired (duplicate when `--duplicate-of` is given) |

## ankra tickets create

File a ticket on the AI board. `--kind` defaults to request and `--priority` to
medium. With `--parent` the ticket is filed as a sub-ticket of an open ticket:
it is worked like any ticket and counts toward its parent's sub-tickets. A
sub-ticket takes no `--cluster` or `--staffing` of its own.

To put an existing ticket under a root whose work covers it, use
"ankra tickets nest" instead: a symptom gets no agent run of its own.

```bash
ankra tickets create --title <title> [flags]
```

**Examples**

```bash
ankra tickets create --title "Rotate the registry robot token" --kind chore --priority high
ankra tickets create --title "Ingress cert expires Friday" --kind incident --cluster prod-hel1 --label cert
ankra tickets create --title "Renew the wildcard certificate" --parent T-42
ankra tickets create --title "Track the vendor fix" --staffing manual
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `--body` |   | The ticket's description (markdown) |
| `--cluster` |   | The cluster the ticket is about (name or id); top-level tickets only |
| `--kind` |   | incident, insight, gap, automation, request (the default) or chore |
| `--label` | `[]` | A label to put on the ticket (repeat or comma-separate for more) |
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |
| `--parent` |   | File it as a sub-ticket of this open ticket (42, T-42 or its UUID) |
| `--priority` |   | urgent, high, medium (the default) or low |
| `--staffing` |   | auto (the default: the AI team may staff it) or manual (a person owns it); top-level tickets only |
| `--title` |   | The ticket's title |

## ankra tickets decide

Answer the decision a blocked ticket is waiting on. Pick one of the
options the agent offered with `--option` &lt;key&gt; (see "ankra tickets get"),
or give the decision in your own words with `--answer`. Both together record
the option with your note beside it. The answer lands on the timeline as a
"Decision:" comment and the agent resumes from it.

```bash
ankra tickets decide <ticket> [flags]
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `--answer` |   | The decision in your own words, or a note beside `--option` |
| `--option` |   | Key of the offered option to choose |
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |

## ankra tickets detach

Make a symptom a top-level ticket again, with an event on its timeline and
on its root's. Its status and any question it carries stay as they are, and
it is worked like any other ticket from then on. A ticket that sits under no
root is left unchanged. A sub-ticket is refused: it belongs to its parent.

```bash
ankra tickets detach <ticket> [flags]
```

**Examples**

```bash
ankra tickets detach T-51
ankra tickets detach T-51 --reason "Different cause after all"
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |
| `--reason` |   | Why the ticket stands on its own again, shown on both timelines (up to 1000 characters) |

## ankra tickets get

Show one ticket. Besides its fields this shows where it sits: the ticket it
is under and whether that ticket carries its work (a symptom) or it is a
sub-ticket of it, the open symptoms and sub-tickets under it, every ticket
directly under it with its role, and its links in both directions. A part
that could not be read is said to be unread, never shown as empty, and the
command then exits 1 after printing the rest.

With -o json only the ticket is printed, with its structure fields:
parent_ticket_id, parent_ticket_number, parent_ticket_title,
parent_ticket_status, child_role ("symptom", "subtask" or null),
sub_ticket_count and open_sub_ticket_count (every child, symptoms included),
live_symptom_count and symptoms_needing_person_count. Read the children with
"ankra tickets list `--parent` &lt;ticket&gt; -o json" and the links with
"ankra tickets links &lt;ticket&gt; -o json".

```bash
ankra tickets get <ticket> [flags]
```

**Examples**

```bash
ankra tickets get T-42
ankra tickets get T-42 -o json
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |

## ankra tickets link

Link a ticket to another ticket (by number, T-42, or id) or, with `--kind`, to
another record. The relation defaults to relates_to; the others are
spawned, evidence, fix, duplicate_of and recurrence_of (an earlier ticket of
the same recurring signal, tickets only). Linking what is already linked
answers with the existing link.

To close a ticket as a duplicate, use "ankra tickets close `--duplicate-of`",
which closes it and links it to the keeper in one step.

```bash
ankra tickets link <ticket> <target> [flags]
```

**Examples**

```bash
ankra tickets link T-50 T-42
ankra tickets link T-50 T-31 --relation recurrence_of
ankra tickets link T-50 https://github.com/acme/app/pull/12 --kind merge_request --relation fix
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `--kind` | `ticket` | What the target is: ticket, or another record kind such as merge_request, agent_run or session |
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |
| `--relation` |   | spawned, evidence, fix, duplicate_of, relates_to (the default) or recurrence_of |

## ankra tickets links

List the links a ticket holds and the ticket links other tickets hold on
it, each with the ticket at the other end: its number, title and status.

The relation reads from the ticket you named: "Duplicate of T-42" is a link
this ticket holds, "Duplicate of this ticket T-51" is one T-51 holds on it.
Relations are spawned, evidence, fix, duplicate_of, relates_to and
recurrence_of. The LINK column is the id "ankra tickets unlink" takes.

With -o json the platform's answer is printed as sent: &#123;"links": [...],
"incoming_links": [...]&#125;, each entry with id, ticket_id (the ticket that
holds the link), target_kind, target_id, relation, created_at, direction
("outgoing" or "incoming") and linked_ticket (id, ticket_number, title,
status and resolution of the ticket at the other end, or null for a target
that is not a ticket of the organisation).

```bash
ankra tickets links <ticket> [flags]
```

**Examples**

```bash
ankra tickets links T-42
ankra tickets links T-42 -o json
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |

## ankra tickets nest

Move an existing ticket under a root ticket as a symptom. The root carries
the work: the symptom gets no agent run or thread of its own, and it is
settled or stands on its own again when the root closes. A ticket a person
owes an answer on keeps its question. Naming a symptom as the root nests
under that symptom's own root. Nesting a ticket that is already a symptom
of the root changes nothing.

The platform refuses, with a sentence saying why, a root that is the ticket
itself or does not exist (exit 2), and a closed ticket or root, a sub-ticket
on either side, a ticket that has sub-tickets of its own, a loop, or held
work (exit 1). A concurrent change is refused the same way: read the ticket
again and retry.

```bash
ankra tickets nest <ticket> --root <ticket> [flags]
```

**Examples**

```bash
ankra tickets nest T-51 --root T-42
ankra tickets nest T-51 --root T-42 --reason "Same expired certificate"
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |
| `--reason` |   | Why this ticket is a symptom of the root, shown on both timelines (up to 1000 characters) |
| `--root` |   | The root ticket to nest under: its number (42, T-42) or UUID |

## ankra tickets unlink

Remove one link from a ticket, named by its link id (see "ankra tickets
links") or by the ticket at its other end. A link another ticket holds on
this one is removed too: the CLI sends the removal to the ticket that holds
it. When two tickets are linked more than once, name the one to remove with
`--relation`. The removal is recorded on the ticket's timeline.

```bash
ankra tickets unlink <ticket> <link-id|ticket> [flags]
```

**Examples**

```bash
ankra tickets unlink T-50 T-42
ankra tickets unlink T-50 T-42 --relation relates_to
ankra tickets unlink T-50 4f1c2d0e-8a6b-4c1e-9b7a-2d4e6f8a0b1c
```

**Flags**

| Flag | Default | Description |
|------|---------|-------------|
| `-o`, `--output` |   | Output format: json or yaml (default: human-readable) |
| `--relation` |   | Remove only the link with this relation |
