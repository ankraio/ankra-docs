description: Every step from a repository to production, with the exact page, CLI command or MCP tool on each surface, and the recorded reason where a surface does not have it yet.

Each step from a repository to production, on each surface. A **Gap** says why the surface does not have the step. Gaps marked "by design" stay; the others are meant to close.

The table is generated and checked in the docs build: a command that is no longer on the [CLI reference](/reference/cli/index) or a tool no longer on the [MCP tool reference](/platform/mcp-tools) fails it. UI pages are relative to the [new Ankra portal](https://platform.ankra.app/next).

{/* flow-parity:start - generated by scripts/check_flow_parity.mjs, do not edit by hand */}

| Step | UI | CLI | MCP |
| --- | --- | --- | --- |
| **Connect GitHub** | `/organisation/integrations` - Source control, install the Ankra GitHub App | **Gap.** Installing a GitHub App is a browser consent. Register a repository once the connection exists. | **Gap.** By design: a credential is never created over MCP, because the secret would be a tool argument. |
| **Register the repository** | `/applications/create` - Choose a repository, Create application | `ankra application add`, `ankra application ship` | `create_application` |
| **Read the setup pull request** | `/applications/[id]` - Ship, Go live | `ankra application add --wait` | `get_application_setup_proposal` |
| **Approve pipeline authority** | `/applications/[id]` - Pipelines, Approve | `ankra pipeline definitions approve` | **Gap.** By design: only a person approves what a pipeline may do. |
| **Watch a run** | `/applications/[id]` - Pipelines | `ankra pipeline get --wait`, `ankra pipeline logs` | `watch_pipeline_run`, `get_pipeline_step_logs` |
| **Read findings** | `/applications/[id]` - Protect | `ankra pipeline findings`, `ankra application container-security` | `get_application_container_security`, `list_security_findings` |
| **AI fix, with approval** | `/applications/[id]` - Protect, Fix | `ankra chat`, `ankra chat actions confirm` | **Gap.** No tool starts Ankra AI's fix. The connected client writes the change itself and opens a pull request with scm_create_pull_request. |
| **Merge** | **Gap.** Merging happens on GitHub; the page links to the pull request. | **Gap.** No merge verb; the merge train is the only route and must be enabled. | `scm_merge_pull_request`. Refused while merge-when-green is off for the connection. |
| **Deploy with Postgres** | `/applications/[id]/deploy` - Deploy a version | `ankra application ship --set-up-database` | `deploy_application`, `prepare_service_setup`, `confirm_service_setup`. Cannot yet install the Postgres operator on a cluster without one. |
| **Public address** | `/applications/[id]/deploy` - Public access, Public hostname | `ankra application deploy --set` | `deploy_application` |
| **Pull request previews**<br />Open bug on every surface: a preview on Ankra Cloud does not come up. | `/applications/[id]` - Ship, Previews | `ankra application demo config set`, `ankra application demo deploy` | `update_application_demo_config`, `deploy_pr_demo` |
| **AI review** | `/organisation/integrations` - Source control, repository rules | `ankra org ai-review repos set`, `ankra application pull-request-reviews` | `list_application_pull_request_reviews`. Reads reviews. Turning review on for a repository is not a tool. |
| **Promote** | `/applications/[id]` - Ship, Promote a version | `ankra application deploy --set`. No promote verb: deploy the tag that passed. | `promote_application` |
| **Roll back** | `/applications/[id]` - Ship, Put back | `ankra application deploy --set`. Deploy the previous tag. | `deploy_application`. Deploy the previous tag. |
| **Connect Slack** | `/organisation/integrations` - Chat apps, Slack | **Gap.** No install verb; the browser sign-in starts from the portal. | **Gap.** Slack's install is a browser consent, so no tool starts it. |
| **Route alerts** | `/organisation/notification-routes` - Add a route | `ankra alerts destinations create`, `ankra alerts routes create` | `create_alert_destination`, `create_notification_route` |
| **AI sandbox** | `/organisation/ai-workspaces` - Choose the cluster | `ankra org ai-environment set`, `ankra cluster node-group add`. A new CI cluster needs a labelled node group first. | `update_ai_environment`, `add_node_group` |
| **CI cluster** | `/organisation/pipelines` - CI cluster pool | `ankra org ci-settings pool add` | **Gap.** No tool changes the organisation's CI cluster pool. |

{/* flow-parity:end */}

To change it, edit `scripts/flow_parity.json`, then run `node scripts/check_flow_parity.mjs --write`.
