## Cluster Configuration Options

| Parameter | Default | Description |
|-----------|---------|-------------|
| `name` | *required* | Unique cluster name |
| `credential_id` | *required* | UpCloud API credential ID |
| `ssh_key_credential_id` | *required* | SSH key credential ID |
| `zone` | *required* | UpCloud datacenter zone |
| `zones` | | Zone pool for a multi-zone cluster, must include `zone` (the primary). At least 3 zones and 3 control planes; `kubeadm` only. See [Multi-zone clusters](/guides/upcloud-clusters#multi-zone-clusters) |
| `network_mode` | *derived* | `private_network` or `wireguard_mesh`; `wireguard_mesh` for a pool, and on a single zone it makes the cluster mesh-capable so zones can be added later. On a `wireguard_mesh` cluster the load balancer backends are addressed on the private network rather than the overlay, so `LoadBalancer` Services work unchanged - see [the guide](/guides/upcloud-clusters#loadbalancer-services-on-a-meshed-cluster) |
| `network_ip_range` | `10.0.0.0/24` | Private network IP range. A multi-zone pool takes one consecutive `/24` per zone from this range |
| `bastion_plan` | `STARTER-1xCPU-1GB` | Server plan for the bastion host |
| `control_plane_count` | `1` | Number of control plane nodes (1 or 3) |
| `control_plane_plan` | `PREMIUM-2xCPU-4GB` | Server plan for control planes |
| `worker_count` | `1` | Number of worker nodes (legacy, use `node_groups` instead) |
| `worker_plan` | `PREMIUM-2xCPU-4GB` | Server plan for workers (legacy, use `node_groups` instead) |
| `node_groups` | | Array of node group definitions (see [Node groups](/guides/operate-ankra-managed-clusters#node-groups)) |
| `distribution` | `kubeadm` | Kubernetes distribution (`kubeadm` or `k3s`) |
| `kubernetes_version` | *latest stable* | Kubernetes version (optional) |
| `k3s_disabled_components` | | k3s only. Packaged components the k3s install leaves out (`k3s --disable`), on top of what the provider's k3s shape already disables: any of `coredns`, `servicelb`, `traefik`, `local-storage`, `metrics-server`, `runtimes`, for example `["traefik"]` on a cluster that brings its own ingress. A list on a `kubeadm` cluster is refused with a `400` (`k3s_disabled_components is only supported for the k3s distribution.`); an entry outside those six or an entry listed twice is a `422` validation error pointing at the entry |

## Node Group API Reference

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/v1/clusters/upcloud/{id}/zones` | PUT | Grow a multi-zone cluster's zone pool (`{"zones": [...]}`, primary first; zones are only ever added) |
| `/api/v1/clusters/upcloud/{id}/node-groups` | GET | List all node groups |
| `/api/v1/clusters/upcloud/{id}/node-groups` | POST | Add a node group |
| `/api/v1/clusters/upcloud/{id}/node-groups/{name}/scale` | PUT | Scale a node group (0 to 100) |
| `/api/v1/clusters/upcloud/{id}/node-groups/{name}/instance-type` | PUT | Change server plan |
| `/api/v1/clusters/upcloud/{id}/node-groups/{name}/labels` | PUT | Update labels |
| `/api/v1/clusters/upcloud/{id}/node-groups/{name}/taints` | PUT | Update taints |
| `/api/v1/clusters/upcloud/{id}/node-groups/{name}` | DELETE | Delete a node group |

## Node Actions API

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/v1/clusters/upcloud/{id}/nodes` | GET | List all nodes (control plane, workers, bastion) |
| `/api/v1/clusters/upcloud/{id}/nodes/{node_id}` | GET | Get a single node's details |
| `/api/v1/clusters/upcloud/{id}/nodes/{node_id}/restart` | POST | Restart a node (native reboot, falls back to power cycle) |
| `/api/v1/clusters/upcloud/{id}/bastion/instance-type` | PUT | Resize the bastion instance type |

See [Restart a node](/guides/operate-ankra-managed-clusters#restart-a-node) and [Bastion](/guides/operate-ankra-managed-clusters#bastion) for how to use them.

## Disabled k3s Components API

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/v1/clusters/upcloud/{id}/k3s-disabled-components` | GET | The stored `k3s_disabled_components` (empty when nothing is stored), the k8s node `resource_ids` carrying it, `control_plane_count` and `applies` |
| `/api/v1/clusters/upcloud/{id}/k3s-disabled-components` | PUT | Replace the stored list on a running k3s cluster, for example `{"k3s_disabled_components": ["traefik"]}` |

The `k3s_disabled_components` list set at create can grow on a running k3s cluster. The body is the complete list and has to contain every entry already stored; an unknown or repeated entry is a `422` validation error pointing at the entry. `applies` answers: "The platform's maintenance read lane compares each control plane's k3s server config against this list within about five minutes and flags the ones missing an entry; the reconcile lane then patches the config and restarts k3s on one control plane at a time, in the cluster's k8s update chain. Control planes already carrying every entry are not touched. The list only grows: re-enabling a bundled component is not supported yet, so a change that removes a stored entry is refused, and so is any change while a node update, version upgrade or node restart is still in progress on the cluster." The refusals answer `409` with the detail shown:

| Request | Detail |
|---------|--------|
| The cluster runs kubeadm (the read is refused too) | `k3s_disabled_components is only supported for the k3s distribution.` |
| The cluster has no Kubernetes node resources (the read is refused too) | `No Kubernetes node resources found for this cluster` |
| The list drops a stored entry, here `traefik` | `k3s_disabled_components: re-enabling a bundled component is not supported yet, so a stored entry cannot be removed: traefik. Send the stored list plus any additions.` |
| The list adds `coredns` | `k3s_disabled_components: coredns cannot be disabled on a running cluster. It is load-bearing for in-cluster DNS, and k3s removes it on the first control plane that restarts with the entry.` |
| A node update, version upgrade or node restart is in progress | `k3s_disabled_components cannot be changed while a Kubernetes node update, version upgrade or node restart is in progress on this cluster. Retry once it has finished.` |

## Architecture

```mermaid
flowchart TB
    Internet((Internet))
    Platform[Ankra Platform]

    subgraph Network [UpCloud private SDN network]
        Bastion[Bastion<br/>public + private IP]
        CP[Control plane nodes<br/>no public interface]
        Workers[Worker nodes<br/>no public interface]
        Agent[Ankra Agent<br/>runs in the cluster]
    end

    Router[SDN router]
    NAT[Managed NAT gateway]

    Platform -->|SSH to public IP| Bastion
    Bastion -->|SSH jump| CP
    Bastion -->|SSH jump| Workers
    Agent -->|outbound only - NATS| Platform
    CP -->|default route| Router
    Workers -->|default route| Router
    Router --> NAT
    NAT --> Internet
```

The managed NAT gateway on the router carries all node egress; the bastion is an SSH jump host only. On a multi-zone cluster each additional zone gets its own router, private network and NAT gateway, and a WireGuard mesh (`wg0`) joins every node over the account-wide utility network. See [What Ankra created in your account](/guides/upcloud-clusters#what-ankra-created-in-your-account).
