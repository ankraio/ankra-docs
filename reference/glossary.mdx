---
title: Glossary
description: "One line for each word the Ankra portal and these docs use, with the page that explains it."
---

Words in **bold** are labels you see in the portal. [Find your way around Ankra](/platform/find-your-way-around) shows where each one lives.

| Term | What it means | Read more |
| --- | --- | --- |
| **Add-on** | A Helm chart, or a set of manifests, that a Stack installs on a cluster | [Add-ons](/concepts/addons) |
| **Agent** | The Ankra software in each cluster. It connects out to Ankra and carries out the work Ankra sends back | [Ankra Agent](/concepts/cluster-agent) |
| **Ankra AI** | Ankra's AI: it answers in **Ask Ankra**, watches alerts, works tickets and reviews pull requests | [Ankra AI](/platform/ai-overview) |
| `Ankra pipeline` check | The status check Ankra posts on each commit and pull request it runs a pipeline for | [Get started with Ankra CI](/get-started/ankra-ci) |
| Ankra Pipelines, Ankra CI | CI/CD that runs `.ankra/pipeline.yaml` as Kubernetes Jobs on your own cluster | [Ankra Pipelines](/guides/ankra-pipelines) |
| **Application** | Your own code, from a Git repository, built and deployed by Ankra to one or more clusters | [Applications](/concepts/applications) |
| **Ask Ankra** | The conversation with Ankra AI. **Home** opens on it, and `⌘ J` or `Ctrl J` opens it on any page | [Ankra AI assistant](/platform/ai-assistant) |
| Authority approval | An administrator's one-time approval of a pipeline's protected settings, such as secrets, network access and CPU | [Approve the pipeline once](/get-started/ankra-ci#7-approve-the-pipeline-once) |
| **Backup vault** | An S3-compatible bucket that cluster backups are copied into | [Backup vaults](/concepts/backup-vaults) |
| **Builds and clusters** | The organisation page that says which cluster runs pipelines, the build rules, and the pipeline settings waiting for approval | [Get started with Ankra CI](/get-started/ankra-ci) |
| **Build & delivery** | The menu area for pipelines, registries and **Stack profiles** | [Find your way around](/platform/find-your-way-around) |
| **Cluster mesh** | Kubernetes clusters connected with Cilium ClusterMesh over Ankra's WireGuard overlay | [Cluster mesh](/platform/cluster-mesh) |
| **Connect a cluster** | Bringing a cluster you already run into Ankra by installing the agent | [Add a cluster](/guides/import-cluster) |
| **Credential** | A secret Ankra holds to act on another service: a cloud account, a Git host, a registry | [Credentials](/platform/credentials) |
| **Find** | The search box at the top of the menu, for pages, clusters, applications and actions | [Find your way around](/platform/find-your-way-around#find) |
| Free tier | What an organisation without a payment method may do: 100 Ankra-hosted pipeline minutes and USD 1 of AI a month, and no new clusters apart from the free trial playground | [Why was I refused?](/guides/why-was-i-refused#the-free-allowance-without-a-payment-method) |
| GitOps | Keeping a cluster's configuration in a Git repository that Ankra syncs both ways | [GitOps](/concepts/gitops) |
| **Helm registries** | The chart repositories Ankra reads add-ons from | [Helm registries](/guides/registries) |
| ImportCluster | The YAML file that describes a cluster and its Stacks, applied with `ankra cluster apply` or synced from Git | [ImportCluster YAML](/reference/importcluster) |
| **Infrastructure** | The menu area for **Clusters**, **Managed services** and **Cluster meshes** | [Find your way around](/platform/find-your-way-around) |
| **Kubernetes sync** | The cluster settings page that shows how Ankra's copy of the cluster's resources is kept current, with a full sync that reads every resource again | [Cluster settings](/platform/cluster-settings) |
| **Managed service** | A service such as PostgreSQL or object storage that runs on your own cluster from a package Ankra publishes, connected to your applications | [Managed services](/concepts/managed-services) |
| **Needs you** | Every approval, fix and alert that waits on you, in one list | [Find your way around](/platform/find-your-way-around) |
| **Node group** | A set of worker nodes of one size in a cluster Ankra builds | [Nodes](/platform/cluster-nodes) |
| **Operations** | The record of each change Ankra made to a cluster, step by step | [Operations](/platform/operations) |
| **Organisation** | Your team's account in Ankra: its members, clusters, applications and billing | [Organisations](/concepts/organisations) |
| Pipeline cluster | The cluster your organisation's pipeline steps run on, chosen under **Builds and clusters** | [Get started with Ankra CI](/get-started/ankra-ci#1-choose-the-cluster-your-builds-run-on) |
| Pipeline worker | A slot on a cluster's agent that runs one pipeline step at a time. Set with `ankra cluster agent ci set` | [Get started with Ankra CI](/get-started/ankra-ci#2-turn-on-pipeline-workers-on-that-cluster) |
| **Playground** | A real Kubernetes cluster on servers Ankra runs, for trying Ankra without a cloud account | [Playground](/guides/cluster-sandbox) |
| **Previews** | A short-lived copy of an application for a branch or pull request | [Preview environments](/guides/pr-preview-environments) |
| **Project** | A part of an organisation that holds its own clusters and applications. A member can be limited to one project | [Projects](/concepts/projects) |
| Protected settings | The parts of a pipeline a pull request cannot grant itself: secrets, credentials, caches, CPU and memory, timeouts, services, network access and where a step runs | [Get started with Ankra CI](/get-started/ankra-ci#when-you-add-more-to-the-pipeline) |
| **Registries** | The image registries your application builds publish to | [Harbor registry](/guides/harbor-registry) |
| **Roles** | What a member of the organisation may see and do | [Roles and access](/guides/roles-and-access) |
| Sandbox runtime | A node group labelled `ankra.cloud/sandbox-runtime=gvisor`, where Ankra AI runs code it writes | [Get started with Ankra CI](/get-started/ankra-ci#1-choose-the-cluster-your-builds-run-on) |
| Service token | An API token for automation that acts as a service account, not as a person | [Service tokens](/guides/service-tokens) |
| **Ship** | The application view where you deploy a version and try a branch | [Applications](/concepts/applications) |
| SOPS | The encryption Ankra uses to keep secret values in a Git repository | [SOPS](/guides/sops) |
| **Stack** | A named set of add-ons, manifests and applications that Ankra deploys to a cluster in dependency order | [Stacks](/concepts/stacks) |
| **Stack profiles** | A Stack turned into a reusable, versioned template you can apply to many clusters | [Stack profiles](/concepts/stack-profiles) |
| Trial limit | The 30 vCPUs an organisation may run until an owner approves paid usage | [Why was I refused?](/guides/why-was-i-refused#the-30-vcpu-trial-limit) |
| Two-step sign-in | A second step after your password or sign-in provider: a passkey or an authenticator app | [Account security](/platform/account-security) |
| **Variables and secrets** | Values a Stack or a pipeline reads by name, kept by the organisation | [Variables](/concepts/variables) |
| **Watching** | The Ankra AI view of the alerts it watches and what it did about them | [Alerts](/guides/alerts) |
| Welcome credit | EUR 59 of credit for 30 days, given when the organisation saves a payment method | [Pricing explained](/platform/pricing-explained) |
| **Work** | The Ankra AI view of its tickets | [AI board](/platform/ai-board) |
| Worker vCPU-hour | One vCPU of a worker node for one hour: the unit the platform fee is metered in | [Pricing explained](/platform/pricing-explained) |
