title: Quickstart
description: "In about 15 minutes, connect a Kubernetes cluster to Ankra (or start a free playground), deploy your first Stack, and ask Ankra's AI about what is running."
---

Each step below ends with something you can see, so you know it worked before you move on.

**What you need:** an Ankra account ([sign up at platform.ankra.app](https://platform.ankra.app)), and either a Kubernetes cluster you can run `helm` against, or nothing at all - the free playground gives you a cluster.

---

## 1. Get a cluster

<Tabs>
  <Tab title="No cluster: use the playground">
    The [playground](/guides/cluster-sandbox) is a real, writable Kubernetes cluster that Ankra runs for you. It is ready in about two minutes and needs no cloud account.

    <Steps>
      <Step title="Start it">
        On your first visit, the dashboard offers **See a demo app first** - click **Start the playground**. You land on the new cluster's overview and can watch it provision.
      </Step>
      <Step title="Check it is ready">
        When it is ready, the overview shows **Your app is live** with the public URL of a small starter app Ankra deployed for you. Open it.
      </Step>
    </Steps>

    The free playground expires after the organisation has been away for 3 hours (a week on a paid plan), with a warning first. Everything you do here works the same on your own cluster.
  </Tab>
  <Tab title="Connect your own cluster">
    Any conformant cluster works: EKS, GKE, AKS, k3s, kind, minikube or on-premises. You need `helm` and a kubeconfig that can create a namespace.

    <Steps>
      <Step title="Create the cluster in Ankra">
        Go to **Clusters**, click **Import**, give the cluster a name, and click **Import cluster**. The Git repository and add-on fields are optional - you can add both later.
      </Step>
      <Step title="Install the agent">
        Ankra shows a `helm` command for this cluster. Copy it exactly as shown - it carries your cluster's token and pins the agent version - and run it wherever your kubeconfig points at the cluster. It looks like this:

        ```bash
        helm upgrade --install ankra-agent oci://registry.ankra.cloud/ankra/ankra-agent \
          --version <version> \
          --set config.ankra_url=https://platform.ankra.app \
          --set config.token=<your-cluster-token> \
          --namespace=ankra --create-namespace
        ```

        The agent only makes outbound connections to Ankra, so it works behind firewalls, NAT and private networks.
      </Step>
      <Step title="Check it is connected">
        The cluster's status changes from **Awaiting Connection** to **Healthy**, usually within a minute. Open the cluster: you can now browse its workloads, events and logs.

        Not connecting? Run `kubectl get pods -n ankra` and see [Ankra Agent troubleshooting](/concepts/cluster-agent).
      </Step>
    </Steps>
  </Tab>
</Tabs>

<Tip>
Want Ankra to build a new cluster on Hetzner, AWS, DigitalOcean or another provider, or create EKS, GKE or AKS for you? See [Add a cluster](/guides/import-cluster) - then come back to step 2.
</Tip>

## 2. Deploy your first Stack

A **Stack** is what a cluster should run: Helm charts (called [add-ons](/concepts/addons)) and your own Kubernetes YAML ([manifests](/concepts/manifests)), deployed together in the right order. You will deploy [Grafana](https://grafana.com/oss/grafana/), the dashboarding tool, so there is something real to look at.

<Steps>
  <Step title="Open the Stack Builder">
    Open your cluster, go to **Stacks**, and click **+ Create**. The builder canvas opens.
  </Step>
  <Step title="Add the add-on">
    Click **Add Add-on**, search for **Grafana**, and select it. The defaults are fine - click the add-on on the canvas if you want to see or change its Helm values.
  </Step>
  <Step title="Deploy it">
    Name the Stack (for example `dashboards`) and click **Create Stack**. This saves and deploys it in one step, straight through the agent - no Git repository needed.
  </Step>
  <Step title="Check it is running">
    The Stack's status moves to deployed within a minute or two. Go to **Kubernetes** → **Workloads** → **Pods** and you will see the `grafana` pod **Running**.
  </Step>
</Steps>

<Note>
You can build the same Stack by asking the AI instead: press <kbd>⌘</kbd> + <kbd>J</kbd> (<kbd>Ctrl</kbd> + <kbd>J</kbd> on Windows and Linux) and type *"Add a Stack with Grafana to this cluster"*. The AI picks the chart, builds the Stack and deploys it for you.
</Note>

---

## 3. Ask the AI about it

Ankra's AI sees what you are looking at - the pod's logs, events, manifest and recent deploys - so you can ask plain questions without pasting anything.

<Steps>
  <Step title="Open the assistant on the pod">
    Open the `grafana` pod from step 2 and press <kbd>⌘</kbd> + <kbd>J</kbd>. Leave the mode on **Ask**, which reads and explains but does not change anything already running.
  </Step>
  <Step title="Ask a question">
    Try *"Is this pod healthy, and how do I open Grafana and log in?"* or *"What would happen if this pod restarted?"*. The answer is based on your cluster's actual state.
  </Step>
</Steps>

When you want the AI to make changes, switch to **Agent** (it asks you to confirm each change) or **Plan** (you approve a whole plan once). See [AI Assistant](/platform/ai-assistant) for what each mode may do.

---

## 4. Optional: keep the cluster's configuration in Git

Stacks work without Git. Connect a GitHub repository when you want every change to be reviewed, versioned and reversible - Ankra then commits each Stack change to the repository, and commits you push are deployed back to the cluster.

<Steps>
  <Step title="Connect a repository">
    Open the cluster, go to **Settings** → **GitOps**, choose a GitHub credential (or add one), and pick the repository. Nothing extra is installed on the cluster.
  </Step>
  <Step title="Check the commit">
    Your `dashboards` Stack appears in the repository under `clusters/`, as Helm values and manifests you can review like any other code.
  </Step>
</Steps>

See [GitOps](/concepts/gitops) for how two-way sync and conflicts work.

---

## You are done

You now have:

- a cluster connected to Ankra, showing **Healthy**
- a Stack deployed to it, with its pod **Running**
- an answer from the AI based on your cluster's real state
