You manage your infrastructure with Terraform and want Ankra clusters in the same plan. The Ankra Terraform provider is published on the [Terraform Registry](https://registry.terraform.io/providers/ankraio/ankra) as `ankraio/ankra`. This page describes the latest released version, **0.1.6**, exactly as it is.

<Warning>
**Provider 0.1.6 cannot create or update a cluster against the current Ankra API.** Ankra now registers a cluster in the background and answers the request without a cluster ID. Provider 0.1.6 treats that as a failure: `terraform apply` stops with `Failed to create cluster: missing cluster_id`, although Ankra has registered the cluster. Use one of the [alternatives below](#register-clusters-as-code-today) to register clusters as code.
</Warning>

## What 0.1.6 contains

```hcl
terraform {
  required_providers {
    ankra = {
      source  = "ankraio/ankra"
      version = "0.1.6"
    }
  }
}
```

| | In 0.1.6 |
|---|---|
| Provider configuration | None. The provider block takes no arguments; the token is set on each resource. |
| Resources | `ankra_cluster` only |
| Data sources | None |
| `terraform import` | Not supported |
| Detecting changes made outside Terraform | No. Reading a cluster is a no-op, so a plan compares your configuration with Terraform state only. |

### `ankra_cluster`

Registers an imported cluster with its cluster GitOps repository on GitHub, and optional Stacks of raw manifests.

| Argument | Required | Notes |
|---|---|---|
| `cluster_name` | Yes | Changing it replaces the cluster. |
| `ankra_token` | Yes | An Ankra API token. Changing it **replaces the cluster** - Terraform destroys and recreates it. |
| `github_credential_name` | Yes | The name of the GitHub credential in Ankra. |
| `github_repository` | Yes | `my-org/my-repo` |
| `github_branch` | Yes | |
| `stacks` | No | Blocks with `name`, `description` and `manifests`. |
| `stacks.manifests` | No | `name`, `namespace` and `manifest_base64` (the manifest, base64-encoded). Leave `parents` unset: 0.1.6 sends it in a shape the API refuses. |
| `stacks.addons` | No | Do not use. The block's fields do not match the API, which refuses it. |

| Attribute | Notes |
|---|---|
| `cluster_id` | The Ankra cluster ID. |
| `helm_command` | The command that installs the Ankra agent in the cluster. It contains a live agent token. |

`terraform destroy` deletes the cluster from Ankra by name.

## Register clusters as code today

- **`ankra cluster apply`** takes the same cluster definition as a YAML file and can run in any pipeline. See the [ImportCluster YAML schema](/reference/importcluster) and the [Ankra CLI](/integrations/ankra-cli).
- **GitOps** keeps each cluster's Stacks and add-ons in a repository that Ankra syncs. See [GitOps](/concepts/gitops).
- **Terraform without the provider**: call `ankra cluster apply` from a `terraform_data` resource with a `local-exec` provisioner, if the rest of your stack must stay in one Terraform run.

Whichever you pick, keep each cluster managed from one place only, so two tools do not overwrite each other's changes.
