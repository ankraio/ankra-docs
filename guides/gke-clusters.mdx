[Google Kubernetes Engine (GKE)](https://cloud.google.com/kubernetes-engine) is Google Cloud's managed Kubernetes service. Google runs the control plane; Ankra provisions the cluster, then manages everything on top - node pools, Kubernetes upgrades, addons, stacks, GitOps, and AI-assisted operations.

This page covers GKE specifically. For the shared concepts across all managed providers - live options, discovery/import, and day-2 API patterns - see [Managed Kubernetes](/guides/managed-kubernetes).

<Tip>
**Already running GKE?** You can bring it into Ankra two ways. A **managed import** uses your GCP credential: open **Infrastructure → Clusters → Connect a cluster** and choose the **Find a managed cluster** tab, or run `ankra cluster managed discover --provider gke` and `ankra cluster managed import --provider gke`. Ankra fetches the kubeconfig and installs the agent, so there is nothing to run on the cluster, and the cluster gains the same node-pool and upgrade operations as clusters Ankra created. The **Helm import** needs no cloud credential and works for any cluster: the **Install the agent** tab on the same page gives you the command - see [Import an existing cluster](/guides/import-cluster).
</Tip>

## Why GKE with Ankra

- **Live pricing and options** - locations, Kubernetes versions, machine types (GPU types included) and the project's VPC networks are read live with your service account.
- **Standard or Autopilot, with a release channel** - through the API, run node pools you size yourself or let Google manage nodes with Autopilot, and pin the cluster to the `RAPID`, `REGULAR` or `STABLE` channel.

## Before you start

- A **GCP service account key** stored in Ankra, with the **Kubernetes Engine Admin** (`roles/container.admin`) and **Service Account User** (`roles/iam.serviceAccountUser`) roles, and the **Kubernetes Engine API** enabled on the project. To create a VPC network through the API, the service account also needs **Compute Network Admin** (`roles/compute.networkAdmin`) for the `compute.networks.create` permission. See [Google Cloud (GCP) Credentials](/platform/credentials/gcp). If you have none, the create form shows **Add a Google Kubernetes Engine credential first** with an **Add a credential** button.
- A **payment method** on the organisation. Without one the review step warns "A payment method is required to create this cluster." and the create is refused - see [Billing](/platform/billing).
- A role with the `clusters.create` permission. Without it **Add a cluster** reads "Your role does not allow creating clusters."

GitOps is optional: connect a repository at creation and Ankra commits the cluster's stack definitions to Git.

## Creating a GKE cluster

<Tabs>
  <Tab title="Portal">
    The portal creates a Standard cluster with no release channel. Autopilot, a release channel and a new VPC network are set through the API.

    <Steps>
      <Step title="Choose Google Cloud, run by Google">
        Open **Infrastructure → Clusters → Add a cluster** (`/next/clusters/new`). Choose **Google Cloud** as the provider, then **Provider managed** under **Who runs Kubernetes on Google Cloud?**. The page now reads **Add a Google Kubernetes Engine cluster**.
      </Step>
      <Step title="Name and purpose">
        Enter a **Cluster name** (at most 40 characters; GKE allows lowercase letters, digits and hyphens, starting with a letter) and answer **What will this cluster run?**. The answer is required before you can review.
      </Step>
      <Step title="Where it runs">
        Pick the **Google Kubernetes Engine credential** and a **Region** - a zone (`europe-west1-b`) or a region (`europe-west1`). Locations load live from Google Cloud. Then pick the **VPC network** the cluster attaches to: Ankra lists the project's networks, and preselects `default` when the project has one. See [VPC networking](#vpc-networking).
      </Step>
      <Step title="Worker nodes">
        Each node group has a **Group name**, a number of **Nodes**, a **Size for** the group (machine types with live pricing) and **Scale this group automatically** with **At least** and **At most**. **Add a node group** adds another; **Placement, labels and taints** holds node labels and taints.
      </Step>
      <Step title="Kubernetes and Git">
        Pick a **Kubernetes version** or keep **Provider default**. Under **Cluster configuration in Git**, optionally choose a **Git connection**, **Repository** and **Branch**.
      </Step>
      <Step title="Review and create">
        Click **Review cluster**, check the settings and the **Checks before creating**, then click **Create cluster**. Ankra provisions the cluster, retrieves the kubeconfig and installs the Ankra agent. The page reads **Your cluster is ready** when it is done.
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">

    <CliVersion since="0.5.1" />

    ```bash
    ankra cluster managed create \
      --provider gke \
      --name my-gke-cluster \
      --credential-id <gcp-credential-id> \
      --location europe-west1 \
      --node-pool-name workers \
      --node-pool-size e2-standard-4 \
      --node-pool-count 2
    ```

    The release channel and Autopilot mode are set through the API only; `--autoscaling` with `--autoscaling-min` and `--autoscaling-max` sets the initial pool's bounds.
  </Tab>
  <Tab title="API">
    ```bash
    curl -X POST https://platform.ankra.app/org/clusters/managed/gke \
      -H "Authorization: Bearer $ANKRA_API_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{
        "name": "my-gke-cluster",
        "credential_id": "<gcp-credential-id>",
        "location": "europe-west1",
        "kubernetes_version": "1.32.3",
        "node_pools": [
          {
            "name": "workers",
            "size": "e2-standard-4",
            "count": 2,
            "autoscaling": {"enabled": true, "min_count": 2, "max_count": 5}
          }
        ],
        "gke": {"release_channel": "REGULAR", "mode": "standard"}
      }'
    ```

### GKE options

| Field | Description |
|-------|-------------|
| `gke.release_channel` | `RAPID`, `REGULAR`, or `STABLE` |
| `gke.mode` | `standard` (you manage node pools) or `autopilot` (Google manages nodes) |
| `gke.network` | The VPC network the cluster attaches to, by name. Omitted, GKE assumes a network literally named `default` - which many projects don't have, so pick one explicitly |
| `gke.subnetwork` | Optional subnetwork override. For custom-mode networks Ankra resolves the subnetwork in the cluster's region automatically when this is omitted |

<Note>
**Autopilot** clusters ignore node-pool sizing - Google manages the nodes automatically. Cluster names are lowercase letters, numbers, and hyphens, and must start with a letter.
</Note>

## VPC networking

Every GKE cluster attaches to a VPC network. The **VPC network** field lists the project's networks live with your credential and preselects `default` when the project has one; projects without a `default` network must pick one explicitly - otherwise the GKE API fails the create with "no network named default". The subnetwork for the cluster's region is resolved automatically (auto-mode networks have one per region; for custom-mode networks Ankra picks the region's subnetwork).

Don't have a usable network? The portal cannot create one. Create it through the API: the VPC is created in **auto subnet mode** - Google creates a subnetwork in every region, exactly like the built-in `default` network - so the cluster can attach in any location with no further subnet setup. It then appears in the **VPC network** list:

```bash
curl -X POST https://platform.ankra.app/api/v1/clusters/managed/gke/networks \
  -H "Authorization: Bearer $ANKRA_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"credential_id": "<gcp-credential-id>", "name": "my-vpc"}'
```

<Warning>
Creating a network requires the `compute.networks.create` permission, which is **not** part of the base GKE provisioning roles. Grant **Compute Network Admin** (`roles/compute.networkAdmin`) to the service account - see [Google Cloud (GCP) Credentials](/platform/credentials/gcp). Without it, the create fails with `Required 'compute.networks.create' permission`; attaching to an existing network keeps working.
</Warning>

## Verify

The create progress view follows the control plane, the node pools, kubeconfig retrieval and the Ankra Agent install. The cluster shows **Online** once the agent has connected. Then point `kubectl` at it through Ankra - this needs a [Cluster Access](/guides/cluster-access) grant - and check that every node is `Ready`:

```bash
ankra cluster kubeconfig add <cluster-name> --use
kubectl get nodes
```

See [Accessing Clusters with kubectl](/guides/kubeconfig).

## Day-2 operations

Node pools, upgrades, and deletion work from the portal, the CLI or the API. The CLI examples use `--provider gke`:

```bash
# scale a pool to a fixed count
ankra cluster managed node-pool scale <cluster_id> workers --provider gke --count 5

# upgrade the cluster
ankra cluster managed upgrade <cluster_id> --provider gke --version 1.32.3

# delete the cluster
ankra cluster managed delete <cluster_id> --provider gke
```

In the portal, node pools are under **Infrastructure → Clusters → &lt;your cluster&gt; → Kubernetes → Nodes → Manage nodes and groups**, upgrades under **Settings → Upgrades and maintenance**, and disconnect and delete under **Settings → Terminate or remove**. GKE clusters cannot be stopped and started. Autoscaling bounds are set from the portal (**Change autoscaling** on a pool), with `ankra cluster managed node-pool update --autoscaling --autoscaling-min <n> --autoscaling-max <n>`, or with the `PATCH .../node-pools/{name}` endpoint. See [Managed Kubernetes - day-2 operations](/guides/managed-kubernetes#day-2-operations) for the shared mechanics.

## Importing an existing GKE cluster

Already running GKE? Discover clusters in your project and adopt them into Ankra without touching them. Discovery and import run from the portal (**Infrastructure → Clusters → Connect a cluster → Find a managed cluster**), the CLI (`ankra cluster managed discover --provider gke`, then `ankra cluster managed import --provider gke`) or the API - see [Managed Kubernetes - importing existing clusters](/guides/managed-kubernetes#importing-existing-clusters).
