Choose DigitalOcean when your team already runs on DigitalOcean and you want a Kubernetes cluster whose control plane you own, on Droplets in your own account. Ankra creates the VPC, NAT gateway, bastion and Droplets, installs Kubernetes and the DigitalOcean cloud integration, and then operates the cluster for you - this is an **Ankra Managed** cluster. DigitalOcean bills you directly. If you would rather DigitalOcean ran the control plane, use [DOKS](/guides/doks-clusters) instead; [Managed Kubernetes](/guides/managed-kubernetes) compares the two.

## Before you start

- A **payment method** on the organisation. Without one, the create is refused with "Add a payment method to create this cluster." See [Credit and payment method](/platform/billing#credit-and-payment-method).
- A **DigitalOcean personal access token** with read and write scope, stored as a [DigitalOcean credential](/platform/credentials/digitalocean): **Integrations & alerts → Credentials → Add credential → DigitalOcean**, or **Add a credential** inside the create form. Tokens start with `dop_v1_`.
- An **SSH key credential** - your own public key, or one Ankra generates. See [SSH Key Credentials](/platform/credentials/ssh-key).
- Room in your account limits for the Droplets, a VPC, load balancers and volumes. Check them in the [DigitalOcean Control Panel](https://cloud.digitalocean.com/); DigitalOcean support raises them.

## Create the cluster

<Tabs>
  <Tab title="Portal">
    Follow [Create a Cluster](/guides/create-a-cluster) with these DigitalOcean choices:

    <Steps>
      <Step title="Choose DigitalOcean">
        Go to **Infrastructure → Clusters**, click **Add a cluster**, pick **DigitalOcean**, then **Ankra managed** under **Who runs Kubernetes on DigitalOcean?** (**Provider managed** creates a [DOKS](/guides/doks-clusters) cluster).

        The form **Add a DigitalOcean cluster** opens.
      </Step>
      <Step title="Where it runs">
        Choose the **DigitalOcean credential**, the **Region** and, if you want to sign in over SSH yourself, an **SSH key**, for example `nyc3`, `fra1` or `lon1`. Only regions DigitalOcean reports as available are listed.
      </Step>
      <Step title="Control plane, servers and worker nodes">
        Pick **Single node** or **High availability**, the **Control plane size**, the **Management server** size, and one or more node groups. Each size field lists the region's Droplet sizes, with prices, under **Exact server type**; GPU Droplets (`gpu-` sizes) are listed there only. The form starts with `s-2vcpu-4gb` for the control plane and workers.
      </Step>
      <Step title="Advanced configuration (optional)">
        **Private network range** is the cluster's VPC, a private range from `/16` to `/28`. Leave it empty and Ankra picks a `10.x.y.0/24` for the cluster, different for each cluster. **Addresses allowed to reach the management server** limits SSH to the bastion.
      </Step>
      <Step title="Review and create">
        Click **Review cluster**. Ankra checks the name and settings here; your DigitalOcean account is checked when creation starts. Check the cost, then click **Create cluster**. The progress page follows the stages to **&lt;cluster name&gt; is ready**.
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">
    <CliVersion since="0.61.0" />

    ```bash
    ankra credentials digitalocean create --name my-do-token   # prompts for the token
    ankra credentials digitalocean ssh-key create --name my-ssh-key --generate

    # What your credential can deploy
    ankra cluster digitalocean regions --credential-id <digitalocean-credential-id>
    ankra cluster digitalocean sizes --credential-id <digitalocean-credential-id> --region nyc3 --available-only

    ankra cluster digitalocean create \
      --name my-cluster \
      --credential-id <digitalocean-credential-id> \
      --ssh-key-credential-id <ssh-key-credential-id> \
      --region nyc3 \
      --control-plane-count 1 \
      --control-plane-size s-2vcpu-4gb \
      --worker-count 2 \
      --worker-size s-2vcpu-4gb
    ```

    `--distribution k3s`, `--etcd-topology external` with `--etcd-node-count` and `--etcd-size`, `--include-networking=false`, `--gateway-api` ([Gateway API](/guides/gateway-api)), `--network-ip-range`, `--bastion-allowed-ips` and the `--gitops-*` flags cover the other choices.
  </Tab>
  <Tab title="API">

## Verify

1. In **Infrastructure → Clusters**, the cluster's status moves from **In progress** to **Online** once the Ankra Agent has connected.
2. Point `kubectl` at it through Ankra (this needs a [Cluster Access](/guides/cluster-access) grant) and check the nodes:

   <CliVersion since="0.3.0" command="cluster kubeconfig add" />

   ```bash
   ankra cluster kubeconfig add my-cluster --use
   kubectl get nodes
   ```

   Every control plane and worker should be `Ready`. See [Accessing Clusters with kubectl](/guides/kubeconfig).

## What Ankra created in your account

- **A VPC** for all traffic between the Droplets.
- **A VPC NAT gateway**, set as the VPC's default route - the egress path for the nodes. DigitalOcean bills it separately; see [VPC NAT gateway pricing](https://docs.digitalocean.com/products/networking/vpc/details/pricing/).
- **A bastion Droplet** - the only Droplet with a public IP and the only SSH entry point. It carries no workload or egress traffic.
- **Control plane and worker Droplets** with private IPs only, and dedicated etcd Droplets for a kubeadm cluster with external etcd.
- **Two tag-scoped cloud firewalls**, kept as defence in depth.
- **The `digitalocean-cloud-provider` stack**: the DigitalOcean cloud controller manager (load balancers for `LoadBalancer` Services) and CSI driver (block storage through the `do-block-storage` StorageClass), using your credential.

The [DigitalOcean Reference](/reference/digitalocean#architecture) has the full layout.

## DigitalOcean specifics

<CliVersion since="0.31.0" command="cluster digitalocean bastion allowed-ips" />

- **Clusters created before private-Droplet support** keep their original layout: every Droplet has a public IP and the tag-scoped cloud firewalls are the ingress boundary. Public networking is fixed when a Droplet is created, so those clusters - including nodes added when you scale them - stay on that model. Only new clusters get private nodes and a NAT gateway.
- **Resizing a node group** powers each Droplet off, resizes it and powers it on again, with brief downtime for its workloads. Droplet sizes only grow; for smaller nodes, create a new group and delete the old one.
- **SSH allowlist.** At create time, **Addresses allowed to reach the management server** (or `--bastion-allowed-ips`) limits SSH to the bastion to the IPv4 addresses or ranges you list; empty allows any address. On a running cluster, replace the list with `ankra cluster digitalocean bastion allowed-ips my-cluster 203.0.113.7 198.51.100.0/24`, or remove it with `--clear`.
- **A stop** deletes the node Droplets, the bastion and the VPC NAT gateway, and keeps the cluster's configuration, network definition and SSH keys. The block storage volumes the CSI driver created are kept and keep billing while the cluster is stopped.
- **Terminating** deletes the Droplets, NAT gateway, VPC and SSH keys. Anything left over from an earlier teardown can be removed in the [DigitalOcean Control Panel](https://cloud.digitalocean.com/).

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Cluster stuck in provisioning | Check the token's permissions and your account limits |
| Invalid API token | Create a new read and write token in the [DigitalOcean Control Panel](https://cloud.digitalocean.com/account/api/tokens) (prefixed `dop_v1_`) and [rotate the credential](/platform/credentials/digitalocean) |
| Droplet size unavailable | Try another region or size; `ankra cluster digitalocean sizes --available-only` lists what the region offers |
| Cannot scale workers | Check that the cluster is **Online** and no operation is running |
| `LoadBalancer` Service stuck in `Pending` | Check that the CCM runs in the `digitalocean-cloud-provider` namespace |
| PVCs stuck in `Pending` | Check that the CSI driver runs and the `do-block-storage` StorageClass exists |
