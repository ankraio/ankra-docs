---
title: Connect a Local minikube Cluster
description: Start a minikube cluster on your own machine and connect it to Ankra with the agent install command, to try Stacks and add-ons locally.
---

Use this guide to run Kubernetes on your laptop with [minikube](https://minikube.sigs.k8s.io/docs/) and manage it with Ankra. You end with a local cluster that shows as connected in Ankra, ready for [add-ons](/concepts/addons). The Ankra agent only makes outbound connections to Ankra, so your machine needs no inbound port.

## Before you start

- **A payment method on the organisation.** Without one, the connect page warns "Add a payment method before you connect a cluster" and adding the cluster is refused. See [Credit and payment method](/platform/billing#credit-and-payment-method).
- **The `clusters.create` permission.** Without it the page says "Your role does not allow adding clusters." Showing the install command also needs `agents.manage`, because the command contains the agent's access token. See [Roles and access](/guides/roles-and-access).
- **A minikube driver**: [Docker](https://docs.docker.com/get-docker/), [Podman](https://podman.io/docs/installation), [VirtualBox](https://www.virtualbox.org/wiki/Downloads), [Hyper-V](https://learn.microsoft.com/en-us/virtualization/hyper-v-on-windows/about/) or [KVM](https://minikube.sigs.k8s.io/docs/drivers/kvm2/).
- **[`kubectl`](https://kubernetes.io/docs/tasks/tools/)** and **[Helm](https://helm.sh/docs/intro/install/)**. The install command Ankra gives you runs `helm`.

## Start minikube

<Steps>
  <Step title="Install minikube">
    <Tabs>
      <Tab title="macOS">
        ```bash
        brew install minikube
        ```
      </Tab>
      <Tab title="Linux">
        ```bash
        curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64
        sudo install minikube-linux-amd64 /usr/local/bin/minikube
        ```
      </Tab>
      <Tab title="Windows">
        ```powershell
        choco install minikube
        ```
      </Tab>
    </Tabs>

    Other methods are in the [minikube documentation](https://minikube.sigs.k8s.io/docs/start/). Check it with `minikube version`.
  </Step>
  <Step title="Start the cluster">
    ```bash
    minikube start
    ```

    The first start downloads the images it needs. When it finishes, `kubectl config current-context` prints `minikube`.
  </Step>
</Steps>

## Connect it to Ankra

<Tabs>
  <Tab title="Portal">
    <Steps>
      <Step title="Open the connect page">
        Go to **Infrastructure → Clusters** and click **Connect a cluster** (`/next/clusters/import`). The page **Connect an existing cluster** opens on the **Install the agent** tab.
      </Step>
      <Step title="Name the cluster">
        Under **Name and purpose**, enter the **Cluster name** (3 to 53 lowercase letters, digits and hyphens, starting with a letter), for example `my-laptop`. Under **What will this cluster run?**, pick **Local**. Click **Get the install command**.

        The page now reads **Install the agent in &lt;cluster name&gt;** and shows the install command.
      </Step>
      <Step title="Run the install command">
        The install command is already on the page. Check that `kubectl` points at minikube first:

        ```bash
        kubectl config current-context
        ```

        It must print `minikube`, because the command installs into whichever cluster your kubeconfig points at. Then copy the command under **Run this in your terminal** and run it in the same terminal. It installs the agent in the `ankra` namespace with Helm.

        <Warning>
        The command contains this cluster's agent token. Do not share it or commit it to Git.
        </Warning>
      </Step>
      <Step title="Wait for the connection">
        Under the command, a picture of the cluster and Ankra says **Connecting** until the agent reports in, usually within a minute. **Check now** reads the status again. Once the agent has reported, the picture says **Connected** and the page reads **&lt;cluster name&gt; is connected**. Click **Open the cluster**.
      </Step>
    </Steps>
  </Tab>
  <Tab title="MCP">
    The `import_cluster` tool adds the cluster to Ankra without provisioning anything. It needs a token with the `mcp:write` scope. Run the agent install command it returns against minikube, as in the portal steps. See [MCP tools](/platform/mcp-tools).
  </Tab>
</Tabs>

## Verify

1. Check the agent pod in minikube:

   ```bash
   kubectl get pods -n ankra
   ```

   The agent pod is `Running`.
2. In **Infrastructure → Clusters**, the cluster's status reads **Online**.

## Reach LoadBalancer Services

minikube gives a `LoadBalancer` Service no external address on its own. To get one, run this in a separate terminal and leave it running:

```bash
minikube tunnel
```

`kubectl get services` then shows an `EXTERNAL-IP` for each `LoadBalancer` Service.

## What can go wrong

| What you see | What to do |
|---|---|
| "Add a payment method before you connect a cluster" | Click **Add a payment method**, save one, then come back to the page |
| "Your role does not allow adding clusters." | Ask an organisation owner for the `clusters.create` permission |
| "Your role cannot show the install command" | Ask an organisation owner to show it, or to grant you `agents.manage` |
| The picture stays on **Connecting**, then says **No connection yet** | Check `kubectl get pods -n ankra` on minikube. The machine must reach the addresses and ports in the agent's [network requirements](/concepts/cluster-agent#network-requirements) |
| The agent went into another cluster | `kubectl config current-context` did not print `minikube`. Run `kubectl config use-context minikube` and run the command again |
