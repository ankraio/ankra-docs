Cloudflare Tunnel exposes services running in your cluster to the internet without public IPs, open firewall ports or certificates you manage yourself. You create the tunnel in Cloudflare, then run its connector, `cloudflared`, on your cluster as a [Stack](/concepts/stacks) of three manifests. The tunnel token is sealed with your organisation's encryption key, so it never reaches Git in plain text.

You end up with a `cloudflare-tunnel` Stack on your cluster and a service answering on a Cloudflare hostname. It takes about 20 minutes.

| Ingress on the cluster | Cloudflare Tunnel |
|---------------------|-------------------|
| Needs a public IP or a LoadBalancer | Works behind NAT, no public IP needed |
| Ports 80 and 443 open to the internet | No inbound ports |
| Certificates issued on the cluster | TLS ends at Cloudflare |
| DNS records point at the cluster | Cloudflare creates the hostname's record |

A tunnel suits clusters on premises or in private networks, development and staging clusters, and services you want behind Cloudflare Access.

## Before you start

- **A Cloudflare account** with a domain added.
- **A cluster connected to Ankra** and online, with the service you want to expose running on it. See [Import a cluster](/guides/import-cluster).
- **A role that may create and deploy Stacks** on that cluster. See [Create and change a stack](/guides/create-and-change-a-stack).
- **The organisation's encryption key.** Open **Infrastructure → Variables and secrets**. If **Encryption key** reads **No encryption key yet**, click **Make the key** (it needs a role that may manage the key). See [SOPS](/guides/sops).
- **The `ankra` CLI**, signed in to your organisation, to seal the token.

## Step 1: Create the tunnel in Cloudflare

<Steps>
  <Step title="Open Tunnels">
    In the [Cloudflare dashboard](https://dash.cloudflare.com), open **Zero Trust**, then **Networks** → **Tunnels**.
  </Step>
  <Step title="Create a tunnel">
    Click **Create a tunnel**, choose **Cloudflared** as the connector type, and give it a name such as `my-cluster-tunnel`.
  </Step>
  <Step title="Copy the tunnel token">
    Cloudflare shows the token in its install command (it starts `eyJ`). Copy it; you need it in Step 3. Do not install the connector: the Stack runs it. Click **Next**.
  </Step>
  <Step title="Add a public hostname">
    Add a hostname for your service:
    - **Subdomain**: for example `app`
    - **Domain**: your Cloudflare domain
    - **Service**: `http://<service>.<namespace>.svc.cluster.local:<port>`

    Click **Save tunnel**. The tunnel shows as **Inactive** until the connector runs.
  </Step>
</Steps>

## Step 2: Create the Stack in Ankra

The Stack holds a Namespace, the Secret with the token, and the `cloudflared` Deployment, in that order. The steps below use the stack editor; [Create and change a stack](/guides/create-and-change-a-stack) explains each screen.

<Steps>
  <Step title="Start the draft">
    Open **Clusters → &lt;your cluster&gt;**, then **Stacks** under **Technical details**. Click **Create a stack**, keep **Compose a stack**, enter `cloudflare-tunnel` as the **Stack name**, and click **Start the draft**.

    The stack editor opens and reads **No resources yet**.
  </Step>
  <Step title="Add the namespace">
    Click **Add → Manifest**. Enter `cloudflare-namespace` as the **Resource name**, paste this into **Manifest source**, and click **Add to draft**:

    ```yaml
    apiVersion: v1
    kind: Namespace
    metadata:
      name: cloudflare
    ```
  </Step>
  <Step title="Add the Secret, with a placeholder">
    Click **Add → Manifest** again. Enter `cloudflare-tunnel-token` as the **Resource name** and paste the Secret below. Leave the placeholder: you set the real token in Step 3, sealed, so it is never stored in plain text.

    ```yaml
    apiVersion: v1
    kind: Secret
    metadata:
      name: cloudflare-tunnel-token
      namespace: cloudflare
    type: Opaque
    stringData:
      token: replace-me
    ```

    Click **Add to draft**.
  </Step>
  <Step title="Add the cloudflared Deployment">
    Click **Add → Manifest**, enter `cloudflared` as the **Resource name**, paste this and click **Add to draft**. Replace `latest` with a release tag from [cloudflared's releases](https://github.com/cloudflare/cloudflared/releases) so every deploy runs the same version.

    ```yaml
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: cloudflared
      namespace: cloudflare
    spec:
      replicas: 2
      selector:
        matchLabels:
          app: cloudflared
      template:
        metadata:
          labels:
            app: cloudflared
        spec:
          containers:
            - name: cloudflared
              image: cloudflare/cloudflared:latest
              args:
                - tunnel
                - --no-autoupdate
                - --metrics
                - 0.0.0.0:2000
                - run
                - --token
                - $(TUNNEL_TOKEN)
              env:
                - name: TUNNEL_TOKEN
                  valueFrom:
                    secretKeyRef:
                      name: cloudflare-tunnel-token
                      key: token
              resources:
                requests:
                  memory: 64Mi
                  cpu: 10m
                limits:
                  memory: 128Mi
                  cpu: 100m
              livenessProbe:
                httpGet:
                  path: /ready
                  port: 2000
                initialDelaySeconds: 10
                periodSeconds: 10
    ```

    The editor now shows three resources and reads **All changes saved**.
  </Step>
  <Step title="Set the order">
    Select `cloudflare-tunnel-token`, open its **Parents** tab and tick `cloudflare-namespace` under **Depends on**. Then select `cloudflared` and tick `cloudflare-tunnel-token`.

    The **Graph** draws namespace, then Secret, then Deployment.
  </Step>
  <Step title="Review and deploy">
    Click **Review changes**, read the **Draft change log**, then click **Create and deploy stack**.

    The editor reads "Deployment accepted. Follow the operation for its outcome." Follow it in **Deployments** in the editor, or the cluster's **Operations**. The `cloudflared` pods restart in a loop until the token is set in Step 3, and their log reads `Provided Tunnel token is not valid.` That is expected.
  </Step>
</Steps>

## Step 3: Set the token, sealed

Set the real token and seal it in one command. The CLI applies the value in memory, sends the document to Ankra to be encrypted with your organisation's key, and writes the sealed result back to the Stack in a single change, so the plain token never reaches Git history.

<CliVersion since="0.20.0" />

```bash
ankra cluster encrypt manifest cloudflare-tunnel-token \
  --key token \
  --set 'stringData.token=<your-tunnel-token>' \
  --cluster my-cluster
```

Every cluster decrypts sealed values when it deploys them; there is nothing to turn on per cluster. The one exception is a playground: while the organisation has a cluster of its own, the playground's agent is not handed the organisation's key, so run the tunnel on one of your own clusters.

In Git, the Secret then looks like this, with `ENC[...]` in place of the token and the encryption parameters in the `sops` block:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: cloudflare-tunnel-token
  namespace: cloudflare
type: Opaque
stringData:
  token: ENC[AES256_GCM,data:...,iv:...,tag:...,type:str]
sops:
  age:
    - recipient: age1...
      enc: |
        -----BEGIN AGE ENCRYPTED FILE-----
        ...
        -----END AGE ENCRYPTED FILE-----
  encrypted_regex: ^(token)$
```

To rotate the token later, run the same command with the new token. See [SOPS](/guides/sops) for how sealing works.

## Verify

1. The pods are running:

   ```bash
   ankra cluster get pods -n cloudflare --cluster my-cluster
   ```

   Both `cloudflared` pods read `Running`.
2. In Cloudflare's **Zero Trust** → **Networks** → **Tunnels**, your tunnel reads **Healthy**.
3. Open your hostname, for example `https://app.example.com`. Your service answers.

## Add more services

You choose which services the tunnel exposes in Cloudflare, not in Kubernetes. Open the tunnel in **Zero Trust** → **Networks** → **Tunnels**, then open **Configure**, choose **Public Hostname** and click **Add a public hostname**, and give each one a service URL in this form:

```
http://SERVICE_NAME.NAMESPACE.svc.cluster.local:PORT
```

| Hostname | Service |
|----------|---------|
| `app.example.com` | `http://frontend.default.svc.cluster.local:80` |
| `api.example.com` | `http://backend.default.svc.cluster.local:3000` |
| `grafana.example.com` | `http://grafana.monitoring.svc.cluster.local:3000` |

## Run more replicas across nodes

For production, open `cloudflared` in the stack editor, edit its **Source** tab, and spread three replicas over different nodes:

```yaml
spec:
  replicas: 3
  template:
    spec:
      affinity:
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
            - weight: 100
              podAffinityTerm:
                labelSelector:
                  matchLabels:
                    app: cloudflared
                topologyKey: kubernetes.io/hostname
```

Then **Review changes** and **Deploy reviewed changes**.

## Put Cloudflare Access in front

Cloudflare Access adds sign-in in front of a tunnel hostname: in **Zero Trust** → **Access** → **Applications**, click **Add an application**, choose **Self-hosted**, enter the tunnel hostname and add the policies you need. See [Cloudflare's Access documentation](https://developers.cloudflare.com/cloudflare-one/policies/access/).

## What can go wrong

<AccordionGroup>
  <Accordion title="The tunnel stays Inactive">
    1. Check the pods and their logs:
       ```bash
       ankra cluster get pods -n cloudflare --cluster my-cluster
       ankra cluster logs -l app=cloudflared -n cloudflare --tail 50 --follow=false --cluster my-cluster
       ```
    2. If the logs read `Provided Tunnel token is not valid.`, the Secret still holds `replace-me`, an old token, or something that is not the tunnel token. Run the command in [Step 3](#step-3-set-the-token-sealed) again with the token from Cloudflare's install command.
    3. If the deployment failed, open the cluster's **Operations** for the failing step.
  </Accordion>
  <Accordion title="502 Bad Gateway">
    The tunnel works but cannot reach the service.
    1. Check the service URL in Cloudflare.
    2. Check the service exists:
       ```bash
       ankra cluster get services -n <namespace> --cluster my-cluster
       ```
    3. Call it from inside the cluster. The `cloudflared` image has no shell and no `wget` or `curl`, so run the call from another pod of yours whose image has `wget`:
       ```bash
       ankra cluster exec <pod> -n <pod-namespace> --cluster my-cluster -- wget -qO- http://<service>.<namespace>.svc.cluster.local:<port>
       ```
  </Accordion>
  <Accordion title="The hostname does not resolve">
    1. A new hostname can take a few minutes to answer.
    2. Check the hostname is configured on the tunnel in Cloudflare.
    3. Check your domain's name servers point to Cloudflare.
  </Accordion>
</AccordionGroup>
