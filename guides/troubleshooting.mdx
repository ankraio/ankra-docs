title: Troubleshooting by Symptom
description: Start from what you see - a crash-looping pod, a failed deploy, an offline cluster, a pending certificate, a missing pipeline run - and go to the page that fixes it.
---

Find the row that matches what you see and follow its link. For the general order of checks on a cluster that misbehaves, read [Troubleshoot a Cluster](/guides/troubleshoot-a-cluster) first.

## By symptom

| You see | Where it shows | Go to |
|---------|----------------|-------|
| A pod is crash-looping | **Health → Pods** counts it under crash-looping; the pod's **Restarts** keep rising | [Troubleshoot a Cluster → Read what the containers printed](/guides/troubleshoot-a-cluster#3-read-what-the-containers-printed): read **Previous instance** on the pod's **Logs** tab, then [Logs](/platform/logs) |
| A pod stays Pending | **Health → Pods** counts it under pending; the pod's phase reads Pending | [Troubleshoot a Cluster → Find the object in Kubernetes](/guides/troubleshoot-a-cluster#2-find-the-object-in-kubernetes): the pod's **Events** say why it was not scheduled. When no node has room, add nodes in [Cluster Nodes](/platform/cluster-nodes) or turn on [Cluster Autoscaling](/guides/cluster-autoscaling) |
| A deploy failed | The cluster's **Technical details → Operations** lists a failed operation | [Find out why a deploy failed and retry it](/platform/operations) |
| The cluster is offline | The cluster shows **Offline**; **Health** says `The cluster agent is offline. These are the last reported readings.` | [Ankra Agent → Troubleshooting](/concepts/cluster-agent#troubleshooting), and [what still works meanwhile](/guides/troubleshoot-a-cluster#when-the-agent-is-offline) |
| A cluster's health check is not healthy | The cluster's **Health** page shows a check or a score that is not healthy | [Read a cluster's overview and health → Go from a check that is not healthy](/platform/cluster-overview-and-health#4-go-from-a-check-that-is-not-healthy) |
| A hostname has no certificate, or does not resolve | The certificate stays pending; the Ingress host does not answer | [Use Your Own Domain → What can go wrong](/guides/use-your-own-domain#what-can-go-wrong) |
| A push or pull request made no pipeline run | No `Ankra pipeline` check on the commit, or a check that says why nothing ran | [Ankra CI Troubleshooting](/guides/ankra-ci-troubleshooting#a-push-or-pull-request-started-no-run) |
| The bill went up | The invoice or the usage report is higher than last period | [Usage](/platform/usage) for which meter grew and on which cluster, [Cloud Cost](/platform/cloud-cost) for each cluster's spend, [Cost Budgets and the Autopilot](/guides/cost-budgets-and-autopilot) to cap it |
| A log search finds nothing older than the containers keep | **Cluster logs → History** offers to set up a log store | [Ankra Hosted Logs](/guides/hosted-logs), or connect a [log source](/integrations/log-sources) |
| No shell in the container | The **Exec** tab connects and the shell exits, or the image is distroless | [Debug Pods](/platform/debug-pods) |
| A Secret's values read `[protected]` | The Secret's **YAML** tab | [Kubernetes Resources → Secrets](/platform/kubernetes-insights#secrets) |

## By message

Messages as the product shows them, with the page that explains each.

| Message | Where | Explained on |
|---------|-------|--------------|
| `The cluster agent is offline. These are the last reported readings.` | Cluster **Health** | [Troubleshoot a Cluster](/guides/troubleshoot-a-cluster#when-the-agent-is-offline) |
| `The cluster is offline. These are previously recorded resources.` | Kubernetes resource lists | [Kubernetes Resources](/platform/kubernetes-insights#resource-lists) |
| `The cluster agent is offline, so no pods are reported.` | Pods list | [Troubleshoot a Cluster](/guides/troubleshoot-a-cluster#when-the-agent-is-offline) |
| `A stack or a Helm release declares this object. Change it there.` | **Review resource actions** | [Kubernetes Resources → Change a resource](/platform/kubernetes-insights#change-a-resource) |
| `Your role cannot perform this action.` | **Review resource actions** | [Kubernetes Resources → Change a resource](/platform/kubernetes-insights#change-a-resource) |
| `Your role cannot read container logs on this cluster.` | A pod's **Logs** tab | [Logs](/platform/logs#what-can-go-wrong) |
| `Live logs need the cluster agent.` | **Cluster logs → Live** | [Logs](/platform/logs#what-can-go-wrong) |
| `Ankra hosted logs are on, but no line has arrived from this cluster.` | **Cluster logs → History** | [Logs](/platform/logs#what-can-go-wrong) |
| `The log store could not confirm these lines are this cluster's.` | **Cluster logs → History** | [Log Sources → Sharing one log store between clusters](/integrations/log-sources#sharing-one-log-store-between-clusters) |
| `This search could not be run.` | **Cluster logs → History** | [Logs](/platform/logs#what-can-go-wrong) |
| `This cluster's agent cannot send logs to Ankra yet.` | An application's **Logs → Search** | [Ankra Hosted Logs → What the Logs page tells you](/guides/hosted-logs#what-the-logs-page-tells-you) |
| `Connecting a log store of your own is not available` | **Settings → Integrations → Log store** | [Log Sources → What can go wrong](/integrations/log-sources#what-can-go-wrong) |
| `You need kubernetes.exec permission on this cluster.` | A pod's **Exec** tab | [Pod Terminal → Troubleshooting](/platform/pod-terminal#troubleshooting) |
| `The terminal did not connect. Check the agent and try again.` | A pod's **Exec** tab | [Pod Terminal → Troubleshooting](/platform/pod-terminal#troubleshooting) |
| `AGENT_OUTDATED` | `ankra cluster debug create` | [Debug Pods → Requirements](/platform/debug-pods#requirements) |
| `No trigger this pipeline declares matches this event, so there is nothing to run.` | The `Ankra pipeline` check | [Ankra CI Troubleshooting](/guides/ankra-ci-troubleshooting) |
| `Awaiting authority approval` | The `Ankra pipeline` check | [Ankra CI Troubleshooting](/guides/ankra-ci-troubleshooting) |

## Still stuck

Press `⌘J` (`Ctrl+J`) on the page where you see the problem and ask [Ask Ankra](/platform/ai-assistant) about it, or [contact support](/platform/support).
