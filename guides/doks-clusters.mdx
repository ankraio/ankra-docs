[DigitalOcean Kubernetes (DOKS)](https://www.digitalocean.com/products/kubernetes) is DigitalOcean's managed Kubernetes service. DigitalOcean runs the control plane; Ankra provisions the cluster, then manages everything on top - node pools, Kubernetes upgrades, addons, stacks, GitOps, and AI-assisted operations.

This page covers DOKS specifically. For the shared concepts across all managed providers - live options, discovery/import, and day-2 API patterns - see [Managed Kubernetes](/guides/managed-kubernetes).

## Why DOKS with Ankra

- **Live pricing and options** - regions, Kubernetes versions with support windows, and droplet sizes are fetched live with your DigitalOcean token, with a monthly cost summary as you build the cluster.
- **Highly available control plane** - opt into DigitalOcean's HA control plane at creation, through the API.
- **Full day-2 from the portal, the CLI or the API** - add and scale node pools, upgrade Kubernetes, and manage add-ons and Stacks the same way as any Ankra cluster.

## Before you start

- A **DigitalOcean API token** with read/write, stored in Ankra. See [DigitalOcean API Credentials](/platform/credentials/digitalocean). If you have none, the create form shows **Add a DigitalOcean Kubernetes credential first** with an **Add a credential** button.
- A **payment method** on the organisation. Without one the review step warns "A payment method is required to create this cluster." and the create is refused - see [Billing](/platform/billing).
- A role with the `clusters.create` permission. Without it **Add a cluster** reads "Your role does not allow creating clusters."

GitOps is optional: connect a repository at creation and Ankra commits the cluster's stack definitions to Git.

## Creating a DOKS cluster

<Tabs>
  <Tab title="Portal">
    The portal creates the cluster without the HA control plane. To turn HA on, create the cluster through the API.

    <Steps>
      <Step title="Choose DigitalOcean, run by DigitalOcean">
        Open **Infrastructure → Clusters → Add a cluster** (`/next/clusters/new`). Choose **DigitalOcean** as the provider, then **Provider managed** under **Who runs Kubernetes on DigitalOcean?**. The page now reads **Add a DigitalOcean Kubernetes cluster**.
      </Step>
      <Step title="Name and purpose">
        Enter a **Cluster name** (3 to 53 lowercase letters, digits and hyphens, starting with a letter) and answer **What will this cluster run?**. The answer is required before you can review.
      </Step>
      <Step title="Where it runs">
        Pick the **DigitalOcean Kubernetes credential** and a **Region** (for example `fra1`). Regions load live from DigitalOcean.
      </Step>
      <Step title="Worker nodes">
        Each node group has a **Group name**, a number of **Nodes**, a **Size for** the group (Droplet sizes with live pricing) and **Scale this group automatically** with **At least** and **At most**. **Add a node group** adds another; **Placement, labels and taints** holds node labels and taints. The **Estimated monthly cost** panel follows your choices.
      </Step>
      <Step title="Kubernetes and Git">
        Pick a **Kubernetes version** or keep **Provider default**. Under **Cluster configuration in Git**, optionally choose a **Git connection**, **Repository** and **Branch**.
      </Step>
      <Step title="Review and create">
        Click **Review cluster**, check the settings and the **Checks before creating**, then click **Create cluster**. Ankra provisions the cluster, retrieves the kubeconfig and installs the Ankra agent. The page reads **Your cluster is ready** when it is done.
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">

    <CliVersion since="0.5.1" />

    ```bash
    ankra cluster managed create \
      --provider doks \
      --name my-doks-cluster \
      --credential-id <do-credential-id> \
      --location fra1 \
      --node-pool-name workers \
      --node-pool-size s-2vcpu-4gb \
      --node-pool-count 2
    ```

    The HA control plane is set through the API only; `--autoscaling` with `--autoscaling-min` and `--autoscaling-max` sets the initial pool's bounds.
  </Tab>
  <Tab title="API">
    ```bash
    curl -X POST https://platform.ankra.app/org/clusters/managed/doks \
      -H "Authorization: Bearer $ANKRA_API_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{
        "name": "my-doks-cluster",
        "credential_id": "<do-credential-id>",
        "location": "fra1",
        "kubernetes_version": "1.33.1-do.0",
        "node_pools": [
          {"name": "workers", "size": "s-2vcpu-4gb", "count": 2}
        ],
        "ha": true
      }'
    ```

## Verify

The create progress view follows the control plane, the node pools, kubeconfig retrieval and the Ankra Agent install. The cluster shows **Online** once the agent has connected. Then point `kubectl` at it through Ankra - this needs a [Cluster Access](/guides/cluster-access) grant - and check that every node is `Ready`:

```bash
ankra cluster kubeconfig add <cluster-name> --use
kubectl get nodes
```

See [Accessing Clusters with kubectl](/guides/kubeconfig).

## Day-2 operations

Node pools, upgrades, and deletion work from the portal, the CLI or the API. The CLI examples use `--provider doks`:

```bash
# scale a pool to a fixed count
ankra cluster managed node-pool scale <cluster_id> workers --provider doks --count 5

# upgrade the cluster
ankra cluster managed upgrade <cluster_id> --provider doks --version 1.33.1-do.0

# delete the cluster
ankra cluster managed delete <cluster_id> --provider doks
```

In the portal, node pools are under **Clusters → &lt;your cluster&gt; → Kubernetes → Nodes → Manage nodes and groups**, upgrades under **Settings → Upgrades and maintenance**, and disconnect and delete under **Settings → Terminate or remove**. DOKS clusters cannot be stopped and started. Autoscaling bounds are set from the portal (**Change autoscaling** on a pool), with `ankra cluster managed node-pool update --autoscaling --autoscaling-min <n> --autoscaling-max <n>`, or with the `PATCH .../node-pools/{name}` endpoint. See [Managed Kubernetes - day-2 operations](/guides/managed-kubernetes#day-2-operations) for the shared node-pool and upgrade mechanics.

## Importing an existing DOKS cluster

Already running DOKS? Discover clusters at DigitalOcean and adopt them into Ankra without touching them. Discovery and import run from the portal (**Infrastructure → Clusters → Connect a cluster → Find a managed cluster**), the CLI (`ankra cluster managed discover --provider doks`, then `ankra cluster managed import --provider doks`) or the API - see [Managed Kubernetes - importing existing clusters](/guides/managed-kubernetes#importing-existing-clusters).
