[UpCloud Managed Kubernetes (UKS)](https://upcloud.com/products/managed-kubernetes) is UpCloud's managed Kubernetes service, hosted in UpCloud's European and global zones. UpCloud runs the control plane; Ankra provisions the cluster, then manages everything on top - node pools, Kubernetes upgrades, addons, stacks, GitOps, and AI-assisted operations.

This page covers UKS specifically. For the shared concepts across all managed providers - live options, discovery/import, and day-2 API patterns - see [Managed Kubernetes](/guides/managed-kubernetes).

## Why UKS with Ankra

- **Live pricing and options** - zones, Kubernetes versions, and node plans are fetched live with your UpCloud token, with a monthly cost summary as you build the cluster.
- **Development and production control-plane plans** - choose the UKS control-plane plan that fits the workload.
- **Full day-2 from the portal, the CLI or the API** - add and scale node pools, upgrade Kubernetes, and manage add-ons and Stacks the same way as any Ankra cluster.

## Before you start

- An **UpCloud API credential** (API access for an UpCloud subaccount), stored in Ankra. See [UpCloud API Credentials](/platform/credentials/upcloud). If you have none, the create form shows **Add an UpCloud Managed Kubernetes credential first** with an **Add a credential** button.
- A **payment method** on the organisation. Without one the review step warns "A payment method is required to create this cluster." and the create is refused - see [Billing](/platform/billing).
- A role with the `clusters.create` permission. Without it **Add a cluster** reads "Your role does not allow creating clusters."

GitOps is optional: connect a repository at creation and Ankra commits the cluster's stack definitions to Git.

## Creating a UKS cluster

<Tabs>
  <Tab title="Portal">
    <Steps>
      <Step title="Choose UpCloud, run by UpCloud">
        Open **Infrastructure → Clusters → Add a cluster** (`/next/clusters/new`). Choose **UpCloud** as the provider, then **Provider managed** under **Who runs Kubernetes on UpCloud?**. The page now reads **Add an UpCloud Managed Kubernetes cluster**.
      </Step>
      <Step title="Name and purpose">
        Enter a **Cluster name** (3 to 53 lowercase letters, digits and hyphens, starting with a letter) and answer **What will this cluster run?**. The answer is required before you can review.
      </Step>
      <Step title="Where it runs">
        Pick the **UpCloud Managed Kubernetes credential** and a **Region** - an UpCloud zone such as `de-fra1`. Zones load live from UpCloud. Then choose the **Control plane plan**: **UpCloud default**, or one of the plans UpCloud offers.
      </Step>
      <Step title="Worker nodes">
        Each node group has a **Group name**, a number of **Nodes** and a **Size for** the group (plans with live pricing). **Add a node group** adds another; **Placement, labels and taints** holds node labels and taints. Leave **Scale this group automatically** off: UKS refuses it with "Node pool autoscaling is not supported for UpCloud managed Kubernetes".
      </Step>
      <Step title="Kubernetes and Git">
        Pick a **Kubernetes version** or keep **Provider default**. Under **Cluster configuration in Git**, optionally choose a **Git connection**, **Repository** and **Branch**.
      </Step>
      <Step title="Review and create">
        Click **Review cluster**, check the settings and the **Checks before creating**, then click **Create cluster**. Ankra provisions the cluster, retrieves the kubeconfig and installs the Ankra agent. The page reads **Your cluster is ready** when it is done.
      </Step>
    </Steps>
  </Tab>
  <Tab title="CLI">

    <CliVersion since="0.5.1" />

    ```bash
    ankra cluster managed create \
      --provider uks \
      --name my-uks-cluster \
      --credential-id <upcloud-credential-id> \
      --location de-fra1 \
      --node-pool-name workers \
      --node-pool-size K8S-2xCPU-4GB \
      --node-pool-count 2
    ```

    The control-plane plan has no CLI flag: set it in the portal or through the API.
  </Tab>
  <Tab title="API">
    ```bash
    curl -X POST https://platform.ankra.app/api/v1/clusters/managed/uks \
      -H "Authorization: Bearer $ANKRA_API_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{
        "name": "my-uks-cluster",
        "credential_id": "<upcloud-credential-id>",
        "location": "de-fra1",
        "node_pools": [
          {"name": "workers", "size": "K8S-2xCPU-4GB", "count": 2}
        ],
        "cluster_plan": "production"
      }'
    ```
  </Tab>
</Tabs>

### UKS options

| Field | Description |
|-------|-------------|
| `cluster_plan` | Control-plane plan (`development` or `production`) |
| `gpu_plan.storage_size` | Storage size for GPU node pools |

## Verify

The create progress view follows the control plane, the node pools, kubeconfig retrieval and the Ankra Agent install. The cluster shows **Online** once the agent has connected. Then point `kubectl` at it through Ankra - this needs a [Cluster Access](/guides/cluster-access) grant - and check that every node is `Ready`:

```bash
ankra cluster kubeconfig add <cluster-name> --use
kubectl get nodes
```

See [Accessing Clusters with kubectl](/guides/kubeconfig).

## Day-2 operations

Node pools, upgrades, and deletion work from the portal, the CLI or the API. The CLI examples use `--provider uks`:

```bash
# scale a pool to a fixed count
ankra cluster managed node-pool scale <cluster_id> workers --provider uks --count 5

# upgrade the cluster
ankra cluster managed upgrade <cluster_id> --provider uks --version 1.33

# delete the cluster
ankra cluster managed delete <cluster_id> --provider uks
```

<Note>
Ankra does not manage node-pool autoscaling on UKS: a pool you scale through Ankra is set to a fixed count, and Ankra never changes that count on its own. To autoscale a pool, run UpCloud's Cluster Autoscaler in the cluster and mark the pool as [externally managed](/guides/managed-kubernetes#externally-managed-node-pools) so nothing in Ankra can override the count the autoscaler reaches. See [Managed Kubernetes - day-2 operations](/guides/managed-kubernetes#day-2-operations) for the shared mechanics.
</Note>

In the portal, node pools are under **Infrastructure → Clusters → &lt;your cluster&gt; → Kubernetes → Nodes → Manage nodes and groups**, upgrades under **Settings → Upgrades and maintenance**, and disconnect and delete under **Settings → Terminate or remove**. UKS clusters cannot be stopped and started.

## Importing an existing UKS cluster

Already running UKS? Discover clusters at UpCloud and adopt them into Ankra without touching them. Discovery and import run from the portal (**Infrastructure → Clusters → Connect a cluster → Find a managed cluster**), the CLI (`ankra cluster managed discover --provider uks`, then `ankra cluster managed import --provider uks`) or the API - see [Managed Kubernetes - importing existing clusters](/guides/managed-kubernetes#importing-existing-clusters).
