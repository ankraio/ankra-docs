---
title: Ankra Hosted Logs
description: Keep a cluster's container logs in Ankra for 7 days, with no log store of your own, and search them from an application's log history. Turn it on from the application, the cluster's settings or the CLI.
---

import { CliVersion } from "/snippets/cli-version.jsx";

An application's log **History** searches the logs its cluster keeps. Ankra hosted logs keeps them for you: the cluster's agent sends the log lines of every running container on the cluster to Ankra, where they are kept for 7 days and can be searched from each application's log history. There is no logging stack to install, run or connect.

Hosted logs are off by default and turned on per cluster. Nothing leaves a cluster until someone with permission to change it turns them on.

| | |
|---|---|
| **What is sent** | The log lines of every running container on the cluster |
| **Kept for** | 7 days, in Ankra's own log store |
| **Price** | Included during the pilot. The bytes and lines accepted are recorded as [usage](/platform/usage). |
| **Who can read them** | Members of your organisation, in each application's log history |
| **Who can turn them on or off** | People with the `clusters.write` permission on the cluster |

- **History starts when you turn it on.** Lines written while hosted logs are off are never sent later.
- **Your own log store comes first.** While a [log source](/integrations/log-sources) of your own is connected to the cluster, log history searches that store instead.
- **Live logs need none of this.** **Live** reads the running containers through the cluster's agent, with or without hosted logs.

<Note>
Ankra turns hosted logs on platform by platform. Where they are not offered yet, you can still turn them on for a cluster, and nothing is sent until they are. The cluster's settings and `ankra cluster logs-ship status` say which applies to yours.
</Note>

---

## Before you start

- **The cluster's agent must follow the switch.** An agent that is too old, or that has log shipping turned off in its own Helm values (`logs_ship.enabled`), sends nothing whatever the switch says. Upgrade it with `ankra cluster agent upgrade --cluster <cluster>`, or turn on automatic agent upgrades in the cluster's settings.
- **Your role needs `clusters.write` on the cluster.** Anyone else is told which roles can turn hosted logs on. See [Roles and access](/guides/roles-and-access).

## Turn it on from an application

<Steps>
  <Step title="Open the application's logs">
    In the new Ankra portal, open the application, choose **Health**, then **Logs**.
  </Step>
  <Step title="Choose History">
    When the cluster keeps no logs, History says so instead of showing an empty list: **Ankra hosted logs are off for this cluster.**, or **No log store is connected to this cluster.**
  </Step>
  <Step title="Choose Turn on Ankra hosted logs">
    A dialog says what is sent, how long it is kept, that it is included during the pilot, and that lines written while it is off are never sent later.
  </Step>
  <Step title="Confirm">
    Choose **Turn on hosted logs**. History then reads **Waiting for the first logs from &lt;cluster&gt;.** and checks again every few seconds. The agent starts sending within a minute or two.
  </Step>
</Steps>

Hosted logs are turned on for the whole cluster, so every application with an environment on that cluster gets log history from then on.

---

## Turn it on from the cluster's settings

In the new Ankra portal, open the cluster, choose **Settings** and find **Ankra hosted logs**. It says in one sentence whether the cluster sends its logs to Ankra, and when that was last changed. Choose **Turn on hosted logs**, read the dialog, and confirm with **Turn on hosted logs**.

The same section turns hosted logs off: see [Turn it off](#turn-it-off).

---

## Turn it on with the CLI

<CliVersion since="0.24.0" />

Check the cluster first:

```bash
ankra cluster logs-ship status --cluster <cluster>
```

The status says whether the cluster ships its logs, whether hosted logs are offered on your platform yet, and whether the cluster's agent follows the switch. Then turn it on:

```bash
ankra cluster logs-ship enable --cluster <cluster>
```

`enable` says what is sent and asks before it turns anything on. `--yes` answers the question for scripts.

## What History tells you

When History has nothing to show, it says why, with the next step:

| What you see | What it means | What to do |
|--------------|---------------|------------|
| **Ankra hosted logs are off for this cluster.** | Hosted logs are offered here but turned off for this cluster | **Turn on Ankra hosted logs**, or ask someone with one of the roles it names |
| **No log store is connected to this cluster.** | Neither hosted logs nor a store of your own keeps this cluster's logs | **Turn on Ankra hosted logs**, or **Connect your own log store**. Where hosted logs are not offered yet, History says so and offers only a store of your own. |
| **This cluster's agent cannot send logs to Ankra yet.** | The agent is too old to follow the switch, or log shipping is off in its own settings | Upgrade the agent with the command shown |
| **Waiting for the first logs from &lt;cluster&gt;.** | Hosted logs were just turned on | Wait a minute or two. Lines written before it was turned on are not sent. |
| **Nothing from &lt;cluster&gt; reached Ankra in the &lt;time range&gt;.** | Hosted logs are on, but no line from the cluster arrived | **Check the cluster**: its agent sends the lines, so make sure it is connected |
| **Ankra's hosted logs hold nothing from &lt;namespace&gt; in the &lt;time range&gt;.** | Lines from the cluster arrive, but the application's containers wrote nothing in this window or were not running | Choose a longer time range, or read **Live** logs |

## Turn it off

In the cluster's **Settings**, under **Ankra hosted logs**, choose **Turn off hosted logs** and confirm. With the CLI:

```bash
ankra cluster logs-ship disable --cluster <cluster>
```

The cluster stops sending its container logs to Ankra within a minute. Lines already sent stay readable until they are 7 days old. Lines written while hosted logs are off are never sent later.
