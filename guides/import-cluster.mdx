There are three ways to get a cluster into Ankra. If you already run one - EKS, GKE, AKS, k3s, on-premises, even minikube on your laptop - import it in a couple of minutes with one `helm` command. If you need a new one, Ankra can build it on your own cloud account, or create a cluster your cloud provider runs for you. Whichever you choose, the cluster and its servers stay yours: they keep running if you ever disconnect from Ankra.

## Which path is mine?

| You have... | You want... | Choose | Start here |
|---|---|---|---|
| A running cluster, anywhere | To manage it with Ankra | **Import** | [Import an existing cluster](#import-an-existing-cluster) below |
| A cloud or server account | A new cluster where Ankra installs, upgrades and operates Kubernetes for you | **Ankra Managed** | A provider guide under [Build a new cluster](#build-a-new-cluster) |
| An AWS, Google Cloud, Azure, DigitalOcean, OVHcloud or UpCloud account | A new cluster that your cloud provider runs (EKS, GKE, AKS, DOKS, MKS, UKS) | **Cloud Managed** | [Managed Kubernetes](/guides/managed-kubernetes) |
| Nothing yet | To try Ankra first | **Playground** | [Playground](/guides/cluster-sandbox) - a real cluster in about two minutes, no cloud account needed |

<Tip>
**Already running EKS, GKE or AKS?** You can import it either way. The `helm` import below needs no cloud credential. A [managed import](/guides/managed-kubernetes#importing-existing-clusters) uses your cloud credential instead: Ankra fetches the kubeconfig, installs the agent for you, and the cluster gains the same node-pool and upgrade operations as clusters Ankra created.
</Tip>

## Import an existing cluster

Importing installs the Ankra agent in your cluster. The agent only makes outbound connections to Ankra, so the cluster can sit behind a firewall, NAT or a private network.

**You need:** `helm` and a kubeconfig for the cluster with permission to create a namespace and cluster-wide RBAC. The agent's permissions are described in [Agent compliance](/security/agent-compliance) and can be narrowed with [agent hardening](/security/agent-hardening).

<Steps>
  <Step title="Create the cluster in Ankra">
    Go to **Clusters**, click **Import**, give the cluster a name, and click **Import cluster**. The Git repository and add-on fields are optional - you can connect a repository and add Stacks later.
  </Step>
  <Step title="Run the install command">
    Ankra shows a `helm` command for this cluster. Copy it exactly as shown - it carries the cluster's own token and pins the agent version - and run it with your kubeconfig pointing at the cluster:

    ```bash
    helm upgrade --install ankra-agent oci://registry.ankra.cloud/ankra/ankra-agent \
      --version <version> \
      --set config.ankra_url=https://platform.ankra.app \
      --set config.token=<your-cluster-token> \
      --namespace=ankra --create-namespace
    ```
  </Step>
  <Step title="Check it is connected">
    The cluster's status changes from **Awaiting Connection** to **Healthy**, usually within a minute. Open the cluster to browse its workloads, events and logs.

    If it stays on **Awaiting Connection**, check the agent pod:

    ```bash
    kubectl get pods -n ankra
    kubectl logs -n ankra -l app.kubernetes.io/name=ankra-agent --tail=50
    ```

    The most common causes are egress to `platform.ankra.app` on port 443 being blocked, or a token copied from a different cluster. See [Ankra Agent](/concepts/cluster-agent) for more.
  </Step>
</Steps>

## Build a new cluster

### Ankra Managed

Ankra creates the servers, private network and bastion on your own account, installs Kubernetes (kubeadm with Cilium by default, or k3s), and then operates it for you: upgrades, node groups, stop and start. The provider bills you directly.

### Cloud Managed

Your cloud provider runs the Kubernetes control plane; Ankra creates the cluster and its node pools through your cloud credential, connects the agent, and manages what runs on it. Start with [Managed Kubernetes](/guides/managed-kubernetes), which compares the options, or go straight to [EKS](/guides/eks-clusters), [GKE](/guides/gke-clusters), [AKS](/guides/aks-clusters), [DOKS](/guides/doks-clusters), [OVHcloud MKS](/guides/ovh-mks-clusters), [UKS](/guides/uks-clusters) or [Ankra Cloud Kubernetes](/guides/ankra-cloud-kubernetes) (closed beta).
