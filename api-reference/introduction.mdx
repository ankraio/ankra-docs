The Ankra REST API lets your own tools, scripts and pipelines manage Ankra resources such as clusters and add-ons, start operations and read their status. The Ankra CLI and MCP clients use the same API.

To make your first call, follow [Call the Ankra API: your first request](/guides/first-api-request). This page describes the rules every call follows. The **Endpoints** pages of this reference list every operation with its parameters and response shape, generated from the API's OpenAPI document.

## Base URL

```text
https://platform.ankra.app/api/v1
```

The `/api/v1` routes are the public API and take an API token. Routes under `/org` and `/chat` serve the Ankra portal: they authenticate with the browser's sign-in session, never with a token, and need the `X-Ankra-CSRF` header on every change. Some portal reads also answer under `/api/v1`: a `GET` there that has no `/api/v1` route of its own is served by the portal's route for the same path, and only to a personal token with no scopes and no project pin. Any other token is refused with `403`, and a change never goes this way. Many portal routes also have an `/api/v1` route of their own, changes included: organisation settings and invitations, cluster groups, billing and invoices, the notification inbox and mutes, audit logs, alert history and cluster settings. Some refuse a token pinned to a project.

## Authentication

Send an API token in the `Authorization` header:

```http
Authorization: Bearer <your-token>
```

A token is one of two kinds, never both:

| Kind | How you make it | Reaches |
| --- | --- | --- |
| REST token | **Full API access** under **Your account → API access**, `ankra tokens create <name>` without `--scopes`, or a [service token](/guides/service-tokens) | Every `/api/v1` route your role allows |
| MCP token | **Editor tools: read only** or **Editor tools: read and change**, or `--scopes mcp:read` / `mcp:read,mcp:write` | Only the [MCP server](/platform/mcp-server) at `/api/v1/mcp` |

An MCP token on a REST route is refused with `403` and `MCP-scoped tokens can only access the MCP endpoint`.

- A personal token acts as you, with your role, and stops working when you leave the organisation. In the portal, **Create token** appears only once your account has two-step sign-in. See [API tokens](/reference/tokens).
- A [service token](/guides/service-tokens) belongs to the organisation and carries the role you give it. Use one for CI/CD, Terraform and anything else that runs without a person behind it. Service tokens are under **Identity & access → API and automation** (`/next/organisation/automation`).
- Revoke a personal token from its **Revoke** option under **Your account → API access**. It stops working at once.

<CliVersion since="0.6.0" />

```bash
ankra tokens create my-script --expires 2027-01-31T00:00:00Z
```

Keep tokens out of source control: store them as secrets in your CI/CD system, for example as `ANKRA_API_TOKEN` in GitHub Actions:

```yaml
env:
  ANKRA_API_TOKEN: ${{ secrets.ANKRA_API_TOKEN }}
```

## Organisation and project

A token is bound to the organisation it was made in. Two optional headers move one request elsewhere:

| Header | What it does | Refused with |
| --- | --- | --- |
| `X-Ankra-Organisation-Id: <organisation-id>` | Runs the request in another organisation you are a member of (this is what `ankra --org` sends) | `Not a member of the requested organisation`; `Service account tokens cannot act outside their organisation`; `Pinned tokens cannot act outside their organisation`; `Invalid organisation override header` (`400`) for a value that is not a UUID |
| `X-Ankra-Project-Id: <project-id>` | Runs the request in another [project](/concepts/projects) of the organisation that you reach | `Project not found in this organisation`; `Pinned tokens cannot act outside their project`; `Invalid project override header` (`400`) |

Naming the organisation or project the token already acts in is accepted and changes nothing. MCP tokens take neither header.

While the organisation has projects on, a request acts in, in this order: the project the token is pinned to, the project in `X-Ankra-Project-Id`, or the organisation's default project. A token never follows the project you last selected in the portal, so a script that sees fewer clusters than the portal shows is usually reading the default project. See [Tokens and projects](/concepts/projects#tokens-and-projects).

## Errors

Errors answer with a standard HTTP status and a JSON body with a `detail` field. For most errors `detail` is a message:

```json
{"detail": "MCP-scoped tokens can only access the MCP endpoint"}
```

A request that fails validation answers `422`, and `detail` is a list with one entry per problem, each naming the field (`loc`), the reason (`msg`) and the value sent (`input`).

| Code | Meaning |
| --- | --- |
| `200` | Success |
| `400` | Malformed request, for example `Bearer token not provided` or `Invalid authorization header format` |
| `401` | `Invalid token`: the token is expired, revoked or mistyped |
| `403` | The token may not do this: wrong kind of token, a permission your role lacks, or a header it may not send |
| `404` | Not found |
| `422` | Validation failed |
| `429` | Too many requests, see [Rate limits](#rate-limits) |
| `5xx` | Server error |

## Rate limits

Every `/api/v1` response carries your budget in three headers:

| Header | Value |
| --- | --- |
| `X-RateLimit-Limit` | Requests allowed per minute |
| `X-RateLimit-Remaining` | Requests left in the current budget |
| `X-RateLimit-Reset` | Seconds until the budget is full again |

When the budget runs out, the API answers `429` with `{"detail":"Too Many Requests"}` and a `Retry-After` header giving the seconds to wait. Wait that long, then retry. The Ankra CLI does not retry a `429` for you. The [MCP server](/platform/mcp-server) has its own per-token limits.

## Pagination

Lists come in one of two shapes. The endpoint's page in this reference says which one it uses.

**Pages.** Pass `page` (from 1) and `page_size`. `GET /api/v1/clusters` defaults to 25 per page and takes at most 100. The answer carries the items in `result` and a `pagination` object with `page`, `page_size`, `total_pages` and `total_count`:

```bash
curl -sS -H "Authorization: Bearer $ANKRA_API_TOKEN" \
  "https://platform.ankra.app/api/v1/clusters?page=2&page_size=50"
```

**Cursors.** Pass `limit`, and `cursor` from the previous answer's `next_cursor`. Keep going until `next_cursor` is `null`. `GET /api/v1/org/deployments`, for example, defaults to 20 per call and takes at most 100:

```bash
curl -sS -H "Authorization: Bearer $ANKRA_API_TOKEN" \
  "https://platform.ankra.app/api/v1/org/deployments?limit=50&cursor=<next-cursor>"
```
