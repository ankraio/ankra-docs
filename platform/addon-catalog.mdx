Before you install monitoring, ingress or a database on a cluster, you need to find the right chart, pick a version and know what it will pull in. The add-on catalog is the one place in Ankra that answers this for every Helm registry your organisation has connected. Open it from **Add-ons** in the main sidebar.

## Add-ons and charts

The catalog shows two kinds of cards:

- **Add-ons** - a named tool such as Grafana or cert-manager, with a description, category and links. An add-on groups every chart that deploys it, using match rules (chart names, keywords and home URL prefixes), so the same tool published in several registries appears once. A card is marked **Public** when Ankra curates it for every organisation, or **Organisation** when your organisation curated it.
- **Charts** - a Helm chart from one of your registries. Charts that no add-on matches still appear, as uncurated charts.

A card that is already installed on one of your clusters shows **Installed**, or **Installed ×N** when it is installed more than once.

## Find what you need

Search matches display names, add-on names and the names of the charts an add-on groups. Three filters narrow the list:

| Filter | Options |
| --- | --- |
| Category | Every category in the catalog, with a count. Uncurated charts carry no category. |
| Source | **All sources**, **Curated by Ankra**, **My organisation**, **Uncurated charts**, and **Manifest add-ons** from [Applications](/concepts/applications) |
| In use | **All add-ons**, or **In-use** for the ones already installed |

When the catalog is empty or a chart you expect is missing, **Manage registries** takes you to the registries your organisation has connected. Adding a Helm or OCI registry there is covered in [Registries](/guides/registries); its charts are indexed and appear in the catalog.

## What a chart page shows

Selecting a chart opens it at a specific version, with a version selector and five tabs:

| Tab | What it shows |
| --- | --- |
| **Overview** | The chart's README, registry, homepage, sources, keywords, maintainers and license, and the add-on it belongs to |
| **Values** | The default values for this version |
| **Files** | The files inside the chart package, read-only |
| **Releases** | The chart's release notes |
| **Clusters** | The clusters and Stacks already running this chart, with their version |

The **License** field shows the license's SPDX identifier (for example `Apache-2.0`). Ankra reads it from the `artifacthub.io/license` annotation in `Chart.yaml`, or detects it from a `LICENSE` or `COPYING` file in the package, and says which. Copyleft licenses such as the GPL and AGPL family are highlighted, so a license that carries obligations for derived works stands out before you deploy.

## Install from the catalog

Add-ons run on a cluster as part of a [Stack](/concepts/stacks): you add the chart to a Stack, set its values, and Ankra installs it with Helm and keeps it reconciled. The steps are in [Install add-ons](/concepts/addons#install-add-ons). From a chart's **Overview** you can also use **Install with AI**, which asks the AI Assistant to help you pick a cluster and configure the installation.

## Curate your own add-ons

**Create add-on** defines an add-on for your organisation: a name, display details, a category and the match rules that link charts to it. On an add-on curated by Ankra, customising it creates your organisation's own copy, which takes precedence over the global one in your catalog. An add-on's page lists the charts that resolve to it, lets you link or unlink a chart by hand, and shows the clusters it is installed on.

Two guides cover sharing what you build:

- [Publishing add-ons](/platform/addon-publishing) - propose an add-on your organisation curated to the global catalog every organisation sees.
- [Publishing applications as add-ons](/platform/application-addons) - snapshot an application's manifests as a versioned add-on your organisation can install on any cluster.
