Before you install monitoring, ingress or a database on a cluster, you need to find the right chart, pick a version and know what it will pull in. Ankra reads every Helm registry your organisation can install from (Ankra's public catalogue, the public registries you add and the private ones you connect) and indexes their charts. Where those registries come from is explained in [Chart sources](/concepts/chart-sources).

You reach the indexed charts in three places:

- **The stack editor.** **Add → Helm add-on** on any Stack opens **Find a chart**, which searches every connected registry. This is where you install a chart; see [Create and change a stack](/guides/create-and-change-a-stack).
- **Infrastructure → Managed services → Helm** in the portal, to browse registries and read a chart before you install it.
- **The CLI**, with `ankra helm addon-catalog`.

## Add-ons and charts

A chart is one Helm chart in one registry. An **add-on** is a named tool, such as Grafana or cert-manager, described by an add-on definition: its name, description, category and links, and match rules (chart names, chart keywords and home URL prefixes) that say which charts deploy it. The catalogue groups the charts that match a definition under one add-on, so the same tool published in several registries appears once. A chart that no definition matches still appears, under its own name.

Ankra curates a set of definitions for every organisation, and your organisation can add its own (see [Curate your own add-ons](#curate-your-own-add-ons)).

## Browse charts in the portal

<Note>
**Helm** is a tab of **Managed services**, but it is not part of the [managed services](/concepts/managed-services) closed beta: every organisation has it, whether or not managed services are turned on for it.
</Note>

Open **Infrastructure → Managed services** and select the **Helm** tab (`/next/services/helm`). Your role needs to read Helm charts; otherwise the page says "Your role cannot read the Helm registries. Someone who may read Helm charts can."

The page counts **Public registries**, **Private registries** and **Charts available**, then lists the registries:

| Control | What it does |
| --- | --- |
| **Both**, **Public**, **Private** | Shows every registry, the ones anyone can read without a login (Ankra's catalogue and public registries your organisation added), or the ones that sign in with a registry credential |
| **Search registries** | Narrows the list by registry name |
| **Manage registries** | Opens **Build & delivery → Helm registries**, where registries are added, synced and removed ([Helm registries](/guides/registries)) |

Each row shows the registry's name, whether it is an **OCI registry** or an **HTTP chart repository** with its address, its access (**Public** or **Private**) and its chart count. **Reading charts** means Ankra is still indexing it; **Last read failed** means the last index failed.

Select a registry to open it. **Access** shows who provides it (**Ankra, for every organisation** or **Your organisation**), the registry credential it signs in with, and when it was **Last read**. **Charts** lists its chart releases with **Chart**, **Release** and **Published**, and **Search charts** narrows them. **Manage in Settings** opens the registry under **Helm registries**.

## What a chart page shows

Select a chart to open it at one release. When the chart has more than one version, a version selector at the top switches between them. The page has five tabs:

| Tab | What it shows |
| --- | --- |
| **Overview** | The chart's **README**, **Chart details** (registry, version, app version, published date, licence, homepage, sources, keywords and maintainers) and **Add-on**, the add-on definition the chart installs as |
| **Values** | The chart's default values for this version |
| **Files** | The files in the chart package, as the registry served it, read-only |
| **Releases** | The chart's releases and their notes |
| **Clusters** | The clusters running this chart at any version, with the add-on, Stack and version on each |

**Add-on** says **Curated by Ankra** or **Curated by your organisation**, or "No add-on definition names this chart; it installs under its own name."

**Licence** shows the licence's SPDX identifier (for example `Apache-2.0`) and where Ankra read it: "Declared by the chart." when it comes from the `artifacthub.io/license` annotation in `Chart.yaml`, or "Read from" a `LICENSE` or `COPYING` file in the package. A licence of the AGPL, GPL, LGPL, MPL, EPL, SSPL, BUSL, EUPL, CDDL or OSL family carries a **Copyleft** badge, so a licence with obligations for derived works stands out before you deploy. **Not declared** means Ankra found no licence.

A release that its registry no longer serves says "This release is no longer available from its registry. What is shown is what Ankra indexed."

## Find charts with the CLI

<CliVersion since="0.74.0" />

`ankra helm addon-catalog` gives the same add-on view to every organisation:

```bash
# One page of the catalogue, narrowed by search and category
ankra helm addon-catalog list --search postgres --category databases

# One add-on: its charts and the clusters that run it
ankra helm addon-catalog get cert-manager
```

`--types manifest_addon` includes the [manifest add-ons](/platform/application-addons) your organisation published from applications. `-o json` prints the page with its pagination and category facet. To list one registry's charts, use `ankra helm registries get <name>`. Every flag is in the [`ankra helm` reference](/reference/cli/helm).

## Install a chart

Add-ons run on a cluster as part of a [Stack](/concepts/stacks): you add the chart to a Stack's draft, set its values, review and deploy, and Ankra installs it with Helm and keeps it reconciled. The chart page itself has no install action; its **Add-on** section says to open a cluster's Stack in the stack editor and add the chart there. The steps are in [Create and change a stack](/guides/create-and-change-a-stack).

## Curate your own add-ons

Your organisation can define its own add-ons so its charts are grouped and described the way you want. The portal shows which add-on a chart belongs to but has no page to create or edit a definition. Use `ankra helm addon-definitions`:

```bash
# Define an add-on and the charts it matches
ankra helm addon-definitions create internal-gateway --display-name "Internal gateway" \
  --category networking --match-chart-name internal-gateway --match-keyword gateway

# Include a chart the match rules miss
ankra helm addon-definitions link-chart internal-gateway --chart edge-proxy \
  --registry-url https://charts.example.com

# Undo a manual link
ankra helm addon-definitions unlink-chart internal-gateway --chart edge-proxy \
  --registry-url https://charts.example.com
```

`link-chart --type exclude` keeps a chart out of an add-on whose rules match it. Ankra's own definitions are read-only: changing or deleting one is refused with `403`. Deleting your definition stops the grouping; the charts stay in their registries and installed add-ons keep running.

Two pages cover sharing what you build:

- [Publishing add-ons](/platform/addon-publishing) - propose an add-on your organisation curated to the global catalogue every organisation sees.
- [Publishing applications as add-ons](/platform/application-addons) - snapshot an application's manifests as a versioned add-on your organisation can install on any cluster.
