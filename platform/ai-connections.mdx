You want to ask Ankra AI about a failing deploy from the chat tool your team already uses, and have its approvals and findings reach people there. Every chat app and code host Ankra AI talks through is connected on **Ankra AI → Gateway connections** (`/next/ai/settings/gateway`). The page has one section each for **Slack**, **Microsoft Teams**, **GitHub**, **GitLab** and **Bitbucket**, then **Review instructions** and **Tools, tickets and notifications**.

**Ankra AI → Gateway** (`/next/ai/gateway`) is the overview: which surfaces are connected, and **Set up the gateway** to connect them in order. See [Set up the AI Gateway](/platform/ai-guided-setup). How a message travels from Slack or a pull request to Ankra AI and back is explained in [AI Gateway](/pipelines/ai-gateway). To put it all to work during an incident, follow [Ankra AI on call in Slack or Microsoft Teams](/guides/ai-on-call-in-chat).

## Before you start

- **An owner or admin role** to connect or disconnect a chat app and change its AI mode. Everyone else sees the connections, and each section says **Only organisation owners and admins can connect or disconnect chat apps and change their AI mode.**
- **A Slack workspace or a Microsoft 365 tenant** where you may add apps. For Teams, you may need your Teams administrator; see [Connecting Microsoft Teams](#connecting-microsoft-teams).

## Slack and Microsoft Teams

Each connected Slack workspace or Teams tenant is one row, with **Connected** and the date, the number of linked people, and its own **AI mode** - what Ankra AI may do when talked to from there:

- **Ask** reads, and makes only low-risk new things. Buttons that change something are refused.
- **Agent** can make changes, with the permissions of the person asking. The row is marked **Can act**.

A new Slack or Teams connection starts in the mode set by **How new chat connections start** on **Ankra AI → AI workspaces**, which is **Ask** unless an admin changes it. Code host connections do not follow it: they start with every capability off, see [AI code review](/platform/ai-code-review#ai-mode-ask-or-agent).

Your own Slack, Teams, GitHub and Bitbucket accounts, and the notifications you get there, are on **Connected accounts** under your account, not here. See [User profile](/platform/user-profile).

### Connecting Slack

Slack takes one Ankra owner or admin to install the app, then each person links their own Ankra account the first time they use it.

<Steps>
  <Step title="An owner or admin installs the app">
    On **Ankra AI → Gateway connections**, in the **Slack** section, press **Add to Slack** (**Add a workspace** once one is connected). Slack asks you to approve the app for your workspace and sends you back to Ankra, which says **The Slack workspace is connected.** The workspace now shows as a row in the **Slack** section.

    If you see **Slack was not connected: the installation was not finished. Try again.**, press **Add to Slack** again.

    From a terminal, the admin runs `ankra slack connect` instead. It prints the install address and waits until the install finishes; open the address in any browser and approve it there. It needs a person's token, not a service account's.

    <CliVersion since="0.71.0" />

    ```bash
    ankra slack connect
    ```

    Check it with `ankra slack status`, which lists the connected workspaces.

    The install link lasts 10 minutes from the moment you press **Add to Slack**. Start the install from Ankra, not from Slack: that is what tells Ankra which organisation's clusters the workspace may see. An install started from Slack ends on a **One more step** page instead, and **Continue in Ankra** there starts it from Ankra. One Slack workspace links to one Ankra organisation, and installing it from a different organisation revokes every account link in it.
  </Step>
  <Step title="Each person links their own Ankra account">
    The first time someone mentions **@Ankra**, sends it a direct message, runs `/ankra`, or presses one of its buttons, Ankra replies to them alone with **Connect Ankra account**. They sign in with their normal Ankra login and confirm the Slack user and workspace shown, and Ankra then answers the question they asked. The row's count of linked people goes up by one.

    This is per person on purpose: the bot answers with *that* person's Ankra permissions, and their name - never the bot's - is what lands in the audit log.
  </Step>
  <Step title="Set the AI mode">
    Pick **Ask** or **Agent** on the workspace's row. In Ask mode, the buttons that change something - acknowledging an alert, approving a remediation, working a ticket - are refused.
  </Step>
  <Step title="Optionally, choose a home channel">
    See [Ankra's home channel](#ankra%E2%80%99s-home-channel) below.
  </Step>
</Steps>

### What the Slack app can see

The app receives messages that mention it, direct messages sent to it, and messages in channels it has been added to. It uses a channel message only when it is a reply in a thread that already holds an Ankra conversation or an Ankra ticket, so you can follow up without mentioning it again. Every other channel message is dropped as it arrives and is never stored.

The first time it is mentioned inside an existing thread, it reads up to 50 of that thread's replies once, so it can see the alert or error you were already discussing. Those replies are kept with the conversation in your Ankra organisation, like the question itself.

It asks Slack for these permissions and no others:

| Slack permission | What Ankra uses it for |
| --- | --- |
| `app_mentions:read` | Knowing that someone mentioned **@Ankra** in a channel. |
| `assistant:write` | Showing a status while it works, and offering starter questions in Slack's assistant pane. |
| `channels:history`, `groups:history` | Reading the thread it was mentioned in, and following replies in threads it is already part of, in public and private channels it has been added to. |
| `channels:read`, `groups:read` | Listing channels in the alert and home channel pickers. Names only, no messages. |
| `chat:write` | Posting its answers, cards and notifications. |
| `chat:write.public` | Delivering an alert to a public channel an admin chose, without being invited first. |
| `commands` | The `/ankra` command. |
| `im:history` | Receiving the direct messages you send it. |
| `im:write` | Opening a direct message to tell you a task you started has finished. |
| `users:read` | Showing your Slack name on the page where you confirm the account link. |

It does not ask for email addresses, files, or anyone's direct messages with other people.

### What the bot can do in Slack

- **Ask it anything** - mention **@Ankra** in a channel, message it directly, or open it in Slack's assistant pane. Say `use cluster <name>` to scope the thread to one cluster. An answer in a channel is visible to that channel.
- **`/ankra`** - on its own it links your account. `/ankra status` shows whether you are linked, `/ankra logout` disconnects you, and `/ankra help` shows what it can do. Anything else after `/ankra` shows the same help, because a question typed there does not reach Ankra AI: mention the bot or message it instead. Sending it **help** as a message shows the help too.
- **Act on alerts** - alert cards carry **Acknowledge** and **Snooze 1h** buttons, and AI remediation approvals carry **Approve** and **Deny** (**Approve all** and **Deny all** for a batch). A decided card is replaced by its outcome.
- **Approve Ankra AI's writes** - when a turn proposes a change that needs confirmation, the bot posts a **Confirmation needed** card with **Confirm** and **Deny**. Only the person who asked can decide it, and if the cluster changed in the meantime the card shows what moved and offers **Confirm anyway**.
- **Work tickets from the thread** - an escalated ticket's thread carries **Assign to me** and, while a plan is awaiting a verdict, **Approve plan** and **Request changes**. A reply in a ticket's thread is added to the ticket as a comment.

Every button runs as *your* Ankra user through your own linked account, so your role decides what it may do and the audit log records your name.

### Ankra's home channel

The home channel is the Slack channel Ankra posts in when something important happens and no [notification route](/guides/notification-routing) matches it: failures, agents going offline, security findings. Only critical and warning notifications fall back to it.

Set it on **Ankra AI → AI workspaces**, on the **Ankra’s home channel in Slack** card: pick a channel and press **Save home channel**. The card now reads **The home channel is** followed by the channel. **Clear the home channel** removes it. The card needs a connected Slack workspace, and changing it needs an owner or admin; everyone else sees the current channel.

### Disconnecting Slack

- **For the whole workspace** - an owner or admin presses **Disconnect** on the workspace's row on **Gateway connections** and confirms **Disconnect workspace**. Ankra AI stops answering there, and the people linked there stop getting notifications. Uninstalling the app from Slack has the same effect.
- **For yourself** - run `/ankra logout`, or press **Disconnect** in the app's Home tab in Slack.

### If Slack does not work

| What you see | What it means |
| --- | --- |
| The bot never answers a mention | Run `/ankra status`. If it says the workspace is not connected to an Ankra organisation yet, an Ankra owner or admin needs to press **Add to Slack** from Ankra. |
| **One more step** after authorising | The install started from Slack, so the workspace is not connected to an Ankra organisation. Press **Continue in Ankra** as an owner or admin and approve it once more. |
| **Install link no longer valid** after authorising | The install took longer than 10 minutes. Press **Continue in Ankra** on that page, or **Add to Slack** in Ankra again - you do not need to remove the app from Slack first. |
| **Almost there** after authorising | Linking the workspace to your organisation failed. Retry **Add to Slack** from Ankra. |
| `/ankra` says the workspace is not connected to an Ankra organisation | The app is installed in Slack but no organisation holds it. An Ankra owner or admin follows the link in that reply, or presses **Add to Slack** in Ankra. |
| **Link expired** when connecting your account | The connect link is short-lived. Mention the bot again for a fresh one. |
| **Your Ankra connection has expired** | Run `/ankra` to link your account again. |
| **Alert actions are disabled for this workspace** (or AI actions, or ticket actions) | The workspace's AI mode is **Ask**, which refuses buttons that change something. An admin can switch it to **Agent**. |
| **Your Ankra role cannot confirm AI actions in this organisation** | Your Ankra role does not allow the change. Ask an admin, or someone whose role does, to confirm it. |
| The home channel picker says some channels are not listed | The app is missing a Slack permission. Reinstall it from Ankra with **Add to Slack**. |
| **Slack cannot be used right now** on **Gateway connections** | This Ankra platform has no Slack app set up, or Slack could not be reached. Reload the page in a moment. |

### Connecting Microsoft Teams

Teams setup involves up to three people. Agree who is who before you start: most delays come from one person waiting on another without knowing it.

| Who | What they do | How often | Ankra login |
| --- | --- | --- | --- |
| **Microsoft 365 / Teams administrator** | Allows Ankra AI in your tenant, only needed if it restricts Store apps or requires approval | Once | Not needed |
| **Ankra owner or admin** | Connects the tenant to your Ankra organisation | Once per tenant | Owner or admin role |
| **Everyone else** | Links their own Ankra account | Once per person | Any role |

</Tip>

<Steps>

    1. In Teams, open **Apps**.
    2. Search for **Ankra AI**.
    3. Press **Add**.

    On **Ankra AI → Gateway connections**, the **Microsoft Teams** section's **Connect a tenant** card (**Connect another tenant** once one is connected) has **Get it from the Teams Store** and **Or open it in Teams**, which take you to the same app.

    <Note>
    If **Ankra AI** does not appear in the search, or Teams says it needs approval, your tenant restricts Store apps. A Teams administrator allows it once in the **Teams admin center** under **Teams apps** → **Manage apps**: search for **Ankra AI** and press **Allow**. Under **Teams apps** → **Permission policies**, they also check that the people who should use it are allowed to. The [ready-made message](#what-to-send-your-teams-administrator) covers both steps.
    </Note>
  </Step>
  <Step title="An Ankra owner or admin connects the tenant">
    1. In Teams, add **Ankra AI** to a team, group chat, or personal chat.
    2. The bot sends you a welcome card with a claim code. Press **Connect to Ankra**.
    3. **Gateway connections** opens with **Claim code received from Microsoft Teams** and the code already in the **Claim code** field. Press **Connect**.

    The card now says the tenant **is connected**, and the tenant shows as a row in the **Microsoft Teams** section. This tells Ankra which organisation's clusters this Teams tenant may see.

    Good to know:

    - **The card arrives in a personal chat.** Whoever redeems the claim code connects the whole tenant, so the code is never posted in a channel. If you add the bot to a team or group chat, it messages you privately and tells the channel who got the code. Anyone else can get it by opening a personal chat with **Ankra AI** and saying hi.
    - **Typing the code by hand also works.** The welcome card shows the code. On **Gateway connections**, type it into **Claim code** on the **Connect a tenant** card and press **Connect**.
    - **The code lasts up to 24 hours.** Asking the bot again returns the same code until it is close to expiring, so a colleague talking to the bot won't invalidate yours.
    - **One tenant, one organisation.** A Microsoft tenant connects to exactly one Ankra organisation, while one organisation can connect several tenants. If a tenant was connected to the wrong organisation, disconnect it there and message the bot for a new code.
  </Step>
  <Step title="Each person links their own Ankra account">
    Message the bot, or mention **@Ankra AI** in a channel, then press **Connect Ankra account** and sign in with your normal Ankra login. You only do this once.

    This is per person on purpose: the bot answers with *your* Ankra permissions, and your name, never the bot's, is what appears in the audit log.
  </Step>
  <Step title="Optionally, set the AI mode">
    Pick **Ask** or **Agent** on the tenant's row. **Ask** is read-only, and **Agent** lets Ankra AI act.
  </Step>
  <Step title="Optionally, send alerts and pipeline notifications to a Teams channel">
    Once the bot is in a team, a Microsoft Teams notification destination (**Integrations & alerts → Notification destinations**) can post to that team's channels. The bot posts the card itself, so you don't need a Power Automate URL. Add the bot to every team whose channels should receive notifications. If a team the bot is already in lists no channels, mention **@Ankra AI** once in that team and reload.

    Apart from alerts that list it as their own destination, a destination only receives what a [notification route](/guides/notification-routing) sends it, so add a route for each kind of notification the channel should hear. For pipeline runs, route the [pipeline notification kinds](/guides/ankra-pipelines#what-is-in-place-today). From the CLI:

    ```bash
    ankra alerts destinations channels --provider teams     # find the channel id and tenant id
    ankra alerts destinations create --name "Pipelines in Teams" --type teams \
      --channel-id "19:...@thread.tacv2" --teams-tenant-id <tenant-id>
    ankra alerts routes create --destination-id <destination-id> --organisation-wide \
      --kinds pipeline_run_failed,pipeline_authority_approval_requested,image_gate_blocked,preview_failed
    ankra alerts routes create --destination-id <destination-id> --organisation-wide --severity critical
    ```

    The first route sends pipeline failures, approval requests, blocked images and failed previews; the second adds every critical notification, except opt-in kinds such as `application_down`, which a route must name. Add `pipeline_run_succeeded` or `preview_ready` only if the channel wants every green run and every pull request preview that comes up: the first fires once per green run, the second when a preview becomes reachable. Without `--organisation-wide`, a route delivers only your current project's notifications. Check where a notification would go with `ankra alerts routes preview --kind pipeline_run_failed`.
  </Step>
</Steps>

### What your Teams administrator will want to know

<AccordionGroup>
  <Accordion title="Does it need admin consent or Graph permissions?">
    No admin consent. Ankra AI is a bot-only app and asks for no tenant-wide Microsoft Graph scope, so allowing it in **Manage apps** and in a permission policy is the whole tenant approval.

    From version 1.1.0, its manifest also declares one resource-specific consent (RSC) permission, `ChannelMessage.Read.Group`. A team owner grants it for their own team when they add the app; it never covers other teams. Whether team owners may grant RSC is a tenant setting; see Microsoft's [resource-specific consent](https://learn.microsoft.com/microsoftteams/resource-specific-consent) guide. Adding version 1.1.0 to a team means granting it: Teams does not let a team owner decline one permission and keep the app. If your tenant blocks team owners from granting RSC, they cannot add this version until an administrator allows it. Versions before 1.1.0 declare no RSC permission. **Manage apps** shows which version your tenant has.
  </Accordion>
  <Accordion title="Can it read our channel history?">
    Only in teams it was added to, and only to answer. With version 1.1.0, Teams delivers that team's channel messages to the bot, which:

    - Answers only messages that `@mention` it. Everything else in a channel goes unanswered.
    - When mentioned inside a thread, reads that thread so it knows what "this" refers to, for example the alert card the thread started from.
    - Copies a plain reply onto an Ankra board ticket's timeline only when the thread mirrors that ticket, and ignores every other unmentioned message.

    With earlier versions, it only receives `@mentions` and direct messages.
  </Accordion>
  <Accordion title="What data leaves Microsoft Teams?">
    The messages people send to the bot, the thread a mention was made in (version 1.1.0), and replies in threads that mirror an Ankra board ticket, plus the IDs needed to reply (tenant, conversation and user). These reach the Ankra platform so the assistant can answer, and the conversation is stored against your Ankra organisation. Unmentioned channel messages outside those threads are not stored or exported.
  </Accordion>
  <Accordion title="Does it need a firewall or network change?">
    No. The bot runs in Ankra's platform and talks outbound to Microsoft's Bot Framework, which relays to Teams. Nothing connects inbound to your network, and there is no IP range to allow-list.
  </Accordion>
  <Accordion title="Who does it act as?">
    The person using it. Every answer and button runs with that person's own Ankra permissions and is recorded under their name in your organisation's audit log. Someone who has not linked an account gets a connect prompt instead of an answer. An Ankra owner or admin can also limit what the integration may do with the **AI mode** on the tenant's row (*Ask* for read-only, *Agent* to let it act).
  </Accordion>
  <Accordion title="How do we remove it?">
    In the Teams admin center: **Manage apps** → **Ankra AI** → **Block**. If you uploaded the app package instead of using the Store, delete it from your org's catalog. In Ankra: **Ankra AI → Gateway connections**, press **Disconnect** on the tenant's row and confirm **Disconnect tenant**. Ankra AI stops answering there, and the people linked there stop getting notifications.
  </Accordion>
</AccordionGroup>

## MCP Tool Servers

Register your own MCP servers to give Ankra's agent runs extra tools. Each server exposes its tools after a health probe, and every tool needs an explicit **role grant** before runs can call it - registering a server grants nothing by itself.

The portal has no page for MCP tool servers. Register and grant them with `ankra org mcp-servers`, or with the tools in the [Agent MCP Tool Servers](/platform/mcp-tools#agent-mcp-tool-servers) reference. Managing them needs an organisation admin.

```bash
ankra org mcp-servers catalog
ankra org mcp-servers add sentry --adapter sentry --url https://mcp.sentry.dev/mcp \
  --secret-header Authorization
ankra org mcp-servers grant sentry get_issue --role member
ankra org mcp-servers health sentry
```

`--secret-header` stores the header's value in an organisation secret and registers the server with a reference to it, so the value never lands in the server record. See [`ankra org mcp-servers`](/reference/cli/org#ankra-org-mcp-servers) for every flag.

This is the opposite direction from Ankra's own [MCP Server](/platform/mcp-server), which lets your MCP client - Claude, Cursor, or your own agent - call Ankra. To have your own agent pick up and work board tickets, see [Work the AI board with your own agent](/guides/board-own-agent).

## Ticket Sync

Mirror [AI board](/platform/ai-board) tickets into a Jira project, a Linear team, or your own webhook endpoint. The external issue is created once per ticket and timeline events follow as comments. Each connection carries its own filters for ticket kind, minimum priority, and whether timeline events are relayed at all. Sync is one-way: edits and comments made in the tracker do not come back to the board.

The portal has no page for ticket sync. Set it up with `ankra tickets sync connections create`; [Sync board tickets to Jira, Linear, or a webhook](/guides/ticket-sync) shows where each provider value comes from, the webhook payload contract, and troubleshooting.

## Outbound Delivery

Where Ankra's notifications go is set outside the Ankra AI menu, under **Integrations & alerts**:

- **Integrations & alerts → Notification destinations** (`/next/organisation/notification-destinations`) - the Slack channels, Teams channels and webhook endpoints that receive platform events, with ready-made templates for Slack, Teams, Discord, and PagerDuty, or a custom JSON payload template. **Send a test** in a destination's menu checks the wiring. See the [webhook guide](/guides/webhooks) for payloads and templates.
- **Integrations & alerts → Notification routes** (`/next/organisation/notification-routes`) - rules that decide which events (alerts, security findings, agent status, GitOps) go to which destination. Critical and warning events with no matching route fall back to the home channel, except the [opt-in kinds](/guides/notification-routing#opt-in-kinds), which only a route naming them delivers. See [Notification routing](/guides/notification-routing) for matching, ordering, and the one-delivery-per-destination guarantee.

### A Slack or Teams channel per project

A route in a [project](/concepts/projects) delivers only that project's notifications; an organisation-wide route delivers every project's and the organisation's own. With projects `core` and `tools` and channels `#ankra-core` and `#ankra-tools`:

1. Create one catch-all route in each project, **This project**, sending to that project's channel.
2. Bind the same channels under [Project channels](/platform/ai-board#project-channels) on the ticket desk's **Communication** tab, so ticket threads with their approval, plan sign-off and decision buttons land there too.

The organisation's own routes and channels stay the fallback in three cases:

- A notification not tied to a project, such as billing, reaches only organisation-wide routes.
- A notification that matches no rule at all goes to the [home channel](/guides/notification-routing#the-home-channel-fallback), and only when it is critical or warning and not an opt-in kind.
- A ticket whose project binds no channel for Slack or Teams opens its thread in the organisation's tickets channel for that provider.

The walkthrough is [one channel per project](/guides/notification-routing#example-one-channel-per-project).

<Note>
The bot's answers in a project channel still come from your default project, and remediation approval cards still go to the organisation's Slack remediation destination.
</Note>

## Permissions

Connecting and disconnecting Slack and Teams, changing an AI mode, and changing ticket sync connections need an owner or admin. Destinations and routes need `alerts.manage`, MCP tool servers `ai.manage`; owners and admins hold both, and custom roles can grant them. Members see the connections and their settings. Ticket sync credentials are write-only: they are kept in Ankra's secret store, never in the database, and are never returned to anyone.
