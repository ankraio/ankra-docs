Open an application from **Applications** and its page replaces the sidebar with the application's own menu. The menu starts with **Overview** and a **Deploy** group that holds **Environments**, **Pipelines** and **Previews**. Then comes one row per view, with **Settings** last. This page lists every row, in menu order, with what it shows.

Every view lives at one address, `/next/applications/<application-id>?view=<view>`, and a view with sections or tabs adds `&section=<section>`. The **Overview** has no `view`. Links saved before the menu changed still open where they meant, except a bare `view=settings`: it opened Secrets, the view now named **Variables**, and it now opens Settings on **Address**.

Most views show one environment at a time: pick it in the environment menu at the top of the page. **Logs** and **Metrics** share a time range you pick; until you pick one, **Logs** opens on the last 24 hours and **Metrics** on the last hour. The place picked under **Running on** stays picked between **Logs**, **Metrics** and **Architecture**.

The header above a view that reads live state has **Check again**, which reads what the view shows again. After a release that did not go live, the header says which version is still serving, on every view. In the menu, **Security** carries the number of serious findings of the last scans, and **Variables** is marked when the next promotion waits for a secret its target does not have.

## Overview

The application's front page. Its **Environments** card lists each environment with what it runs, what it follows (such as **Follows pushes to main**) and the one action that fits it, such as **Promote to** *environment*, **Wake** or **Open**. **Find an environment** filters the list. **Add** beside the environments starts a new environment on another cluster: see [Environments and branch rules](/guides/application-environments#add-an-environment-on-another-cluster).

When Ankra has a setup change for the application, the Overview says **A setup change is waiting for your approval.** When a release did not go live, the environment's card offers to put the previous version back: see [Roll back an application](/guides/roll-back-an-application).

<CliVersion since="0.74.0" />

```bash
ankra application get <application-id>
```

### Arrange the Overview

The cards under the header are one layout, shared by everyone who opens the application. Until someone saves one, the page shows **Ankra's layout**: Health, Environments, Services, Cost and **Is it safe?**. An organisation without the Cost area has no Cost card. The line above the cards says which layout is on the page and, for a saved one, its version, who saved it and when.

**Edit layout** arranges the cards:

- **Move a card** - drag it by its handle. On a touch screen, each card has arrows that move it one place.
- **Set its width** - pull its right edge, or pick **1/3**, **1/2**, **2/3** or **Full**. In a phone-width window every card is a row of its own, and there is no width control.
- **Take a card off** - the cross on the card.
- **Add a card** - lists every card the Overview can hold: the ones above and three more, **Recent releases**, **Last pipeline runs** and **Backups**. A card already on the page says **On the page**, and any other has **Add**. It also lists what Ankra measures, to add as a chart: see [A chart as a card](#a-chart-as-a-card).
- **Start from** - begins again from Ankra's layout, **On call** or **Release day**.
- **Undo** and **Redo** - step through the changes of this edit.

With the keyboard, a card's handle picks it up: the arrow keys move it, Shift and an arrow key changes its width, Enter puts it down and Escape puts it back. Ctrl+Z (Cmd+Z on a Mac) undoes, and with Shift it redoes.

Nothing changes for anyone until **Save layout**. Saving keeps the layout before it as a version. **Versions** lists them, newest first. Choosing one puts it back as a new version, so nothing saved is lost, and **Ankra's layout** in the same list returns the page to how it was. If someone else saved while you were editing, your save is refused and the page says who saved which version. Your arrangement stays in the editor: **Save layout** again puts it on the page in place of theirs, and **Cancel** shows theirs. Following a link, reloading or closing the tab with changes that are not saved asks first.

Changing the layout needs a role that may change the application (`applications.write`). The header, and the card that says why a release needs you, are not part of the layout: they stay where they are.

#### A chart as a card

**Add a card** also lists **What Ankra measures**: CPU used, Memory used, Copies running, Container restarts, Response time p95, Requests that failed, Requests by status and Log volume by level. **Add** puts the measure on the page as a chart of the last 7 days, for the environment the Overview shows. It is saved with the layout, like any other card.

Above the chart, the card says what the measure comes to, such as **358 MiB now**. Memory is written in MiB, or in GiB from 1,024 MiB, and the axis steps are round in that unit. A line has one point an hour, and bars cover six hours each. A line and bars write their days the same way, such as Fri 13, Sun 15, Tue 17. A time with no reading is a gap in the line, never a zero. On **Response time p95**, a time when more than 5 in 100 requests took longer than the highest bound the cluster's ingress measures is a gap too, because the p95 is known only to be more than that bound: the line under the chart says how many such times there were and names the bound. When Ankra cannot read a measure, the card says why in place of the chart. A member whose role does not reach the cluster the environment runs on is told so.

## Environments

What is live in each environment, and the way to change it. **Add an environment** in the page header adds one on another cluster. Environments is one page with these parts:

- **One card per environment** (`section=deploy` opens the page here): its cluster and state, the version it runs with that version's commit and change, where it runs, and its own buttons. **Running** says how many copies are ready and, when Ankra can say one limit for every copy running, the memory each copy may use at most, such as **3 of 3 copies, 512 MiB each at most**. The limit is each copy's, not the sum. **Promote to** *environment* opens the promotion review. **Deploy a version** opens the deploy page for that environment: choose the version, Ankra checks the cluster has what it needs, and nothing changes until you confirm. **Roll back to** *version* (or **Undo this release**) puts the version before back, **Park** opens **Park or remove** in Settings, and **Open** opens the environment's address. A parked environment has only **Wake**. Until anything of a new application runs, the page shows its **Go live** steps instead, and opening the application lands here: see [Ship your app](/guides/deliver-your-app#ship-from-the-portal).
- **Promote a version**: with two or more environments that run on a cluster, put the version one environment runs live on another. The promotion review shows the version each side runs, with **Live there since** and **Replaces**, and nothing changes until you confirm.
- **Recent releases to** *environment*: a table of the releases to the environment in view, with **Live now** on the version it runs and **Full history** linking to History.
- **Where it runs** (`section=where-it-runs`), last: every place the application runs. See [Where it runs](#where-it-runs) below.

```bash
ankra application deploy <application-id> --cluster <cluster>
ankra application promote <application-id> --from staging --to production --dry-run
```

### Where the cluster is

The line under each environment's name says which cluster it runs on and where that cluster is: **Cluster eu-production, Helsinki, Finland**. On [Data](#data), the **Destination** on **Backups** says the same of the bucket the backup vault writes to: **demo-backups, Hetzner object storage in Helsinki, Finland**. Ankra gives one of three answers:

| Answer | What the page says | What it means |
|---|---|---|
| A place | The country, with the city before it only where the provider's region code names the city: **Helsinki, Finland**. For some providers, the country alone: **Germany**. A cluster with machines in more than one region names each: **Helsinki, Finland and Falkenstein, Germany** | The provider region the machines or the bucket are in |
| Not recorded | **Imported cluster: Ankra has no record of where it is**, **Your own hardware: Ankra has no record of where it is**, or for a vault **A bucket you brought: Ankra has no record of where it is.** | Ankra holds no provider region for it. This is not a fault: Ankra did not create the machines or the bucket, so it has nothing to read the place from |
| Not known | **Place not known**, with the reason when there is one, such as **Place not known: Ankra could not read it just now**, **Place not known: Ankra has no place for region** *code* **yet** or **Place not known: no region is stored for its machines** | Ankra should know the place and could not say it |

Not known is never shown as not recorded, and neither is ever shown as a place. When the answer is not a place, the environment's line gives the cluster and then the reason, and the **Destination** names the vault with the reason on the line under it. An environment on several clusters names each cluster's place in brackets: **Clusters eu-production (Helsinki, Finland), us-production (place not recorded) and eu-backup (place not known)**.

### Where it runs

The last section of Environments: each place the application runs, grouped by environment, and how each one is doing. Places no environment claims are listed under **Outside your environments**, and places being taken off a cluster under **Being removed**. If Ankra cannot read your environments, every place is listed ungrouped under **Every place**. The older addresses `view=where-it-runs` and `view=deployments` open this section.

```bash
ankra application deployments <application-id>
```

## Pipelines

Every build of the application, and how its pipeline is set up. Pipelines has four tabs and opens on the first. **Runs** starts with a card that says where the default branch is and which version each environment runs. A run the image gate stopped reads **Blocked**. See [Ankra Pipelines](/guides/ankra-pipelines).

| Tab | `section=` | What it shows |
|---|---|---|
| **Runs** | none | Every run, with **Run pipeline** to start one and the **Merge train** below the list. A run opens under the same tabs with its stages and steps; **All runs** returns to the list |
| **Schedules** | `schedules` | **Scheduled runs**: **Add a schedule**, a switch on each one that pauses or enables it, and **Edit schedule** and **Delete schedule** in its menu. Each schedule says whether the pipeline file writes it, and one that starts no run says why. **In the pipeline file, not running** lists the `on.schedule` entries no schedule starts, each with **Add this schedule**. See [Run every night](/guides/ankra-ci-starter-pipelines#run-every-night) |
| **Cache** | `cache` | The files a pipeline stage keeps from one run to the next: each cache's name, the key the stage declared, where it is mounted, its size, [what it saves a run](/pipelines/caching#what-a-cache-saves) and when a run last used it. Above the list, what the caches saved together over the last 30 days. Under it, the newest run that ran with every cache cold and why. With **Refresh caches** |
| **Configuration** | `configuration` | A change to the pipeline that waits for an admin's approval comes first, with **Review the change**. Then **Pipeline configuration** (the stages and **Validate pipeline**), **Build infrastructure** (the build cluster, with **Enable build execution** when its agent has not reported pipeline execution support) and **Repository workflow history** |

```bash
ankra pipeline list --application <application-id>
ankra pipeline caches --application <application-id>
```

## Previews

A running copy of a branch, to try before it is merged. Each preview has its own address, and Ankra removes it when its timer ends. **New preview** starts one from a branch that has a published build. Each preview is a card with its address, the run that built it, when it started and when it stops, the cluster it runs on, its version, its data and its namespace, with **Open preview** and **Stop preview**. A card also says when the newest run of its pull request did not pass. What new previews start from is set in **Settings → Deploys**, under **Preview defaults**. See [Preview a branch](/guides/branch-demos).

```bash
ankra application demo list <application-id>
```

## History

The changes to the application: what changed, where, who did it and how it ended. It opens on the last 7 days; pick a longer range, up to **Any time**, to see older changes. A release line you may undo carries **Roll back to** *version* or **Undo this release**: see [Roll back an application](/guides/roll-back-an-application).

**Where each environment stands** sums up each environment's releases over the last 7 days, and **Needs a look** names each release that failed. **Compare versions** puts two versions side by side, with the image each one runs and where it runs, and offers to promote one from there. **Group by release** folds a version's build and its releases into one line. Runs on a timer that passed are counted under the list, and **Show them** lists them. On a wide window the open change sits beside the list, each of its details under its own label. An open change steps to the change before or after it, and changes that arrive while you read wait behind a **1 new change** button. **Export** downloads the changes shown as CSV or JSON.

```bash
ankra application timeline <application-id> --limit 20
```

### Changes to settings

A change to a variable, a secret or a setting is a row of its own: which setting, what happened, who did it, when and where, such as **LOG_LEVEL set to debug in Staging**. Where it can, the line under it says what the value was before. Pick **Settings and secrets** above the list to see only these rows; the page then says what they cover: push to deploy, automatic build fixes, auto-merge of the setup pull request, Who runs it, the pause of Ankra's own actions, environment names, operating expectations, secrets, variables and backups. Changes to copies, CPU and memory are not listed.

Open a row for its **Before and after** table: each value before the change and after it. For most settings the details also link to the page where the setting is changed now, such as **Open Variables**. A value the table cannot show is never left blank:

| The table says | What it means |
|---|---|
| **Not set** | There was no value |
| **A value, not shown** | There was a value, and History does not show it: a secret's, or a plain value's that looked like a secret |
| **Not recorded** | Ankra has no record of the value. This is not the same as no value |
| **Could not be read** | Ankra could not read the value |
| **Empty** | There was a value, and it was empty. A row that sets a variable to an empty value says so, such as **LOG_LEVEL set to empty in Staging** |

A secret's value is never shown: its row says **Secret. Its value is never shown.**, and the table shows **A value, not shown** before and after.

A member confined to some projects sees that a change happened in an environment outside their projects, not what changed. The row says **In an environment outside your projects. What changed there is not shown to you.** and names its place as **Outside your projects**. Its details have no table and no link.

## Logs

What the application's containers wrote, searched over a time range or read live. Logs opens on **Search** over the last 24 hours when the cluster keeps its lines, and on **Live** when it does not; **Previous run** shows what each container wrote before its last restart.

On a search, bars above the lines show when the lines were written, errors and warnings on their own row: see [What the bars count](#what-the-bars-count). Drag across the bars, or pick them with the arrow keys and press Enter, to narrow the time, or use **Zoom to the most errors**. **The same time in Metrics** opens Metrics on the same minutes. **Export** saves the lines **As a text file** or **As NDJSON**, and **Load older lines** reads the next lines from where the list ended. For a cluster's own logs, see [Logs](/platform/logs); to keep lines when the cluster has no log store, see [Ankra hosted logs](/guides/hosted-logs).

### What the bars count

A search does not read every line at once: **Load older lines** reads more. The bars, and the line above them with the lines, errors and warnings, are not counted from the lines read. The log store counts every line it holds for the time you picked that matches the search. The numbers on the level chips above the lines count the lines read. The page says what the bars count:

| Answer | What the page says | What it means |
|---|---|---|
| Counted | The bars and the line above them, with no note | The log store counted every line of the time you picked. When it estimated part of the count, a note says the bars are close but not exact |
| No count | **The bars count the 200 lines read, not every line of the last 24 hours**, with the errors and warnings among them | Ankra has no count of the lines for this search. The bars count the lines the page has read, and say so. When the page has read every line, the bars are every line and need no note |
| Words typed, not yet searched | **The bars and the count are of every line the search matched in the last 24 hours, not only those with “Slow query”. Press Enter to count those.** | The lines below narrow to the words in the search box, but the count is still of the last search. Press Enter to search for the words and count them |
| Could not be read | **The count of every line in the last 24 hours could not be read.**, with **Count again** | Ankra asked the log store for the count and could not read it. The bars count the lines read and say so, as with no count. A count that could not be read is never drawn as empty bars |

The time range goes back only as far as the log store keeps lines, when the store says how long that is. Ankra's hosted logs say it: the range offers nothing older, and says **Lines are kept for up to 7 days.** A log store of your own does not tell Ankra how long it keeps lines, so the range is not shortened for it.

### Saved searches

**Saved searches**, in the row under the search box, keeps searches under a name, to run again. The searches belong to the application, not to you: everyone who can see the application can run them. The menu is on **Search** only, not on **Live** or **Previous run**, and it is not there while the cluster keeps no log history: see [Ankra hosted logs](/guides/hosted-logs) to keep the lines.

- **Save this search** keeps the search on the page: the words it searched for, the level and the copy picked, and the time range. **What it saves** shows them. Give it a **Name** of 1 to 80 characters and press **Save**. Two searches of one application cannot have the same name, capitals aside. A range such as the last 24 hours stays relative, so the search reads the last 24 hours each time it runs, and a range between two moments stays on those moments.
- Picking a search in the menu runs it. The words, the level and the copy become the search's, and so does the time range when it has one. A search saved without a time range runs over the time the page shows. The search goes into the page's address, so a reload or a link keeps it.
- **Rename or remove** opens the list of saved searches, with **Rename** and **Remove**. A change there is made for everyone who can see the application. **Remove** asks first, and a removed search cannot be put back.

Saving, renaming and removing need a role that may change the application (`applications.write`). Anyone else who can see the application can still run the searches, and the menu says **Saving, renaming and removing a search needs permission to change the application. Ask an admin for it.** An application keeps 50 saved searches at most: one more is refused with **This application already has 50 saved searches, the most it can keep. Remove one before saving another.**

A search this page cannot run is still listed, with **cannot be run** beside its name. Picking it opens the list, which says why, such as **It filters on more than one level, and this page filters on one level at a time.** When Ankra can no longer read what a search looked for, the list says so, and offers **Save the search on this page in its place** and **Remove** to people who may change the searches. Saving in its place asks first, shows **What it will look for instead** and keeps the name.

From the terminal, `ankra application log-searches` lists, saves, replaces and removes the same searches, with `list`, `save`, `replace` and `remove`: see [ankra application log-searches](/reference/cli/application#ankra-application-log-searches).

## Metrics

How the application answers requests and what it uses, for the place and the time range you choose. Ankra's own tabs are **Traffic** (`section=traffic`: successful responses, response time and request traffic) and **Runtime** (`section=runtime`: CPU, memory, copies and container restarts). The application's dashboards can be tabs too, and **All dashboards** (`section=dashboards`) is always the last tab. The tabs are the same for everyone who opens the application: see [The tabs of Metrics](#the-tabs-of-metrics). On **Traffic**, **Compare with** draws the period before beside the one you chose. When Ankra missed part of either period, **Requests** and **Requests that failed** say so and are not compared. The **Releases** chip shows or hides the releases on the charts. **Runtime** lists **The copies running now**: each copy, its version, when it started and its restarts. When Ankra's built-in metrics are off but your own Prometheus for the cluster works, the charts stay empty and **Open cluster metrics** opens the cluster's [Metrics page](/platform/cluster-metrics).

Under the charts of **Traffic**, the **Alerts** card lists the alerts that watch this application on the environment: the ones made here, and your organisation's alert rules for a cluster it runs on, each with when it last fired and who acknowledged it. **New alert**, or **Alert** on a chart, makes one. See [Alert on one application](/guides/alerts#alert-on-one-application).

### Response time

The **Response time** card on **Traffic** draws three lines on one chart: **p50, half of requests**, **p95, 95 in 100** and **p99, 99 in 100**. Times under a second are given in milliseconds, longer ones in seconds. Half of the requests took no longer than the p50, 95 in 100 no longer than the p95, and 99 in 100 no longer than the p99. The line under the chart gives p50 and p99 in words: their newest readings while the time range ends now and both are current, otherwise the highest of the time range. While p50, p95 and p99 are all current, p50 and p99 are given under the **Response time p95** figure above the charts instead, and the line under the chart is left out. While the time range ends now and no requests are coming in, the card says **No traffic now** and the line is left out too.

The ingress measures response time against a set of bounds, and the highest bound is as far as it measures. When p50 or p99 lies above that bound, Ankra knows only that it is over it. The chart then draws it as a dashed line at the bound, named **p50, more than** or **p99, more than**, and the card says it as more than the bound.

The **Lines** / **Spread** switch on the card changes how it draws response time. **Spread** draws a grid in place of the lines. Time runs across, and each row is a band of response time between two of the bounds, from **Under** the lowest bound at the bottom to **Over** the highest at the top. The darker a cell, the larger the share of that moment's requests that took that long, in the five steps the key under the grid names, from **Under 5%** to **Over 50%**. A moment with no requests, or with nothing read, has no cells: it is never drawn as a share of 0. Point at a column, or use the arrow keys, to read that moment: about how many requests came in, and the share in each band that held at least half a percent of them. The platform sends at most 20 bounds, and leaves out the fastest ones. When it does, the grid says its lowest band also holds the faster bands it left out.

A time with no reading is a gap in the lines, not a 0. When p50 or p99 has no readings, the line under the chart says it is not available for the time range, or could not be read. When there is no spread, **Spread** says why: there were no requests, the platform answered no response time buckets, or the spread could not be read.

### The tabs of Metrics

The tabs of Metrics are one order, kept by Ankra and the same for everyone who opens the application. Until someone arranges them, they are Ankra's order: **Traffic**, then **Runtime**. A tab can also be a dashboard of the application (`section=board:<dashboard-id>`): it shows the dashboard, with a toolbar above its title. **All dashboards** lists each dashboard of the application you can open, with how many cards it has, who made it, when it changed, who sees it and whether it is on the tabs, and opens any of them as a tab. To make one, see [Make a dashboard](#make-a-dashboard).

The toolbar of a dashboard's tab holds:

- **The time range**, on a dashboard that reads live data, such as **Last 24 hours**. It offers only the ranges the dashboard offers, and the address keeps it, so a link opens the same range. When the address asks for a range the dashboard does not offer, the dashboard shows its own.
- **Edit layout**, for the dashboard's owner and the people who can edit it, on a dashboard laid out on a grid. It opens the dashboard's own layout editor on the tab. Nothing changes until **Save layout**, which saves the layout as a new version of the dashboard, and **Cancel** leaves it as it was. When the dashboard's area on the page is too narrow for the layout, as on a narrow window, the button cannot be pressed and says **Make the window wider to edit the layout.**
- **Add a card**, for the dashboard's owner and the people who can edit it: see [Add a card](#add-a-card).
- **Ask Ankra to change it**, for people who may use Ankra AI (`ai.use`). It opens a new conversation with Ankra AI, with a message that names the dashboard, for you to read and send. If you can only view the dashboard, it cannot be pressed and says **You can view this dashboard but not change it. Ask its owner to make you an editor.** On a dashboard not made in a conversation, such as one made with **New dashboard**, it cannot be pressed either, and says to add cards with **Add a card**.
- **Take off the tabs**, while the dashboard is on the tabs. It takes the dashboard off the tabs for everyone and moves to the tab beside it, and a line under the tabs says *dashboard* **is off the tabs for everyone who opens** *application*. **It is still in All dashboards.** The dashboard itself is not deleted. When the tabs left would be Ankra's own in Ankra's order, Metrics is back on Ankra's order. It needs the same role as **Edit tabs**, and without it the button says why. If someone changed the tabs after you opened them, the dashboard is not taken off and the bar shows their tabs.
- **More**, with **Share at a public link**, which opens the dashboard's **Share** dialog as its page does (see [Canvases](/platform/canvases)), and **Open the dashboard's page**.

The line under the title says the environment and the time range the dashboard's cards show, when the dashboard says them, **made by you** on a dashboard you made, and when it last changed.

While the layout has changes that are not saved, Metrics holds a press on another tab, and the page says **Save or cancel the layout first, so your changes are not lost.** **Add a tab** cannot be pressed then either, for the same reason.

Metrics opens on the tab you last picked, on any device, while that tab is still on the tabs. Before you pick one, it opens on the first tab. Only picking a tab on the bar changes where it opens: following a link to a tab, or picking **All dashboards**, does not.

**Add a tab** and **Edit tabs** change the tabs for everyone, so they need a role that may change the application (`applications.write`), as arranging the Overview does. Without it, the buttons cannot be pressed and say **Arranging the tabs needs permission to change the application, because everyone sees them. Ask an admin for it.**

- **Add a tab** lists what is not on the tabs: Ankra's own as **From Ankra:** *name*, and the application's dashboards shared with the organisation as **Dashboard:** *name*. Choosing one adds it for everyone at once, before **All dashboards**, and opens it.
- **Edit tabs** opens **Tabs on Metrics**: the tabs in order, each with arrows that move it earlier or later and a cross that takes it off. **Not on the tabs** lists the ones that can go back, each with **Add**, and **Put back Ankra's order** returns to Ankra's two tabs. Metrics keeps one tab at least and holds 12 at most, not counting **All dashboards**. Nothing changes for anyone until **Save tabs**, and the page then says **Saved for everyone who opens** *application*. A tab taken off still opens from a link to it.

Only a dashboard shared with everyone in the organisation can be a tab, because everyone who opens Metrics sees its tabs. Under **Not on the tabs**, a dashboard that is not shared cannot be added and says **Not shared with the organisation, and everyone who opens Metrics sees its tabs. Share it with the organisation on its page to add it.** See [Canvases](/platform/canvases) for how to share one.

A dashboard on the tabs that you cannot open, or that is gone, is left off the tabs you see, and a line under them says **One tab is a dashboard you cannot open, so it is not shown to you.** It stays on the tabs for the people who can open it. **Edit tabs** then warns **One tab is a dashboard you cannot open. Saving takes it off the tabs for everyone.** When no tab is left for you to see, Metrics shows Ankra's own tabs and says why, such as **The saved tabs could not be shown, because the dashboard on them is gone or not open to you. Ankra's own tabs are shown instead.** With the right to change the application, **Use Ankra's order** beside it puts the tabs back on Ankra's order for everyone. A link to a dashboard you cannot open, or one that is gone, shows **This dashboard does not exist any more, or you cannot open it.**

Each change is made on the tabs as they were when you opened them. If someone else changed them in the meantime, your change is not saved and the bar shows their tabs. In **Tabs on Metrics**, the page names who changed them and when, then says **Your arrangement is still here. Saving now puts it in place of theirs, which the tabs above show.** **Save tabs** again puts yours in their place, and **Cancel** keeps theirs. A tab chosen in **Add a tab** is not added either, and the page says so, ending **The tabs above are theirs now: add it again if you still want it.**

Before Ankra kept the tabs, each browser kept an order of its own. If yours kept one that is not the order now, Metrics offers it under the tabs: **This browser kept an order of your own: Runtime, then Traffic. Metrics now keeps one order for everyone who opens it.** Ankra does not use it unless you ask. **Use it for everyone** saves it as everyone's tabs, and needs the same role as **Edit tabs**. **Forget it** drops it from this browser.

If the tabs cannot be read, Metrics says so, such as **The tabs of Metrics could not be read. Traffic is shown until they are.** **Read them again** tries again.

### Make a dashboard

**All dashboards** starts with a card that makes a dashboard of the application. While the page reads what you may do, it says **Checking what you can do here…** and offers no button yet.

- **New dashboard** makes an empty dashboard named **New dashboard** that only you see until you share it, and opens it. The page says **Made “New dashboard”. Only you see it. It is in All dashboards. It has no cards yet. Add a card to start.** It is not added to the tabs: it shows on the bar while it is open, and **All dashboards** opens it again. One press makes one dashboard.
- **Ask Ankra for a dashboard**, for people who may use Ankra AI (`ai.use`), opens Ask Ankra with a new conversation and **Make a dashboard of** *application* **from its own numbers.** in the message box, for you to change and send. The suggestions under it, **Failed requests and response time side by side** and **Response time with the deployments on its cluster marked**, are sent at once. Without `ai.use`, the card offers **New dashboard** alone.

Ankra AI draws the dashboard in the conversation. To keep it, open the conversation on **Home** with **Open as a page, with your conversations**, where the dashboard is beside it, and press **Save**. The panel beside the conversation is headed **Dashboard** while everything on it is an application's dashboard, and **Canvas** otherwise. When the conversation is about this application and no other, and the dashboard reads no other application's numbers, **Save** puts it in the application's **All dashboards** and opens it as a tab. The page says **Saved** “*title*” **from your conversation with Ankra. Only you see it. It is in All dashboards of** *application*. Any other dashboard is saved to **Canvases**: see [Canvases](/platform/canvases).

To show a dashboard on the tabs for everyone, share it with the organisation on its page (**More**, then **Open the dashboard's page**), then use **Add a tab**.

#### Add a card

**Add a card** is on the toolbar of a dashboard's tab, and on a dashboard with no cards. Only the dashboard's owner and the people who can edit it have it: anyone else who opens a dashboard with no cards reads **Its maker has not added a card yet.**

It lists what Ankra measures about the application, the same list as on the Overview (see [A chart as a card](#a-chart-as-a-card)), each with **Add**. **Add** puts the measure on the dashboard as a chart, last in its grid, and saves the dashboard as a new version. The chart writes the measure in its unit, as the Overview's charts do: memory in MiB, or GiB from 1,024 MiB, CPU in cores, and response time in ms, or s from a second. The list then says **Added** *measure* **as a new version of the dashboard. It is last in its grid.** A measure that already has a card for this place says **On this dashboard** instead of **Add**. **Done** closes the list.

A card reads the environment Metrics shows when you add it, and one cluster when that environment runs on several. The first line of the list names them. The card keeps reading that place: when Metrics shows another environment, the dashboard says so, such as **These cards read Production. Metrics shows Staging.**

**Add a card** cannot be pressed on a dashboard with no room or no grid for a card, and says why, such as **The grid of this dashboard holds 32 cards, as many as a grid can hold.**

When it cannot make the dashboard or add the card, the page says why, and nothing changes unless it says it may have:

| What happened | What the page says |
|---|---|
| Your organisation is at its limit of dashboards and pages | **Your organisation keeps as many dashboards and pages as it can, so no dashboard was made. Delete one in Canvases to make room.** |
| Ankra did not answer **New dashboard** | **Ankra did not answer in time, so it is not known whether the dashboard was made. The list below is read again: if it is not there, try again.** |
| Someone changed the dashboard after you opened it | **It was changed somewhere else after you opened it, so** *measure* **was not added. Reload to see what it holds now, or add your card to what it holds now as a new version.** **Reload the latest version** shows their version. **Add my card to the latest version** adds your card to it, unless it has that card already |
| Ankra did not answer **Add** | **Ankra did not answer in time, so it is not known whether** *measure* **was added. The dashboard is read again: if the card is not on it, add it again.** |

When **New dashboard** fails, its message has **Try again**.

## Cost

What the application costs a month at today's rate, **This month so far**, and its daily observed cost as bars for the range picked at the top, then what each environment costs, under **Where the money goes**: see [What a rate is made of](#what-a-rate-is-made-of). **This month so far** is what the month's full days cost, to the cent, with today left out, such as **13 full days of November · today excluded**. On the 31st, when the 30 days drawn no longer hold the 1st, it is the platform's own month to date and says **today so far included**. A warning names each environment that costs more than its monthly budget. The daily bars show **All of it** or **By environment**, **Against the budget** puts each environment's monthly rate beside its budget, and **For a million requests** says what the environment the application serves from, its production one when it has one, cost for its requests over the last 7 whole days. The row appears only where cost is enabled for the organisation; anywhere else the view reads **Cost is not enabled for this organisation**. See [Cloud Cost](/platform/cloud-cost).

The Overview's **Cost** card opens this view with **Open Cost**. It reads each environment's budget the same way as this view and compares it by the same rule, so the two never disagree on over or under budget. When every environment has a budget, the card's daily bars have a line for what the budgets allow a day, and the part of a day above it is drawn in the warning colour. Pointing at a day, or the arrow keys, says how far over or under what the budgets allow it is.

### What a rate is made of

Under **Where the money goes**, each environment's monthly rate opens into the rows it is made of, largest first: each instance of a database, with its engine, version and what it reserves; each workload, with its copies and what they reserve; **Storage**, with its size and number of volumes; and **Jobs and other work**, the running copies that belong to no workload or database. A place the application shares with another application is a row under that place's name, with **Shared with another application: counted whole here and for that application**. Every row's amount is to the cent, such as **€4.00**, so the rows under an environment can be added up by eye. Like every figure on Cost, they are estimates: see [Cloud Cost](/platform/cloud-cost).

A row Ankra has no amount for says **Not known**, never €0, and is not added in, such as a workload that reserves no CPU or memory. Only the **Backups** row says **Not priced**, with **Not part of the rate: Ankra does not price backup storage**: it is shown beside the rate, not in it.

| What the page says | What it means |
|---|---|
| The rows, with no note under them | Ankra split the whole rate into rows, and the rows counted in it add up to it |
| A row named **What no row explains**, with **Part of the rate Ankra could not place on a row** | Part of the rate is on no row. It is counted, so the rows still add up to the rate |
| **What no row explains** with **The whole rate: Ankra could not place any of it on a row**, and **Not known** on the other rows | Ankra knows the rate but could not split it into rows. The sentence under the rows says why, such as **The metering did not split compute from storage here, so all of this rate is on no row.** or **This environment is too small to split: the metering rounds compute and storage to whole cents an hour, so all of its rate is on no row.** |
| **These rows add up to €9.03 a month.**, or **This breakdown covers €9.03 a month.** when the whole rate is on no row | The figure the breakdown was made from, said when it differs from the rate beside the environment's name |
| The rows, with a sentence under them such as **Some servers of its cluster have no price, so these amounts add up but may not be exact.** | Part of the breakdown is not exact, and the sentence says which part |
| **Ankra could not read every part of this rate, so these rows do not add up to it: €17.90 is not shown.** | Ankra could not read some of the rows. The amount is what those rows come to |
| **Ankra could not read what this rate is made of just now.** | Ankra could read none of the rows |
| **Ankra could not work out what this rate is made of**, with the reason when there is one, such as **no part of it has a price yet** | There is no breakdown of the rate. It never means the environment costs nothing |
| The environment and its rate, with no rows and no sentence | No breakdown came with the rate. The environment shows its rate as it did before rows were added |

A place the application runs in that belongs to no environment is listed by its cluster and its name, such as my-cluster · my-app, and opens into its rows the way an environment does. Ankra sometimes gives several such places on one cluster a single breakdown. Each of them then lists only the rows that run in it, with **These are the rows Ankra places here.** or **Ankra places no row here.**, and says the breakdown is shared, as in **Ankra gives the 2 places on my-cluster that belong to no environment one breakdown, and the rest of it is said under the last of them.** What runs in none of them, such as their storage or what no row explains, is said once, under the last of them: **Ankra does not place €6.00 a month of it in any one of them**, followed by what that is. When the breakdown has backups, the last of them also says **Backups are not part of the rate: Ankra does not price backup storage.** The page never splits an amount Ankra did not split. When such a place is the only one listed on its cluster and the breakdown is not its alone, it says **Ankra gives this place one breakdown with other places on my-cluster.**

## Variables

Every value the application reads when it runs, in one table: its secrets and its plain values. Each row is marked **Secret** or **Plain**, and the chips above the table narrow it to one kind. The view was named **Secrets** until November 2026, and its address is still `view=secrets`.

A saved value reaches the running application when its environment's values are applied: with **Save and apply**, with **Apply values**, or with the environment's next deploy.

### Secrets

API keys, passwords and connection strings, kept per environment, and **Shared secret defaults** for every environment. A secret's value is never shown after it is saved.

A secret's value stays masked while you type it. **Add secret** takes it on one line, or with **Multiline input** ticked in a box of several lines, where **Reveal** shows what you typed and **Hide** masks it again. **Add shared secret** and **Replace**, under **Shared secret defaults**, take the value in the same kind of box.

**Import…** takes up to 50 secrets for one environment in one import, from `KEY=value` lines, one per line, that you type or paste into a masked box. You can also drop a file of such lines below the box, or pick one with **browse**: its lines are added after what the box already holds, never in its place. **Review import** lists every name, and nothing is stored before **Confirm import**. Each secret is then saved in turn, and the dialog says how many were saved if it stops part way.

```bash
ankra application env-secrets list <application-id>
```

### Plain values

A plain value is configuration that is not a credential: a log level, a feature switch, a public address. Its value is shown in the table to everyone who can open the application, with who changed it and when.

**Add variable** and **Edit** open one sheet for a name. It holds a default for every environment and one field for each environment's own value. An environment whose field is empty reads the default, and the table marks that value **shared default**. A value holds up to 8,192 bytes.

A name is a secret or a plain value in one environment, never both. When a name or a value looks like a password, a token or a key, Ankra stores nothing and asks: add it as a secret, or confirm that it is meant to be plain. Use a secret for anything that grants access.

A pipeline step reads the application's secrets, never its plain values. A step that declares a secret whose name has a plain value's shared default fails, and says so: keep the name as a secret instead, by removing the plain value and then adding the secret, or take it out of the step's secrets, then start the run again.
