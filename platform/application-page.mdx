Open an application from **Applications** and its page replaces the sidebar with the application's own menu. The menu starts with **Overview** and a **Deploy** group that holds **Environments**, **Pipelines** and **Previews**. Then comes one row per view, with **Settings** last. This page lists every row, in menu order, with what it shows.

Every view lives at one address, `/next/applications/<application-id>?view=<view>`, and a view with sections or tabs adds `&section=<section>`. The **Overview** has no `view`. Links saved before the menu changed still open where they meant, except a bare `view=settings`: it opened Secrets, the view now named **Variables**, and it now opens Settings on **Address**.

Most views show one environment at a time: pick it in the environment menu at the top of the page. **Logs** and **Metrics** share a time range you pick; until you pick one, **Logs** opens on the last 24 hours and **Metrics** on the last hour. The place picked under **Running on** stays picked between **Logs**, **Metrics** and **Architecture**.

The header above a view that reads live state has **Check again**, which reads what the view shows again. After a release that did not go live, the header says which version is still serving, on every view. In the menu, **Security** carries the number of serious findings of the last scans, and **Variables** is marked when the next promotion waits for a secret its target does not have.

| Row | `view=` | What it answers |

| [Pipelines](#pipelines) | `pipelines` | Every build, and how its pipeline is set up |
| [Previews](#previews) | `previews` | A running copy of a branch, to try before it is merged |
| [History](#history) | `history` | What changed, where, who did it and how it ended |

## Overview

The application's front page. Its **Environments** card lists each environment with what it runs, what it follows (such as **Follows pushes to main**) and the one action that fits it, such as **Promote to** *environment*, **Wake** or **Open**. **Find an environment** filters the list. **Add** beside the environments starts a new environment on another cluster: see [Environments and branch rules](/guides/application-environments#add-an-environment-on-another-cluster).

When Ankra has a setup change for the application, the Overview says **A setup change is waiting for your approval.** When a release did not go live, the environment's card offers to put the previous version back: see [Roll back an application](/guides/roll-back-an-application).

<CliVersion since="0.74.0" />

```bash
ankra application get <application-id>
```

### Arrange the Overview

The cards under the header are one layout, shared by everyone who opens the application. Until someone saves one, the page shows **Ankra's layout**: Health, Environments, Services, Cost and **Is it safe?**. An organisation without the Cost area has no Cost card. The line above the cards says which layout is on the page and, for a saved one, its version, who saved it and when.

**Edit layout** arranges the cards:

- **Move a card** - drag it by its handle. On a touch screen, each card has arrows that move it one place.
- **Set its width** - pull its right edge, or pick **1/3**, **1/2**, **2/3** or **Full**. In a phone-width window every card is a row of its own, and there is no width control.
- **Take a card off** - the cross on the card.
- **Add a card** - lists every card the Overview can hold: the ones above and three more, **Recent releases**, **Last pipeline runs** and **Backups**. A card already on the page says **On the page**, and any other has **Add**. It also lists what Ankra measures, to add as a chart: see [A chart as a card](#a-chart-as-a-card).
- **Start from** - begins again from Ankra's layout, **On call** or **Release day**.
- **Undo** and **Redo** - step through the changes of this edit.

With the keyboard, a card's handle picks it up: the arrow keys move it, Shift and an arrow key changes its width, Enter puts it down and Escape puts it back. Ctrl+Z (Cmd+Z on a Mac) undoes, and with Shift it redoes.

Nothing changes for anyone until **Save layout**. Saving keeps the layout before it as a version. **Versions** lists them, newest first. Choosing one puts it back as a new version, so nothing saved is lost, and **Ankra's layout** in the same list returns the page to how it was. If someone else saved while you were editing, your save is refused and the page says who saved which version. Your arrangement stays in the editor: **Save layout** again puts it on the page in place of theirs, and **Cancel** shows theirs. Following a link, reloading or closing the tab with changes that are not saved asks first.

Changing the layout needs a role that may change the application (`applications.write`). The header, and the card that says why a release needs you, are not part of the layout: they stay where they are.

#### A chart as a card

**Add a card** also lists **What Ankra measures**: CPU used, Memory used, Copies running, Container restarts, Response time p95 and Requests that failed. **Add** puts the measure on the page as a chart of the last 7 days, for the environment the Overview shows. It is saved with the layout, like any other card.

Above the chart, the card says what the measure comes to, such as **358 MiB now**. A line has one point an hour, and bars cover six hours each. A time with no reading is a gap in the line, never a zero. When Ankra cannot read a measure, the card says why in place of the chart. A member whose role does not reach the cluster the environment runs on is told so.

## Environments

What is live in each environment, and the way to change it. **Add an environment** in the page header adds one on another cluster. Environments is one page with these parts:

- **One card per environment** (`section=deploy` opens the page here): its cluster and state, the version it runs with that version's commit and change, where it runs and the copies running, and its own buttons. **Promote to** *environment* opens the promotion review. **Deploy a version** opens the deploy page for that environment: choose the version, Ankra checks the cluster has what it needs, and nothing changes until you confirm. **Roll back to** *version* (or **Undo this release**) puts the version before back, **Park** opens **Park or remove** in Settings, and **Open** opens the environment's address. A parked environment has only **Wake**. Until anything of a new application runs, the page shows its **Go live** steps instead, and opening the application lands here: see [Ship your app](/guides/deliver-your-app#ship-from-the-portal).
- **Promote a version**: with two or more environments that run on a cluster, put the version one environment runs live on another. The promotion review shows the version each side runs, with **Live there since** and **Replaces**, and nothing changes until you confirm.
- **Recent releases to** *environment*: a table of the releases to the environment in view, with **Live now** on the version it runs and **Full history** linking to History.
- **Where it runs** (`section=where-it-runs`), last: every place the application runs. See [Where it runs](#where-it-runs) below.

```bash
ankra application deploy <application-id> --cluster <cluster>
ankra application promote <application-id> --from staging --to production --dry-run
```

### Where it runs

The last section of Environments: each place the application runs, grouped by environment, and how each one is doing. Places no environment claims are listed under **Outside your environments**, and places being taken off a cluster under **Being removed**. If Ankra cannot read your environments, every place is listed ungrouped under **Every place**. The older addresses `view=where-it-runs` and `view=deployments` open this section.

```bash
ankra application deployments <application-id>
```

## Pipelines

Every build of the application, and how its pipeline is set up. Pipelines has four tabs and opens on the first. **Runs** starts with a card that says where the default branch is and which version each environment runs. A run the image gate stopped reads **Blocked**. See [Ankra Pipelines](/guides/ankra-pipelines).

| Tab | `section=` | What it shows |
|---|---|---|
| **Runs** | none | Every run, with **Run pipeline** to start one and the **Merge train** below the list. A run opens under the same tabs with its stages and steps; **All runs** returns to the list |
| **Schedules** | `schedules` | **Scheduled runs**: **Add a schedule**, a switch on each one that pauses or enables it, and **Edit schedule** and **Delete schedule** in its menu. Each schedule says whether the pipeline file writes it, and one that starts no run says why. **In the pipeline file, not running** lists the `on.schedule` entries no schedule starts, each with **Add this schedule**. See [Run every night](/guides/ankra-ci-starter-pipelines#run-every-night) |
| **Cache** | `cache` | The files a pipeline stage keeps from one run to the next: each cache's name, the key the stage declared, where it is mounted, its size, [what it saves a run](/pipelines/caching#what-a-cache-saves) and when a run last used it. Above the list, what the caches saved together over the last 30 days. Under it, the newest run that ran with every cache cold and why. With **Refresh caches** |
| **Configuration** | `configuration` | A change to the pipeline that waits for an admin's approval comes first, with **Review the change**. Then **Pipeline configuration** (the stages and **Validate pipeline**), **Build infrastructure** (the build cluster, with **Enable build execution** when its agent has not reported pipeline execution support) and **Repository workflow history** |

```bash
ankra pipeline list --application <application-id>
ankra pipeline caches --application <application-id>
```

## Previews

A running copy of a branch, to try before it is merged. Each preview has its own address, and Ankra removes it when its timer ends. **New preview** starts one from a branch that has a published build. Each preview is a card with its address, the run that built it, when it started and when it stops, the cluster it runs on, its version, its data and its namespace, with **Open preview** and **Stop preview**. A card also says when the newest run of its pull request did not pass. What new previews start from is set in **Settings → Deploys**, under **Preview defaults**. See [Preview a branch](/guides/branch-demos).

```bash
ankra application demo list <application-id>
```

## History

The changes to the application: what changed, where, who did it and how it ended. It opens on the last 7 days; pick a longer range, up to **Any time**, to see older changes. A release line you may undo carries **Roll back to** *version* or **Undo this release**: see [Roll back an application](/guides/roll-back-an-application).

**Where each environment stands** sums up each environment's releases over the last 7 days, and **Needs a look** names each release that failed. **Compare versions** puts two versions side by side, with the image each one runs and where it runs, and offers to promote one from there. **Group by release** folds a version's build and its releases into one line. Runs on a timer that passed are counted under the list, and **Show them** lists them. An open change steps to the change before or after it, and changes that arrive while you read wait behind a **1 new change** button. **Export** downloads the changes shown as CSV or JSON.

```bash
ankra application timeline <application-id> --limit 20
```

### Changes to settings

A change to a variable, a secret or a setting is a row of its own: which setting, what happened, who did it, when and where, such as **LOG_LEVEL set to debug in Staging**. Where it can, the line under it says what the value was before. Pick **Settings and secrets** above the list to see only these rows; the page then says what they cover: push to deploy, automatic build fixes, auto-merge of the setup pull request, Who runs it, the pause of Ankra's own actions, environment names, operating expectations, secrets, variables and backups. Changes to copies, CPU and memory are not listed.

Open a row for its **Before and after** table: each value before the change and after it. For most settings the details also link to the page where the setting is changed now, such as **Open Variables**. A value the table cannot show is never left blank:

| The table says | What it means |
|---|---|
| **Not set** | There was no value |
| **A value, not shown** | There was a value, and History does not show it: a secret's, or a plain value's that looked like a secret |
| **Not recorded** | Ankra has no record of the value. This is not the same as no value |
| **Could not be read** | Ankra could not read the value |

A secret's value is never shown: its row says **Secret. Its value is never shown.**, and the table shows **A value, not shown** before and after.

A member confined to some projects sees that a change happened in an environment outside their projects, not what changed. The row says **In an environment outside your projects. What changed there is not shown to you.** and names its place as **Outside your projects**. Its details have no table and no link.

## Logs

What the application's containers wrote, searched over a time range or read live. Logs opens on **Search** over the last 24 hours when the cluster keeps its lines, and on **Live** when it does not; **Previous run** shows what each container wrote before its last restart.

On a search, bars above the lines show when the lines were written, errors and warnings on their own row. Drag across the bars, or pick them with the arrow keys and press Enter, to narrow the time, or use **Zoom to the most errors**. **The same time in Metrics** opens Metrics on the same minutes. **Export** saves the lines **As a text file** or **As NDJSON**, and **Load older lines** reads further back. For a cluster's own logs, see [Logs](/platform/logs); to keep lines when the cluster has no log store, see [Ankra hosted logs](/guides/hosted-logs).

## Metrics

How the application answers requests and what it uses, for the place and the time range you choose. Metrics has two tabs: **Traffic** (`section=traffic`: successful responses, response time and request traffic) and **Runtime** (`section=runtime`: CPU, memory, copies and container restarts). It opens on the tab you last left it on in this browser. **Edit tabs** changes their order and takes a tab off, and **Add a tab** puts it back. On **Traffic**, **Compare with** draws the period before beside the one you chose, and the **Releases** chip shows or hides the releases on the charts. **Runtime** lists **The copies running now**: each copy, its version, when it started and its restarts. When Ankra's built-in metrics are off but your own Prometheus for the cluster works, the charts stay empty and **Open cluster metrics** opens the cluster's [Metrics page](/platform/cluster-metrics).

Under the charts of **Traffic**, the **Alerts** card lists the alerts that watch this application on the environment: the ones made here, and your organisation's alert rules for a cluster it runs on, each with when it last fired and who acknowledged it. **New alert**, or **Alert** on a chart, makes one. See [Alert on one application](/guides/alerts#alert-on-one-application).

## Security

What the last scans found in the image the application runs and in its code, with **What needs you**, **Fix first**, **What stops a release** and **What is running: the image in each environment** first. Filter the findings by severity and open one for what it is and how to fix it; **Fix with Ankra** (or **Ask Ankra how to fix it**) hands it to Ankra AI. See [Security scanning](/concepts/applications#security-scanning).

```bash
ankra application container-security <application-id>
ankra application code-security <application-id>
```

## Data

Data has three tabs and opens on the first:

| Tab | `section=` | What it shows |
|---|---|---|
| **Backups** | none | Backups of the environment, and whether restoring them has been tested |
| **Database** | `database` | Status, storage and backups of the application's database in the environment, with **What Ankra does** under them |
| **Service bindings** | `bindings` | The namespaces a managed service, such as a database, is allowed to connect to |

```bash
ankra application backups <application-id>
```

## Cost

What the application costs a month at today's rate, what it spent so far this month when Ankra can say, and its daily observed cost as bars for the range picked at the top, then what each environment costs. A warning names each environment that costs more than its monthly budget. The daily bars show **All of it** or **By environment**, **Against the budget** puts each environment's monthly rate beside its budget, and **For a million requests** says what the production environment cost for its requests over the last 7 whole days. The Overview's **Cost** card opens this view with **Open Cost**. The row appears only where cost is enabled for the organisation; anywhere else the view reads **Cost is not enabled for this organisation**. See [Cloud Cost](/platform/cloud-cost).

## Variables

Every value the application reads when it runs, in one table: its secrets and its plain values. Each row is marked **Secret** or **Plain**, and the chips above the table narrow it to one kind. The view was named **Secrets** until November 2026, and its address is still `view=secrets`.

A saved value reaches the running application when its environment's values are applied: with **Save and apply**, with **Apply values**, or with the environment's next deploy.

### Secrets

API keys, passwords and connection strings, kept per environment, and **Shared secret defaults** for every environment. A secret's value is never shown after it is saved.

```bash
ankra application env-secrets list <application-id>
```

### Plain values

A plain value is configuration that is not a credential: a log level, a feature switch, a public address. Its value is shown in the table to everyone who can open the application, with who changed it and when.

**Add variable** and **Edit** open one sheet for a name. It holds a default for every environment and one field for each environment's own value. An environment whose field is empty reads the default, and the table marks that value **shared default**. A value holds up to 8,192 bytes.

A name is a secret or a plain value in one environment, never both. When a name or a value looks like a password, a token or a key, Ankra stores nothing and asks: add it as a secret, or confirm that it is meant to be plain. Use a secret for anything that grants access.

## Architecture

What receives requests, what runs and where the application keeps its data, for the place picked under **Running on**. **Parts and connections** sorts the parts into four columns: **Entry points**, **Services**, **Workloads** and **Storage**. **Source components** lists each component with the image it runs.

## Settings

Settings has one tab per section and opens on **Address**. Each tab says what it is for under its title.

| Tab | `section=` | What it holds |
|---|---|---|
| **Address** | none | Where people reach the application in each environment: its **Ankra address** and **Your domain** |
| **Deploys** | `deploys` | What Ankra deploys on its own: **Deploy on every push** and the branches each environment follows, **Pull requests**, **Preview defaults**, and **Repository setup** with **Retry setup** |
| **Scaling** | `scaling` | How many copies run in the environment, from 1 to 10, and the memory and CPU each copy reserves and may use at most, beside what the environment runs now. A change shows its cost before **Review the change**, and the review deploys only the values you changed |
| **Who runs it** | `ai` | What Ankra does on its own in each environment, and on your pull requests, with **Pause Ankra for this app** |
| **Registry** | `registry` | Where the application's images are kept, and how much room they take |
| **Repository** | `repository` | The repository Ankra builds the application from, and the **Deployment files** it keeps there. **Publish to the organisation catalog** offers the application as an add-on: see [Application add-ons](/platform/application-addons) |
| **Service goals** | `goals` | What you expect from the environment, and what Ankra checks each target against |
| **Park or remove** | `runtime` | Stop the application running somewhere for a while, or take it off for good. Each running place says what it would cost parked |

```bash
ankra application auto-deploy get <application-id>
ankra application autonomy get <application-id>
ankra application registry get <application-id>
```

See [Environments and branch rules](/guides/application-environments) for **Deploys**, and [PR preview environments](/guides/pr-preview-environments) for **Pull requests**.
