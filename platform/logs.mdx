A pod is crash-looping or returning errors and you need to see what it printed, across every replica, without setting up `kubectl` access first. Ankra reads container logs through the Ankra Agent, and searches older lines in a log store: Ankra hosted logs, or a store of your own.

There are three places to read logs:

| Where | Menu path | Use it for |
|-------|-----------|------------|
| **Cluster logs** | **Clusters → &lt;your cluster&gt; → Technical details → Kubernetes → Cluster logs** | Every namespace, pod and container in the cluster: search history, or read one namespace live |
| A pod's **Logs** tab | **Kubernetes → Workloads → Pods → &lt;pod&gt; → Logs** | One container of one pod, including the instance that ran before its last restart |
| The CLI | `ankra cluster logs` | Scripts, pipes into `grep`, and reading logs from a terminal |

Reading logs needs the `kubernetes.logs` permission on the cluster. The `owner`, `admin`, `operator` and `member` roles hold it; `viewer` does not, because logs carry whatever a workload prints. See [Roles & Access](/guides/roles-and-access).

## Cluster logs

Open **Clusters → &lt;your cluster&gt; → Technical details → Kubernetes → Cluster logs** (`/next/clusters/<cluster-id>/kubernetes/logs`). The page has two modes, switched with **History** and **Live** at the top right. A badge under the title says where the lines come from: the log store's name, or `Live from the containers`.

### History

**History** searches the lines a log store has kept. It opens on the last hour.

1. Type in **Search text, a request ID, an error…** and press `Enter`, or leave it empty to see every line.
2. Pick a time window with the time range picker and click **Search**. A window covers at least a minute and at most 30 days, and ends no later than now.
3. Narrow with **Filters**: **Namespace**, **Pod**, **Container** and **Severity** (each level, plus **No level**). Each filter you add shows as a chip in the search box; click its **×** to remove it.

The lines appear newest first, under a chart of how many lines were written over the window. Drag across the chart to zoom in. **Load older lines** at the bottom reads further back. **Follow** reads new lines every few seconds while the window ends now.

Which store History reads is set by the **Log store** filter:

| Choice | Reads |
|--------|-------|
| **Automatic** | The cluster's own log store when one is connected, otherwise Ankra hosted logs |
| **Your log store** | The Loki, Elasticsearch, OpenSearch or VictoriaLogs store connected to the cluster. See [Log Sources](/integrations/log-sources). |
| **Ankra hosted logs** | The lines the cluster's agent sends to Ankra. See [Ankra Hosted Logs](/guides/hosted-logs). |

When the cluster has no log store, History shows **Search this cluster's log history** with three choices: **Ankra hosted logs** (with **Turn on hosted logs** if your role can change the cluster), **Your own log store** (**Connect a log store** opens **Settings → Logs and data**, which links to **Integrations**, where the store is connected), and **Live logs, right now** (**Read live logs**).

### Live

**Live** reads what the containers of one namespace are writing, straight through the agent. No log store is needed, but you only get what the containers still hold.

1. Pick a namespace in **Choose a namespace to read live**, or in the **Namespace** field.
2. Choose how far back each container starts in **Lines**: **Last 100 per container**, **Last 300 per container** (the default) or **Last 1,000 per container**.
3. Type in **Filter lines as you type…** to narrow the loaded lines, and use **Filters** for **Pod**, **Container** and **Severity**.

A status line reads `Live · <pods shown> of <pods> pods · <lines> lines`. **Pause** stops new lines arriving, and **Resume** starts them again. **Previous run** shows what each container wrote before its last restart, which is where a crash-looping container's error is; only a container that restarted has one.

### Read a line

Click a line to open **Log line**: its time in UTC, namespace, pod and container (each with a button for only lines from it), the message, any structured fields, the raw line and the lines around it. **Copy line** copies it and **Copy link** copies an address that opens the same line selected.

### Lines and patterns

Above the results, **Lines** shows each line and **Patterns** groups lines with the same shape, with the numbers, IDs and addresses in them set aside, and counts them. A flood of health checks becomes one row, and the one new error stands out. Click a pattern to see its lines. **Order** switches between **Newest first** and **Oldest first**, and **Wrap long lines** wraps them.

To save what you see, click **Export the shown lines as NDJSON**: one JSON object per line, for `jq` or another tool.

### Ask Ankra about the logs

When lines are shown, **Ask Ankra** at the top asks [Ankra AI](/platform/ai-assistant) what is going wrong in them. The question carries the cluster, the window or live view, the filters, and the count of errors and warnings among the shown lines, with the most frequent error patterns.

### Keyboard shortcuts

Press `?` on the page for the list.

| Key | Does |
|-----|------|
| `/` | Search |
| `J` or `↓` | Next line |
| `K` or `↑` | Previous line |
| `Esc` | Close the line |
| `F` | Follow new lines, or pause live logs |
| `P` | Lines or patterns |
| `W` | Wrap long lines |
| `?` | These shortcuts |

## A pod's Logs tab

Open the pod (**Kubernetes → Workloads → Pods**, then the pod, or **View logs** on its row) and click **Logs**.

1. Pick the container in **Container**.
2. Choose **Current instance**, or **Previous instance** for the run before the last restart.
3. Choose **Last 100 lines**, **Last 500 lines** (the default) or **Last 1,000 lines**.
4. Click **Follow** to read the tail again every five seconds; **Pause following** stops it.

**Search loaded lines…** filters the lines on screen.

## From the CLI

`ankra cluster logs` streams a pod's logs, like `kubectl logs -f`. `-n` is required.

<CliVersion since="0.13.0" />

```bash
# The last 100 lines of one container, then follow
ankra cluster logs my-pod -n default -c my-container --tail 100

# The run before the last restart: where a CrashLoopBackOff's error is
ankra cluster logs my-pod -n default --previous

# Every pod matching a label, print what is there and exit
ankra cluster logs -l app=web -n default --tail 50 --follow=false

# Every container of the pod, including init containers, as JSON
ankra cluster logs my-pod -n default --all-containers --follow=false -o json
```

With more than one pod or container, each line is prefixed with `[pod]` or `[pod/container]`. See [`ankra cluster logs`](/reference/cli/cluster#ankra-cluster-logs) for every flag.

AI agents connected over MCP use `get_pod_logs` for one pod and `query_logs` to search the cluster's log store. See [MCP Tools](/platform/mcp-tools).

## What can go wrong

| You see | What it means | What to do |
|---------|---------------|------------|
| `Your role cannot read container logs on this cluster.` | Your role lacks `kubernetes.logs`. | Ask an organisation admin for a role that holds it. |
| `Live logs need the cluster agent.` | The agent is not connected, so containers cannot be read. | Check the cluster's status on its **Overview**. History still works if a store holds lines. |
| `Ankra hosted logs are on, but no line has arrived from this cluster.` | The switch is on but the agent sends nothing. | Check the agent is connected and up to date in **Settings → Logs and data**, or read **Live** meanwhile. |
| `No lines match this search` | Nothing was written in the window that matches. With hosted logs: lines arrive only while hosted logs are on, and are kept for 7 days. | Widen the window or remove filters. |
| `The earlier containers wrote nothing` | **Previous run** is on, but no container restarted. | Turn **Previous run** off. |
| `The log store could not confirm these lines are this cluster's.` | A store shared by several clusters did not say which lines came from this one, so none are shown. | Click **Check the log store settings**. See [Log Sources](/integrations/log-sources). |
| `The log store answered with lines outside these filters.` | None are shown, since they may not be the lines you asked for. | Try again; if it repeats, check the store's labels. |
| `That log store cannot be read here.` | The store chosen under **Log store** cannot be read. | Click **Read automatically instead**. |
| `This search could not be run.` | The window is shorter than a minute, longer than 30 days, or ends in the future. | Pick another window. |
| `The cluster's logs could not be searched.` | The log store did not answer. | Click **Read live logs from the containers**, or try again. |
