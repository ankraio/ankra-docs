A Git credential is how Ankra reaches your repositories: to sync a cluster's GitOps configuration and to build applications. Ankra connects three Git hosts natively:

| Host | How it connects | Full setup |
|---|---|---|
| GitHub | Install the Ankra GitHub App on the repositories you choose; no token to store or rotate | [GitHub integration](/integrations/github) |
| GitLab | An access token, for GitLab.com or a GitLab you run yourself | [GitLab integration](/integrations/gitlab) |
| Bitbucket Cloud | OAuth consent for a Bitbucket workspace | [Bitbucket Cloud integration](/integrations/bitbucket-cloud) |

This page covers adding the credential and reading its access. The integration pages cover what each connection powers, its permissions, webhooks and how to disconnect.

## Before you start

- A role with `credentials.write` (the built-in `owner` and `admin` roles have it). See [Credentials](/platform/credentials#before-you-start).
- For GitHub: permission to install a GitHub App on the account or organisation. On a GitHub organisation you do not own, an owner has to approve the request.
- For GitLab: an access token with the `read_api` and `read_repository` scopes.

## Add a Git credential

Go to **Integrations & alerts → Credentials**, click **Add credential**, and under **Git, registries and keys** choose the host.

<Tabs>
  <Tab title="GitHub">
    1. Click **Install the GitHub App**. GitHub opens; choose the account and the repositories the app may access, and install it.
    2. GitHub brings you back to Ankra. If the page shows **Finish GitHub connection**, click it. The credentials list opens with the new GitHub credential.

    If the page reads **Waiting for a GitHub organisation owner**, GitHub has sent the install request to an owner of that organisation, and no connection exists until the owner approves it.

    **Reconnect an existing installation** lists GitHub App installations on your own personal account that Ankra can attach to this organisation; click **Reconnect** followed by the account's name. To see them, your GitHub identity must be connected in your [profile](/platform/user-profile).
  </Tab>
  <Tab title="GitLab">
    1. Under **Connect GitLab**, enter an optional **Name**.
    2. Leave **GitLab address** empty for gitlab.com, or enter the address of your own GitLab, such as `https://gitlab.example.com`.
    3. Paste the **Access token** and click **Connect GitLab**.
    4. The dialog **Copy the webhook secret now** shows the **Webhook address** and the **Webhook secret**. Add the webhook to each GitLab project with this secret: Ankra shows the secret only this once. Tick **I have put it in GitLab or stored it somewhere safe** and click **Done**.
  </Tab>
  <Tab title="Bitbucket Cloud">
    1. Under **Connect Bitbucket Cloud**, click **Connect Bitbucket**.
    2. Bitbucket asks you to authorise Ankra for your workspace. Approve it; Bitbucket brings you back to Ankra.

    If you see **Bitbucket setup did not complete**, start the connection again and finish it in the same browser and Ankra organisation.
  </Tab>
</Tabs>

The new credential appears in the list on **Integrations & alerts → Credentials**.

## Check repository access

Open the credential and click **Repositories & resources**.

- For **GitHub** and **Bitbucket Cloud**, **Repository access** lists the repositories the connection can reach against the ones your applications need. The counts read **Repositories available**, **Required by applications** and **Access missing**, and each repository's **Access** is **Available**, **Access missing**, **Access not yet verified** or **Owned by another account**. Click **Sync repositories** to read the list from the host again. For GitHub, **Manage GitHub access ↗** opens the app installation on GitHub, where you add or remove repositories.
- For **GitLab**, repository access is managed in GitLab; the tab lists the Ankra resources that use the credential.
- A GitHub credential also lists its **Repository webhooks**, with the **Delivery status** of each.

<CliVersion since="0.13.0" />

From the CLI, read a GitHub credential's live access against what Ankra needs from it:

```bash
ankra credentials repositories my-github
```

It reads the list from GitHub each time, rather than the cached count `ankra credentials list` shows.

## Rename, show or delete

Git credentials share the steps on [Credentials](/platform/credentials): rename under **Settings & access → Display name**, and delete under **Settings & access → Delete this credential**. A role with `credentials.reveal` can open a GitLab credential's **Stored values**. Git credentials have no **Check now** and no **Replace the secret**.

Deleting a GitHub credential marks the connection for deletion; the GitHub App stays installed on GitHub until you remove it there.
