A registry credential is the username and password (or access token) Ankra uses to read a private Helm chart registry. You store it once and pick it by name when you add the registry. Ankra keeps the login encrypted and never shows the password in a list.

<Note>
**Build & delivery → Helm registries** takes HTTP chart repositories, and its **Credential** field picks the login. OCI registries (Harbor, Google Artifact Registry, or another OCI registry) are connected under **Build & delivery → Registries** instead. Its **Admin credential** step stores a new login there, or picks **One already stored**, which needs a role with `credentials.reveal`. See [Registries](/guides/registries).
</Note>

## Before you start

- A role with `credentials.write` (the built-in `owner` and `admin` roles have it). See [Credentials](/platform/credentials#before-you-start).
- A login for the registry with read access. The provider sections below say how to make one.

## Create a Registry Credential

<Tabs>
  <Tab title="Portal">
    1. Go to **Integrations & alerts → Credentials**, click **Add credential**, and under **Git, registries and keys** choose **Helm registry**. The **Connect a Helm registry** form opens.
    2. Enter a **Name** (a unique lowercase name, such as `production-charts`), the **Username**, and the **Password or access token**.
    3. Click **Save registry login**. The credentials list opens with the new credential, shown as **Helm registry**.

    You can also add one where you use it: **Build & delivery → Helm registries**, then **Add credential** under **Registry credentials**. Enter **Name**, **Username** and **Password or token** and click **Add credential**. Both places make the same credential.
  </Tab>
  <Tab title="CLI">
    <CliVersion since="0.41.0" />

    The password is asked for at a prompt, or read from stdin with `--password-stdin`:

    ```bash
    ankra helm credentials create --name production-charts --username robot
    printf '%s' "$REGISTRY_TOKEN" | ankra helm credentials create --name production-charts --username robot --password-stdin
    ankra helm credentials list
    ```
  </Tab>
</Tabs>

## Provider-Specific Setup

<AccordionGroup>
  <Accordion title="GitHub Container Registry (GHCR)">
    **Create a Personal Access Token:**
    1. Go to GitHub → Settings → Developer settings → Personal access tokens
    2. Generate a token with `read:packages` scope
    3. For pushing charts, also add `write:packages`

    **Credential values:**
    - Username: your GitHub username
    - Password: the Personal Access Token
  </Accordion>

  <Accordion title="Google Artifact Registry">
    **Create a Service Account:**
    1. Go to Google Cloud Console → IAM → Service Accounts
    2. Create a new service account
    3. Grant "Artifact Registry Reader" role
    4. Create and download a JSON key

    **Credential values:**
    - Username: `_json_key`
    - Password: the entire JSON key file contents
  </Accordion>

  <Accordion title="Amazon ECR">
    **Get an auth token:**
    ```bash
    aws ecr get-login-password --region us-east-1
    ```

    **Credential values:**
    - Username: `AWS`
    - Password: the token from the command above

    <Warning>
    ECR tokens expire after 12 hours. Refresh the token before it expires.
    </Warning>
  </Accordion>

  <Accordion title="Azure Container Registry">
    **Create a Service Principal:**
    ```bash
    az ad sp create-for-rbac --name ankra-acr-reader \
      --scopes /subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.ContainerRegistry/registries/{registry} \
      --role acrpull
    ```

    **Credential values:**
    - Username: the `appId` from the output
    - Password: the `password` from the output
  </Accordion>

  <Accordion title="Docker Hub">
    **Create an Access Token:**
    1. Go to Docker Hub → Account Settings → Security
    2. Create a new Access Token with Read permissions

    **Credential values:**
    - Username: your Docker Hub username
    - Password: the Access Token (not your password)
  </Accordion>

  <Accordion title="Harbor">
    **Use a robot account (recommended):**
    1. Go to your Harbor project → Robot Accounts
    2. Create a new robot account with pull permissions

    **Credential values:**
    - Username: `robot$project+name` (the robot account name)
    - Password: the robot account secret
  </Accordion>

  <Accordion title="JFrog Artifactory">
    **Create an API Key or Access Token:**
    1. Go to User Profile → Edit Profile
    2. Generate an API Key or create an Access Token

    **Credential values:**
    - Username: your Artifactory username
    - Password: the API Key or Access Token
  </Accordion>
</AccordionGroup>

## Use the credential

1. Go to **Build & delivery → Helm registries** and click **Add registry**.
2. Enter the **Name** and the **Address** of the HTTP chart repository, starting with `https://`. Put the login in the credential, not in the address.
3. Under **Credential**, pick the registry credential. **None, a public registry** is for a registry that needs no login.
4. Click **Add registry**. Ankra reads the registry right away; its row under **Registries** shows the **State** of the read and the **Charts** it found.

See [Registries](/guides/registries) for syncing, chart versions and OCI registries.

## Change the login

<Tabs>
  <Tab title="Portal">
    Open the credential and click **Settings & access**. Under **Registry sign-in**, enter the **Username** and the **New password or access token**, then click **Save registry sign-in**. You see **Registry sign-in updated.**

    On **Build & delivery → Helm registries**, the credential's row under **Registry credentials** has the same action as **Change login…**: enter both values again and click **Save login**. Registries that sign in with it use the new login from their next read.
  </Tab>
  <Tab title="CLI">
    ```bash
    ankra helm credentials update production-charts --username robot
    ```

    See [`ankra helm credentials`](/reference/cli/helm#ankra-helm-credentials-update) for the flags.
  </Tab>
</Tabs>

## Delete the credential

Delete it from the credential's **Settings & access** tab (see [Delete a credential](/platform/credentials#delete-a-credential)), from **Delete…** on its row under **Registry credentials**, or with `ankra helm credentials delete production-charts`.

<Warning>
Registries that sign in with it can no longer be read until they get another login. It cannot be undone.
</Warning>
