Morpheus API credentials store the address of your HPE Morpheus appliance and a long-lived API access token, used to provision and manage self-managed [Morpheus clusters](/guides/morpheus-clusters). Ankra checks the token against the appliance's identity endpoint (`GET /api/whoami`) when you test or save it. For an appliance behind an SSH jumphost, saving does not probe the appliance, but **Test the connection** checks it through the jumphost, so run the test before you save.

## What Ankra Accesses

Ankra drives the Morpheus appliance API with your token:

| Resource | Operations | Why it's used |
|----------|------------|---------------|
| Instances | create, read, start/stop, delete | The cluster's nodes and bastion, provisioned as Morpheus instances |
| Networks | read | Placement options for the cluster's instances |
| Groups, clouds, service plans, instance types | read | The provisioning targets and sizes offered in the cluster wizard |

There is no finer token scoping on the Morpheus side: the token acts as its user, so that user must be able to see the target group and cloud and provision instances into them.

## Before you start

- A role with `credentials.write` (the built-in `owner` and `admin` roles have it). See [Credentials](/platform/credentials#before-you-start).
- A Morpheus user that can provision into the target group and cloud.

## Create a Morpheus API Credential

<Steps>
  <Step title="Get a Morpheus access token">
    In the Morpheus UI, go to **User Settings** → **API Access** and create a long-lived access token for a user that can provision into the target group and cloud.
  </Step>
  <Step title="Add it to Ankra">
    <Tabs>
      <Tab title="Portal">
        Go to **Integrations & alerts → Credentials**, click **Add credential**, and under **Cloud providers** choose **HPE Morpheus**. Fill in:

        - **Name**: 3 to 100 lowercase letters, digits and single hyphens (for example `morpheus-lab`). It cannot change later.
        - **Appliance address**: the address of your Morpheus appliance, such as `https://morpheus.example.com`
        - **Access token**: the token from the previous step
        - **Skip TLS certificate verification**: only for a self-signed certificate on a network you trust

        For an appliance Ankra cannot reach directly, open **Jumphost** and set the **Jumphost address** and **Jumphost private key**. **Jumphost SSH port** is 22 and **Jumphost user** is `root` when left empty.

        Click **Test the connection**. You see **The connection works**. Then click **Add credential**; the credential's page opens.
      </Tab>
      <Tab title="CLI">
        <CliVersion since="0.9.0" />

        The access token is asked for on a masked prompt, never taken as a flag:

        ```bash
        ankra credentials morpheus create --name morpheus-lab --api-url https://morpheus.example.com
        ankra credentials morpheus create --name morpheus-lab --api-url https://morpheus.example.com \
          --jumphost-host 203.0.113.10 --jumphost-private-key-file ~/.ssh/id_ed25519
        ankra credentials morpheus list
        ```

        Add `--tls-insecure` only for a self-signed certificate on a network you trust.
      </Tab>
    </Tabs>
  </Step>
</Steps>

For Morpheus clusters you also need an [SSH key credential](/platform/credentials/ssh-key). Create one from **Add credential → SSH key**, or with `ankra credentials ssh-key create`.

<Note>
You can replace the access token later under **Settings & access → Replace the secret** (see [Replace the secret](/platform/credentials#replace-the-secret)). The **Appliance address is fixed** - to point at a different appliance, create a new credential. The token is write-only: **Stored values** shows the address but never the token.
</Note>

## Troubleshooting Morpheus Credentials

These are the answers **Test the connection** and **Check now** give:

| Result | Cause | Solution |
|--------|-------|----------|
| HPE Morpheus API reachable and token accepted. | Success | Nothing to do |
| HPE Morpheus rejected the API token. | The token is invalid, expired, or revoked | Create a new access token in the Morpheus UI and paste it again |
| Could not reach the HPE Morpheus API. | Wrong appliance address, the appliance is not reachable from Ankra, or a TLS failure on a self-signed certificate | Check the address; for a private appliance, set a jumphost; for a self-signed certificate, turn on **Skip TLS certificate verification** |
| HPE Morpheus returned HTTP `<code>`. | Unexpected appliance-side response | Retry; check the appliance's health if it persists |

With a jumphost, a failure to reach or sign in to the jumphost itself is reported with the SSH error and what to check.

The check verifies the token identifies a user, not what that user may do. If the credential saves fine but provisioning fails, the token's user cannot see or provision into the selected group and cloud - fix the user's Morpheus role, or create a token for a user that can and replace it on the credential's page.
