Ankra's control plane stores the minimum it needs to operate your fleet, and is explicit about what stays inside your cluster. This page describes both sides of that line.

---

## What the control plane stores

| Data | Notes |
|------|-------|
| Cluster metadata | Names, providers, regions, node inventory, and [cluster states](/concepts/cluster-states) |
| Workload inventory | The Kubernetes resource data the agent streams for display - Deployments, Pods, Services, and other resource types. Secret values are replaced with SHA-256 digests before they leave the cluster |
| Platform metrics | Node, namespace and workload metrics the agent ships for built-in [cluster metrics](/platform/cluster-metrics), unless a cluster opts out with `metrics_collect.enabled: false` |
| Security findings and SBOM | Trivy findings and the software bill of materials - every package, version and licence found in each container image - see [Cluster Security](/guides/cluster-security) |
| Credentials | Cloud, Git, and registry credentials, stored encrypted in Vault or OpenBao |
| Audit events | The append-only [audit log](/guides/audit-log) of administrative changes, kept for 365 days |
| Pod terminal transcripts | Recordings of [pod terminal](/platform/pod-terminal) sessions, including whatever the shell printed, kept for 90 days |
| Chat transcripts | AI Assistant conversations, persisted only after always-on secret redaction |

---

## What stays in your cluster

- **Container images** - Trivy Operator runs in-cluster. Ankra reads the findings (CVE identifiers, severities, affected images and workloads) and the SBOM package inventory, but no image contents leave your cluster. See [Cluster Security](/guides/cluster-security).
- **Secret values in the background sync** - the agent replaces Secret values with SHA-256 digests before they leave the cluster, and the AI surface sees keys and counts only. The one exception is the console's **Reveal** action, an on-demand read of one Secret by a member with permission to see it.
- **Values decrypted from Git** - values sealed with [SOPS](/guides/sops) are written to your Git repository as ciphertext only, and the agent decrypts them inside your cluster at deploy time without sending the result back. The control plane is different: it holds the value you entered, so that it can seal it on every push - see [Secret lifecycle](#secret-lifecycle).

---

## Secret lifecycle

Platform credentials are written straight into the secret store on creation, decrypted only when a provisioning or deployment action needs them, and deleted when you remove the credential. For Git-stored values, each organisation gets its own SOPS/AGE key pair: the public key seals values each time Ankra writes them to Git (and in the CLI's local file mode), the private key stays in the secret store and is delivered only to clusters that decrypt. A value you enter in the Stack Builder is held by the control plane as entered, and what reaches Git is ciphertext. Keys can be [rotated](/guides/sops#key-rotation), and per-cluster SSH keys are likewise generated and held in the secret store rather than in cluster definitions - see [Cluster Hardening](/security/hardening).
